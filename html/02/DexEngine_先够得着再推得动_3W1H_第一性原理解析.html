从人手到机械手：先让手臂够得着，再让物理说了算DexEngine · 训练数据

论文发布 2026-11-25 · arXiv 2611.33579
关键词 人→机数据放大 · 运动学重定向 · 残差强化学习 · 物理可执行 · 双臂灵巧手
一句话 人体视频变成机器人训练数据，中间要过两道关：关节够得着、物体真被推动
方向 训练数据
💡 第一性原理核心立论

人类视频里手在动，机器人要的是关节序列，而且这套序列必须真能推动物体。中间缺两样东西：手臂够得着，也就是运动学可行；物理上推得动，也就是物理可执行。这两件事的求解代价差两个数量级——前者是几何搜索，后者要闭环试错。所以顺序只能是先把手摆到手臂够得着的位置，再让残差策略去补物理；反过来做，会先把手腕推到手臂跟不到的地方，白扔四分之一的数据。

What是什么：一条把「人手演示」放大成「双臂灵巧手数据」的流水线

它要交付的东西很具体：给定一段人体手-物演示，输出机器人运动 Q（含双臂与双手的全部关节角）——双臂加双手的全部关节角，且必须同时满足两条：

  • 运动学可行：在关节位置/速度极限内，不穿桌面、不穿固定物、不穿机身、不穿另一条臂；
  • 物理可执行：放到仿真里跑，物体真的沿着演示里那条轨迹被推动。

这两条听起来像同一件事，其实是两个完全不同的问题，代价差一个数量级——全篇的洞察就建立在这个差别上。

Why为什么：必须先把手臂装上去，再谈物理

公理一：人体演示只给「手和物体的位姿」，不给关节
输入是 MANO 手模型与物体轨迹，输出要的是双臂双手的关节角序列。这中间隔着一个逆问题：给定末端轨迹，求一条关节轨迹。而它有无数解，还可能无解。
公理二：「有解」不是给定条件，而是可以搜索出来的
演示里的手在某个位置动，机器人手臂能不能跟到取决于场景怎么摆——桌子多高、物体在基座前方多远、朝哪个方向。所以「可行」不是关于运动本身的性质，而是关于（运动, 摆放）这一对的性质。原文把摆放参数化成 ξ（平移 x/y/z + 绕竖直轴偏航），然后离散成网格去搜。这一步的实测很说明问题：默认场景位置只能保留 1.6% 的 clip，搜遍候选能保留 45.3%。
公理三：「推得动」不能靠几何算，只能靠闭环试错
手摆对了位置，物体也不一定按演示走——接触力、摩擦、物体会不会翻、手指是否打滑，这些几何完全不知道。所以必须放进仿真跑，用残差策略一点点修。这就是代价差两个数量级的地方：前者是可达性图 + IK 解分支搜索，后者是 PPO 强化学习。
推论：顺序不能反，因为物理校正会改变手腕的位置
这是全篇最锋利的一条实证：如果先做「悬浮手」的物理校正、再把手臂装上去，即使采用本文搜出来的最优摆放，能通过手臂 IK 的 clip 仍然少 26%。原因很直白——悬浮手阶段没有手臂约束，物理校正会把手腕推到手臂根本跟不到的地方；等你要装手臂时，这些 clip 已经废了。反过来，先搜摆放、再解 IK、最后在这个可行解附近做物理残差修正，就只剩「小幅偏移」要修。
第二个顺序陷阱在 RL 的重置里。残差策略随机重置到一个中间帧时，如果把手臂 IK 重新解一遍，很可能落到另一个解分支——几何上都对，但关节角差很远，策略学到的是错的对应关系。原文的解法是：直接把手臂 reset 到预计算好的那条 IK 解上。实测差距很大：手臂关节残差 + 随机重解 IK 是 0.544 ADD-AUC / 25.0% SP-SR；改成 reset 到参考解，是 0.856 / 76.6%。同一个算法，只改重置方式，成功率翻三倍。

How怎么做：四个阶段，前两个纯几何，第三个才是 RL

阶段 1：数据准备——对齐、切 clip、过滤
先把序列转到统一的重力对齐坐标系；物体停桌面时，从序列取桌面平面或设为物体静止高度。
再切 clip：每只手每个 clip 只保留一个被操作对象（选移动时间/驱动关节时间最长的那个）；换物体处切分（handover 除外）；静止段过长在中点切；每段尽量 ≥5 秒；单手任务里闲置的那只手保持在身侧静止。
最后过滤掉物理不一致的（物体跳变、陷入桌面）和重定向后指尖偏离过大的。
阶段 2：几何求解——重定向、修穿透、搜摆放、解 IK、重定时
手部重定向用 SPIDER 的 MuJoCo 关键点法（软等式约束 + IK，50 Hz 逐帧 warm-start）。初始穿透要修：首帧手穿进桌面/物体时，用最小的腕姿 + 指关节改动消除，再用短 lead-in 混回原运动；权重设计很讲究——1 厘米腕移动约等于 0.6 弧度拇指/食指运动，所以改手指比改手腕便宜。
摆放搜索用预计算的可达性图（每格 96 个朝向、每姿态最多 4 个 IK 解）：候选要求 ≥80% 帧被覆盖、物体停在桌面区域。IK 求解先在稀疏覆盖帧上用动态规划选一条关节运动最小的连续分支（= 粗路径），再从粗路径起点 + 31 个随机配置共 32 次运行逐帧续解，漂移 >1 cm 的帧重解；通过标准是 99% 帧腕部误差在 3 cm 内、无跳变、无穿透，最后保留肘部旋摆变化最小的那次。重定时把各时间区间拉伸，让最快关节速度略低于限速。
阶段 3：残差 RL——只修物理，不重新发明动作
每 ≤64 个 clip 共享一个残差策略（PPO，从零训，每只手独立 actor/value head 与奖励）。动作定义在腕空间而不是关节空间，因为腕的自由度更少、更接近任务空间；微分 IK 把修正后的腕姿转成手臂关节目标。clip 接受判据：训练后并行跑一批 rollout，≥10% 能到达 clip 末尾且未提前终止，才接受。
阶段 4：数据生成——记录 + 两种增强
重跑被接受的 clip，保留物体最接近参考姿态的那条完整 rollout；记录关节位置、关节目标（作为动作）、物体位姿、每指连杆法向接触力、双目 RGB-D、外中心视图和 VLM 自动生成的语言指令。
位姿增强：在筛选通过的其它摆放上重跑 IK + 重定时，策略不用重训。视觉增强：每轨迹渲 5 种外观（其中 4 种随机材质/光照/桌面/干扰物）。每 clip 最多 20 个 episode。
为什么这套流程能便宜一个数量级？因为它把「搜索」和「学习」分给了不同的工具：几何上可解的东西用可达性图 + DP + 32 次 IK 运行硬搜（确定性、可并行、几秒钟）；物理上不可解析的东西才交给 RL，而且RL 只学「残差」，起点已经是几何最优解。如果一上来就用 RL 学整条动作，那就是把几何问题也当物理问题解。

Formula核心公式：一条带约束的优化，加三处只改一点点的局部修正

① 主目标：物理可执行是目标，运动学可行是约束
\( \min_{\mathcal{Q},\,\bm{\xi}}\; E=\sum_{t}\sum_{j}d\big(\hat{\mathbf{O}}^{j}_{t},\mathbf{O}^{j}_{t}\big)\quad\text{s.t.}\quad \mathcal{Q}\in\mathcal{F}(\bm{\xi}) \)
大白话：\(\hat{\mathbf{O}}\) 是目标物体位姿，\(\mathbf{O}\) 是仿真里跑出来的位姿，\(d\) 是位姿距离，\(\mathcal{F}(\bm{\xi})\) 是「在摆放 \(\bm{\xi\) 下运动学可行的全部运动」这个集合。注意约束是集合包含关系，不是一个罚项——这正是「先几何、后物理」的数学表达：可行域先被划出来，优化只在里面找。
② 残差修正：只在参考动作上加一点点
\( \mathbf{p}^{*}_{t}=\hat{\mathbf{p}}_{t+\ell}+\delta_{p}\,\mathrm{sat}(\mathbf{u}^{p}_{t}),\qquad \mathbf{R}^{*}_{t}=\hat{\mathbf{R}}_{t+\ell}\exp\!\big(\delta_{R}\,\mathrm{sat}(\mathbf{u}^{R}_{t})\big) \)
大白话：策略输出的是残差 \(\mathbf{u}\)，截断到 [−1, 1] 再乘一个缩放 \(\delta\)，加到参考腕姿上；\(\ell\) 是 look-ahead，用来补偿手臂控制器的跟踪滞后。这一行是「RL 不重新发明动作」的技术定义：起始点永远是那条几何解，策略只能动一个小区间。（按原文流程整理，非原文照抄）
③ 手部重定向：一个带先验的 IK
\( \mathbf{q}^{h}=\arg\min_{\mathbf{q}}\sum_{i=1}^{5}k_i\|\mathbf{p}_i(\mathbf{q})-\hat{\mathbf{p}}_i\|^2+k_p\|\mathbf{p}_w(\mathbf{q})-\hat{\mathbf{p}}_w\|^2+k_R\|\log(\hat{\mathbf{R}}_w^{\top}\mathbf{R}_w(\mathbf{q}))\|^2+\lambda\|\mathbf{q}-\mathbf{q}^{h}_{t-1}\|^2 \)
大白话：五个指尖位置 + 手掌位置 + 手掌朝向，三项加权求和，最后一项是把「别乱动」当正则——它让相邻帧的解连续，避免手指抖动。旋转用对数映射而不是直接减矩阵，是因为旋转没有减法。
④ 初始穿透修复：宁可改手指，也不改手腕
\( \min_{\Delta\mathbf{q}^{h}}\;\|\mathbf{w}\odot\Delta\mathbf{q}^{h}\|^{2}+\lambda_n\,n_{\mathrm{pen}}\big(\mathbf{q}^{h}_{1}\oplus\Delta\mathbf{q}^{h}\big)+\lambda_d\,d_{\mathrm{pen}}\big(\mathbf{q}^{h}_{1}\oplus\Delta\mathbf{q}^{h}\big) \)
大白话：第一项要改得少（\(\mathbf{w}\) 让拇指/食指最便宜、腕最贵），后两项罚「穿进去的点数」和「穿透深度」（\(\lambda_n=10^3\)/点，\(\lambda_d=5\times10^4\)/米）。为什么权重这么设？因为穿透是首帧的局部接触问题，动手指几毫米就能解决，动手腕却会破坏整条轨迹的关系。用 Nelder–Mead 三阶段求解（仅手指 → 仅腕 → 两者）。
⑤ 数据放大倍数：一个乘法决定「1 条能变 20 条」
\( N_{\text{ep}}=\sum_{c}\;\big|\Xi_{c}\big|\times\big|V\big|,\qquad \big|\Xi_{c}\big|\le 4,\ \ |V|=5 \)
大白话：\(\Xi_c\) 是通过筛选的摆放集合（位姿增强），\(V\) 是外观集合（视觉增强），所以每条 clip 最多 20 个 episode。关键在于位姿增强不需要重训策略——只重跑 IK 与重定时，因为「换一个摆放」对残差策略来说是分布内的变化。这是把 37 小时变成 578 小时的真正来源。（按原文流程整理，非原文照抄）

Worth价值与局限：数据工厂是真的，接受率三分之二是硬伤

值得带走的

  • 「先几何、后物理」这个顺序，可以被任何做人类数据放大的人直接抄。它不是一个实现技巧，而是一个可验证的判断：先做物理校正会白扔 26% 的 clip（原文实测）。做这类流水线的人几乎都踩过这个坑。
  • 物理校正不是可选项，是生死线。同一批数据：运动学回放 + Diffusion Policy 在仿真上 L0/L1 成功率 0% / 1%，GR00T 是 6% / 5%（而且还用了 3.5–5 倍微调步数）；经过物理校正的数据，DP 是 53% / 40%，GR00T 是 65% / 50%。「合理的图像 + 动作标签」远不够，物理一致性才是数据能不能用的分界。
  • 成本结构做得漂亮。K=64 共享策略 → 2.8 GPU-分钟/clip，比 CHORD 便宜 42 倍、比 FlashDexRetarget 便宜 16 倍，质量还更高。它把「数据生产」从科研项目变成了可预算的工程。
  • mid-training 的价值被单独测出来了。同样 40K 微调步，GR00T 从 65% → 76%（L0）、50% → 57%（L1）；而单纯加长微调只把 L0 提到 82%、L1 还停在 50%。说明同本体大数据改善的是「留出摆放的泛化」，不是「拟合得更狠」——这个区分对数据采购决策很有用。

必须打的折扣

  1. 三分之二的数据被扔掉，而且主要原因是「几何不可行」。接受率约 1/3，作者自己指出：除采集缺陷外，大部分丢失是因为「固定躯干 + 固定基座」下根本不存在手臂能跟随的摆放。换句话说，这个 1/3 是「RB-Y1 这台机器人」的接受率，不是「方法」的接受率；换成移动底盘或可动躯干会变，但论文没测。
  2. 物理校正仍是整条链最贵的一环。几何部分已经是秒级（K=64 时 2.8 分钟/clip 里主要是 RL），而 RL 那部分是「每 ≤64 个 clip 训一个 PPO」。扩到万级 clip 时这部分怎么摊，论文没有给规模化曲线。
  3. 真机只做了 3 个任务、每层 5 次试验，样本量极小。而且有一组数很值得警惕：录制的仿真轨迹在真机上开环回放是 87% / 80%，但只用仿真数据微调的 GR00T 闭环只有 20% / 0%。开环能复现、闭环不能执行——这说明「物理可执行」的判据是在仿真里定义的，它并不能保证策略在真机上闭环可用。
  4. 「物理可执行」的度量是间接的。报告的是 ADD-AUC、SP-SR、MP-SR 三个指标，而它们都是「物体跟得像不像」的代理量，不是「接触力是否合理」「是否打滑」这类物理正确性指标。数据里记了每指法向接触力，但论文没有对接触质量做评估。
  5. 强依赖 9 个外部数据集的标注质量。手部姿态来自人工标注或跟踪，误差会一路传到重定向、IK、RL。论文用「重定向后指尖偏离」做过滤，但没有报过滤掉了多少、也没有报残留误差的分布——而这直接决定细粒度操作能不能学。
  6. 只在一种手（SharpA / Wuji 2）与一种双臂（RB-Y1，7 自由度固定躯干）上验证。「4 种灵巧手」只体现在生成规模上，没有做「换手对策略迁移影响」的实验。
一句话总结：它没有提出新策略，它把「人体数据」这条供应链上的两个断点分别用对的工具接上了。最值得带走的两条判断：① 求解顺序决定数据存活率——先约束可行域，再优化目标，反了就是白干；② 「物理可执行」必须由闭环仿真验证，光有合理的图像和动作标签，策略成功率会掉到个位数。而它留下的最大空白很清楚：接受率 1/3 里那 2/3 的损失，主要是机器人的形态决定的，不是数据决定的——那么「为采集而设计的机器人」会不会比「为数据而改进的算法」更划算？这个问题它提出了，但没回答。
