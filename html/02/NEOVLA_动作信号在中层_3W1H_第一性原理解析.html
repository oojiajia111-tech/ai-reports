💡 第一性原理核心立论

常规视觉语言动作模型的剧本是：先把画面压成一个视觉向量，再在这个向量上做动作决策。这篇论文先做了一次探针，然后才动架构——它逐层测"读到第几层最好办事"，结果发现对动作最关键的信息在视觉表征彻底成型之前就到峰值：冻结骨干时读第 28 层往外跳，比读最后一层高出四个多点，全量微调只能缩小、消不掉，单纯加规模也补不回来。于是它干脆不要视觉编码器，像素用轻量卷积直接进骨干，和语言一起演化，动作专家通过可配置的层映射去读中间层的缓存。真正刺眼的是反向实验：给编码器式模型硬接中间特征，冻结性能反而从 79.5 掉到 64.9。

What是什么：一个"结构上就没有编码器"的 VLA

先说清楚它反对的是什么。现有 VLA 几乎都建立在一个前提上：感知先被视觉编码器压缩，动作推理才开始。这个前提很自然——大模型时代所有多模态系统都这么搭。但论文指出，机器人操作依赖的恰恰是最容易被这种抽象弄丢的信号：局部几何、边界、深度、细微的状态变化。

它做的事（一句话）：把图像用轻量 patch 卷积切成 token，直接扔进骨干的语言 token 空间，与语言一起演化；旁边挂一个窄型的流匹配动作专家，通过可配置的层映射去读骨干中间层的 KV 缓存，预测连续动作块（双臂 + 机身）。

三个组件

组件干什么实现
patch embedder把像素变成 token，不做语义压缩轻量两级卷积，总步长 32；不用预训练视觉编码器、不用图像码本、不用自编码器

训练与数据

预训练语料来自 9 个公开数据集家族（AgiBot-World、Open X-Embodiment、DROID、RH20T、RoboMIND 等），合计 223 万条 episode、9,927 小时。训练分三段：① 冻结骨干、只训动作专家 → ② 全参数训练 → ③ 后训练微调。这个顺序不是随便排的，后面第 ④ 个公式会解释它为什么必须这样。

Why为什么：编码器是信息瓶颈，而且瓶颈的位置选错了

这篇论文最值得学的不是它的架构，而是它先做证据、再做设计的顺序。三段证据，一段比一段狠。

证据一：冻结骨干时，读早期层明显优于读最后一层
同一个模型，只改"动作专家读第几层"：读第 28 层（skip-28）拿到 90.9%，读最后一层（end-28）只有 86.7%。差四个多点，而且这四点不是靠换模型、加数据拿到的，只是换了一个"取货口"。
证据二：全量微调能缩小差距，但消不掉
这条最关键。如果差距只是"训练不充分"，全参微调后应该消失；如果只是"模型不够大"，加规模应该补回来。但它只是缩小，没有消除，而且单纯扩大规模也补不回来——说明这是结构性的：末层表征为了服务"理解/描述"，已经把那部分信息主动丢掉了。
证据三（反向实验，最狠）：给编码器式模型硬塞中间层特征，性能反而崩
把中间视觉塔的特征接到编码器式的 Qwen3-VL 上，冻结性能从 79.5% 掉到 64.9%。
这条说明关键不在"有没有中间层"，而在"表征怎么形成、怎么被暴露"。特征拼上去，但接口的训练方式没变，模型不知道怎么用它。
把三条证据串起来的判断：视觉编码器不是"压缩得不够好"，而是压缩目标错了。它为"把画面说清楚"优化——那是分类、检索、描述的优化目标；而动作要的是几何、边界、深度、状态的微小变化。为描述优化的表征，会把"这块布边翘起两毫米"当成噪声压掉。换更大的编码器不解决，因为优化目标没换。

为什么"免编码器"能成立：一张图的 token 数才是真正的成本

直觉上，扔掉编码器会让骨干直接吃像素，算力爆炸。但这里有个被忽略的账：编码器方案的成本并不低——它要先跑一个 ViT，再把特征投影进语言空间，中间还要对齐。而 patch embedder 用总步长 32 的两级卷积，把一张图压成很短的 token 序列，直接复用骨干的注意力。省掉的是"两套表征之间那道翻译"，不是省掉分辨率。

论文没有明说的推论是：真正的信息损失发生在"表征目标"这一层，不在"空间分辨率"这一层。这也解释了为什么相机扰动 94.5、语言扰动 91.7 都很稳——它保住的正是那些被编码器视为细节、但对操作很关键的量。

How怎么做：三个工程决定，每一个都在还上一段的债

决定一：不用码本、不用自编码器，但也不是"裸像素进 Transformer"

它保留了卷积——两级、总步长 32。这是很克制的选择：卷积自带局部性与平移等变这两个先验，正好对应"边界、局部几何"这类信号；而 Transformer 从零学这两个先验很贵。换句话说：扔掉的是"语义压缩"，留下的是"几何归纳偏置"。

决定二：位置编码按时间、高、宽三维分解

视频输入本质是三维的（时间 × 高 × 宽）。把它压成一维序列再套一维位置编码，等于告诉模型"时间相邻"和"空间相邻"是同一件事。三维分解的作用是让模型能区分"这里变了"和"这时变了"——而"什么时候发生了变化"恰恰是操作任务最需要判断的东西（东西滑了、门开了、手没对准）。

决定三：动作专家的层映射做成可配置

这是全文最实用的设计。它不硬编码"读第几层"，而是把层映射作为超参，允许动作专家从不同深度取特征。理由很简单：哪一层对动作最有用，取决于任务与数据，第 28 层只是在这个设置下的最优解，不该被焊死。

为什么训练必须"先冻骨、再全参"：
① 第一段冻结骨干、只训专家——骨干的表征不能动，专家必须先学会"怎么从给定的中间层读出动作"，这是接口先对齐。
② 第二段全参数训练——接口通了，才允许骨干按"对动作有用"重新塑形。
③ 反过来做（一上来就全参）会怎样？骨干会被动作损失迅速拉走，把语言理解能力破坏掉，而这正是它后面观察到的现象的反面教材。

顺手捡到的两个结论（对做工程的人比榜单更有用）

① 动作数据与理解数据要一起训，否则文本能力归零
协同训练：模型既保留文本输出，策略也最优。只微调动作：文本能力直接归零。含义很直白——把 VLA 当纯策略来训，等于把它的常识一起扔掉，而常识正是它泛化到新任务的本钱。
② 它稳的是"外观"，虚的是"构型"
作者自己交代：对视觉外观变化很稳（换纹理、换光照、换相机位置），但陌生空间构型和任务目标仍显著退化。这是一条很诚实的自我限定，也说明它学到的更多是外观不变性，而不是真正的三维几何理解。

Formula核心公式

① 两种范式：把"终点"换成一个"可选集合"
\[ \underbrace{a \sim \pi_\theta\big(a \mid E_\phi(o),\, l\big)}_{\text{编码器范式：一个固定终点}} \qquad\longrightarrow\qquad \underbrace{a \sim \pi_\theta\Big(a \mid \{h^{(k)}\}_{k \in \mathcal{L}},\, l\Big)}_{\text{原生范式：一组可选的中间站}} \]
\(o\) 观测（图像/视频），\(l\) 语言指令，\(E_\phi\) 视觉编码器，\(h^{(k)}\) 骨干第 \(k\) 层的隐藏表征，\(\mathcal{L}\) 层映射（哪些层供给动作专家）。
差别在哪：左边只有一个入口，而且这个入口是另一个模型（编码器）按另一个目标训练出来的；右边有多个入口，每一层都是骨干在"动作损失 + 语言损失"共同作用下长出来的。
为什么右边更强：\(\mathcal{L}\) 可选，意味着"哪一层的信息对动作最有用"由数据决定，不由架构预设。这是把归纳偏置从"人拍板"改成"可搜索"。
② 逐层探针：动作可分性在末层之前就到峰值
\[ S(k) \;=\; \text{Success}\Big(\pi\big(\cdot \mid h^{(k)}\big)\Big), \qquad \exists\, k^\* < L:\quad S(k^\*) > S(L) \]
\(S(k)\) 是"只读第 \(k\) 层"时的成功率，\(L=40\) 是总层数。论文实测 \(k^\* = 28\)：\(S(28)=90.9\% > S(40)=86.7\%\)。
这条不等式为什么重要：如果 \(S(k)\) 随 \(k\) 单调上升，说明"越深越好"，编码器范式没错。实测是先升后降——末层为了服务理解任务，主动把动作需要的信息压掉了。
它同时给了一个可复用的诊断工具：任何 VLA，只要做一次逐层探针，就能知道自己该在哪一层接动作头。这是全文最便宜、最可迁移的贡献。
③ 流匹配动作头：专家学的不是动作，是"把噪声推向动作的速度"
\[ \mathcal{L}_{\text{FM}}(\theta) \;=\; \mathbb{E}_{t\sim U[0,1],\;\varepsilon\sim\mathcal{N}(0,I)}\Big\|\, v_\theta\big(a_t,\, t \mid c\big) \;-\; \big(a_1 - a_0\big) \Big\|^2, \qquad a_t = (1-t)a_0 + t\,a_1 \]
\(a_0=\varepsilon\) 是纯噪声，\(a_1\) 是专家动作块（\(t=0\) 噪声，\(t=1\) 真动作），\(v_\theta\) 是网络预测的速度场，\(c\) 是条件（读到的中间层 KV + 语言）。
大白话：不直接回归"该出什么动作"（那样只会输出平均值，多峰任务上等于把两条可行路线平均成一条不可行的），而是学"从噪声走到动作，每一步往哪走"。推理时从噪声出发，沿速度场走 10 步欧拉就到了。
为什么这跟"免编码器"是配套的：流匹配需要条件 \(c\) 足够细才能生成多峰的精细动作；如果条件是把画面压成一个粗向量，速度场只能学到一个模糊的平均方向。接口的信息量，直接决定生成的分辨率。
④ 反向实验为什么崩：不是特征不好，是接口错配
\[ \Delta \;=\; S_{\text{frozen}}\big(\text{enc} + \text{mid-feat}\big) \;-\; S_{\text{frozen}}\big(\text{enc}\big) \;=\; 64.9\% - 79.5\% \;<\; 0 \]
把中间视觉塔特征直接拼给编码器式的 Qwen3-VL，冻结状态下掉了 14.6 个点。
正确的解释：中间层特征的统计分布与编码器输出完全不同（尺度、各向异性、语义密度都不一样）。骨干在预训练时只学会了"怎么读编码器输出"，突然多一路没见过的输入，等于在推理时改变了输入分布——这是典型的协变量偏移，冻结状态下无从适配。
所以这个实验证明了什么、没证明什么：它证明了"拼接中间层"这个做法不行；它并没有证明"编码器范式必然更差"。两者被放在一起讲，是这篇论文最容易被误读的地方（见第五节）。
但它顺带解释了训练顺序的必要性：正因为接口一换分布就变，才必须先冻骨训专家（让专家适配新接口）→ 再全参（让骨干适配动作目标）。顺序反了，两端同时漂移，训练必崩。
⑤ 延迟预算：282.5 ms 是什么概念
\[ f_{\max} \;=\; \frac{1}{T_{\text{query}}} \;=\; \frac{1}{0.2825\,\text{s}} \;\approx\; 3.5\ \text{Hz} \]
\(T_{\text{query}}=282.5\) ms（RTX 3090，单次查询）→ 上限约 3.5 Hz。
对比：常规 VLA 大致在 1 Hz 量级，所以 3.5 Hz 确实是进步；但高频闭环控制要 100–1000 Hz，差两到三个数量级。
结论：这类模型只能做慢回路（决定"往哪走、抓什么"），必须配一个独立的快回路（"手滑了赶紧收紧"）。它不是端到端替代控制器，而是替代大脑。

Worth价值与局限

核心价值：它把一个"没人质疑的默认前提"变成了可检验的命题。
① 方法论的干净：先逐层探针拿到证据，再改架构。绝大多数架构论文是反过来的——先造，再造理由。这种顺序本身就是贡献。
② 逐层探针是可以直接抄的工具：任何 VLA 团队花一天就能测出"我的动作头该接在第几层"，不需要重训。
③ 反向实验提供了真实的设计约束：不能靠"把好特征拼进来"获得能力，接口必须一起训。这条对做多模态融合的人有普遍价值。
④ 顺带确认了两条工程常识：动作与理解要协同训练（否则文本能力归零）；层映射不该写死。

批判性审视

  • "反向实验"与"架构结论"被混在一起，这是全文最大的逻辑缝隙：64.9% 那次崩溃，原因很可能是冻结状态下的输入分布错配，而不是"编码器范式不行"。如果允许全参微调那一版（而不是冻结），结果可能完全不同——但论文没有报这个数。用一个"接口没训"的实验去支持"架构不该这么搭"，证据强度被高估了。
  • 四个点（90.9 vs 86.7）没有给置信区间：成功率类指标在小样本评测上，三到四个点常常落在噪声里。论文没有报种子数、评测 episode 数、方差。而这四个点恰恰是整个架构决策的支点——支点不稳，后面全部推论都要打折。
  • 真机证据太薄：只有 3 个任务、各 50 条演示微调，成功率 12/20、17/20、13/20。每个任务 20 次试验，这个量级下 12/20 与 17/20 的差距本身就可能不稳。而"匹敌或超过 π0.5"这句对比，没交代 π0.5 是在什么数据量、什么后训练流程下测的——9,927 小时预训练对上一个未说明口径的基线，公平性无法判断。
  • "开源最好"的定语需要看清：LIBERO-plus 89.7 与 RoboTwin 69.4 都限定在"开源（代码 + 权重）"范围内。闭源系统（尤其是有大规模自有数据的）不在比较集里。这是常见但容易被读成"全面最好"的表述。
  • 基准本身接近饱和：LIBERO 平均 97.4 已经贴着天花板，能区分方法的空间很小；LIBERO-plus 与 RoboTwin 更有信息量，但它们的扰动类型（相机、语言、Clean2Rand）恰好是"外观与指令"层面，而作者自己承认陌生空间构型显著退化。也就是说：它的强项正好被基准覆盖，弱项正好没被测。
  • "免编码器"在小数据场景下的风险没被讨论：预训练用了 9,927 小时、223 万 episode。这个规模下，骨干可以自己学出视觉表征。但如果只有几百小时数据，编码器携带的通用先验就是不可替代的。论文的结论很可能只在"大数据 + 大骨干"这个区间成立，而绝大多数机器人团队不在这个区间。
  • 层映射成了超参，等于把问题挪了个位置：可配置听着优雅，但意味着每换一个本体 / 任务分布，可能要重新搜一遍。论文没有给出"层选择对任务有多敏感"的曲线——如果很敏感，这套架构的迁移成本会比看上去高。
  • 延迟数字的硬件口径偏保守，反而可能是加分项：282.5 ms 是在 3090 上测的。这条要公平地说——换成机器人常用的边缘板卡只会更慢，所以作者用消费级卡测，是在给读者一个乐观下界。这一点值得肯定，但也意味着真机部署的真实延迟会更难看。
