一句话 触觉不该重复视觉已经说过的话，它只该报告「视觉还不知道的那件事」
💡 第一性原理核心立论

给 VLA 加触觉，效果却经常不稳定，有的视触觉模型甚至几乎不看触觉输入。原因很朴素：大部分触觉变化，本来就能从画面和刚做完的动作里推出来——夹爪一合，胶体怎么变形是可预测的。真正值钱的只有那点「视觉和动作都解释不了」的残差，TacInno 把它命名为触觉新息，并且只拿它当训练目标：先用一个压缩器把未来触觉变化压成 4 个 16 值离散码，再让策略去猜这个码。猜码这件事逼着模型去盯接触发生的那一瞬，而不是继续懒在画面上。而猜码模块在部署时被整块扔掉，机器人只多留一条触觉分支。

What是什么：把「触觉该学什么」这件事，改写成一个减法

先说一个很多人没注意到的尴尬事实。过去两年，给 VLA 加触觉这条路上，收益一直不稳定。有的工作报告提升十几个点，有的报告几乎没动，还有一类现象更刺眼——训出来的视触觉模型几乎不依赖触觉输入，你把触觉换成一张静止的空接触帧，它的成功率掉得很少。

这不像「传感器不够好」或「触觉太稀疏」能解释的。这更像是模型找到了捷径。而捷径之所以存在，是因为信号里本来就有大量重复：夹爪闭合时那层胶体会怎么被压、压多深，这件事从图像序列加上你刚发出的那条夹爪闭合指令，基本就能算出来。既然能算出来，模型就没必要去读触觉——触觉在这个意义上是「可被替代的信息」。

TacInno 的切入点是一个减法，不是一个加法。它不去问「怎么把触觉更好地融进去」，而是先问：触觉信号里，有多少是视觉加上已执行动作解释不了的？把那部分单独拎出来，叫 tactile innovation（触觉新息）——借的是控制论里 innovation 的老词义：观测里「不能被预测的那部分意外」。然后它做了一个很硬的取舍：只把这个残差当训练目标，不把原始触觉当拟合对象。

具体形态上，它分两步落地。第一步是个离线压缩器（tokenizer）：把未来 15 步的触觉变化，压成 4 个 token、每个 token 16 个取值（合计 16 bit）的离散码——注意这个码不是压缩全部触觉变化，而是只压缩那个残差。第二步是把码预测塞进 VLA 当辅助任务：策略在动作专家里插 4 个可学习的 code query，让它们去猜这条演示对应的码。

论文报的数字是：仿真 6 个任务平均 87.5%，比最强的视触觉基线高 10.7 个点；真机 4 个任务平均 70.5%，高 9.0 个点。而且它是唯一一个在每个仿真任务上都 ≥75% 的策略。

Why为什么：三层冗余，一层比一层隐蔽

矛盾一：触觉确实有信息，但它和视觉高度重叠

人的直觉是「触觉提供了视觉没有的东西」，这话在接触瞬间成立，但在整段操作里不成立。一次抓取里，触觉真正独占的信息只出现在极短的窗口：刚要碰上的那一刹那、以及物体开始滑但还没滑到肉眼可见的那几帧。其余时间，触觉在重复报告「我正按着它」——而这件事相机早就看见了。信息重叠的后果不是「多余」，而是「可被忽略」：模型在训练里发现不读触觉也能把损失降下去，它就会把这条通路压到很弱。

矛盾二：把整段触觉当监督目标，等于在教模型复述已知

大多数视触觉 VLA 的训练目标是「根据观测预测未来触觉」。这个目标里 60% 以上的内容是可以从视觉里推出来的，模型完全可以靠画面把损失压低，触觉分支学到的只是「怎么把图像翻译成触觉图」——它学到的是跨模态翻译，不是接触动力学。这才是「加了触觉却没涨点」的真正机制：监督信号本身被冗余稀释了。

矛盾三：怎么定义「冗余」，取决于你把哪只眼睛放进条件里

这是全文最精细的一处设计，也是最容易被略过的一处。残差是相对「条件」定义的：条件给得越多，残差越小。如果把条件设成「当前触觉 + 未来视觉 + 已执行动作」，那残差就是「连未来画面都看不见的那些触觉变化」。为什么敢把未来视觉放进去？因为闭环策略在后续时刻真的会看到那些画面——凡是窗口内会变成可见的接触响应，相机迟早会给答案，触觉没必要重复报一遍。

这条设计的代价也说清楚：它把「触觉的必要性」绑定在「视觉的可见性」上。一旦接触发生在遮挡里（手指背面、袋子里、料箱深处），那个「未来视觉」条件其实拿不到有效信息，残差定义就退化了。换句话说，这套方法在「看得见的世界」里最锋利，在「看不见的世界」里它的前提就松了。论文的消融里有个数字很说明问题：无条件化（码去编码全部触觉变化）时成功率从 83.0 掉到 62.0，整整 21 个点——冗余确实是主要矛盾，但这也说明剥离条件的方式一旦选错，代价是断崖式的。

How怎么做：四步，从「算不算得出来」到「猜一个 16 bit 的码」

第 1 步：先切窗口，再算残差——把连续触觉变成「未来 15 步的累计变化」
在第 t 步取四个时刻 t、t+5、t+10、t+15，把每一个都写成相对 t 的累计变化。这一步的意义是：不预测每一帧的触觉像素，只预测「窗口结束时相对现在差了多少」。累计量比逐帧量更稳（噪声被积掉一部分），也更贴任务——抓取成功与否，本质上取决于最后那点差值到不到位。
第 2 步：让压缩器在「看得见答案」的条件下做减法
压缩器（tokenizer）的编码器和解码器都以视觉观察和已执行动作为条件。编码器的角色是逆动力学：看完整窗口（含未来触觉），把这段变化压成四个潜向量；解码器的角色是前向动力学：只看当前触觉 + 那四个码，一次前向重建三个未来时刻的累计变化。关键在解码器：它在 t 之后不再接收任何触觉观察，所以残差信息只能通过那 4 个码流过去。这个「信息瓶颈」就是强迫码携带残差的机制——不是靠损失函数约束，是靠结构断掉旁路。
第 3 步：把高维残差压成 16 bit，用 VQ 落地
残差是逐像素的变化场，维度高到无法直接当预测目标，所以退一步：学一个 4 token、每 token 16 值的离散码当代理。每个 token 有自己独立的码本（16 个可学习向量），取最近邻的索引。编码器是时空 Transformer——帧内做空间注意力、帧间做因果时序注意力，图像特征用冻结的 DINOv2。因为时序注意力是因果的，只有最后一帧附加的 4 个 query 能看到整个窗口，它们的输出就是这四个码。重建用接触加权 L1：接触区域的误差权重更高，毕竟非接触区的触觉图本来就近似常量。
第 4 步：让策略猜码，但堵住它「偷看」
在 π0.5 的动作专家里，噪声动作 token 前面插三组条件：本体感觉 token、60 个触觉 token（来自 t−8、t−4、t 三帧触觉）、以及 4 个可学习 code query。然后加一个块状注意力掩码：code query 可以看前面所有内容，但除它自己之外，任何 token（尤其是动作 token）都不许回头看 code query。这一条是硬约束——它保证「猜码」是纯辅助任务，不会反向污染动作预测的通路。消融很直白：把这个掩码去掉（动作 token 能看 code query），成功率从 83.0 掉到 68.0，整整 15 个点。
部署时把脚手架全撕掉：tokenizer、接触状态预测头、码分类头全部移除，线上模型就是「π0.5 + 一条 60 token 的触觉分支」。这一点很关键——它不是「推理时多算一步」的方法，而是「训练时多一个任务、推理时零成本」的方法。训完之后，触觉新息这个概念就从模型里消失了，只留下被它塑造过的注意力结构。

Formula核心公式：五个式子，从「累计变化」走到一个 16 bit 的码

① 累计触觉变化：不看逐帧，看窗口末端的差值
\[ \Delta X_{t:t+5k} \;=\; X_{t+5k} - X_{t}, \qquad k \in \{1,2,3\} \]
\(X_t\) 是 t 时刻的触觉图像（GelSight 式传感器的胶体变形图），\(k\) 取 1、2、3 分别对应未来 5、10、15 步。大白话：与其一帧帧预测触觉图怎么变，不如只问「15 步之后，相对现在差了多少」。累计量把高频噪声积掉了一部分，同时天然对齐任务目标——抓没抓住，看的就是这个差值够不够大。
② 触觉新息的定义：把变化拆成「可解释」与「意外」两半
\[ \Delta X_{t:t+5k} \;=\; \mathbb{E}\!\left[\Delta X_{t:t+5k} \,\middle|\, X_t,\, o_{t:t+5k},\, a_{t+1:t+5k}\right] \;+\; \nu_{t:t+5k} \]
\(o\) 是视觉观察（注意包含窗口内的未来帧），\(a\) 是已执行的动作，第一项是「给定当前触觉、未来画面、已做动作之后，能被预测出来的那部分」，残差 \(\nu\) 就是触觉新息——视觉和动作都解释不了的那点东西。大白话：这就是一个减法：全部触觉变化，减掉「画面能告诉你的 + 你刚做的动作能推出的」，剩下的才是触觉的独家情报。而残差大小直接决定了方法有没有意义：论文实测 6 个任务平均只有 37% 的触觉变化不可解释——也就是说有 63% 是冗余的。
③ 压缩器三步：编码 → 量化 → 一次前向重建
\[ z_t = E\!\left(X_{t:t+15};\, o_{t:t+15},\, a_{t+1:t+15}\right), \quad c_t = \mathrm{VQ}(z_t), \quad \{\Delta \hat{X}_{t:t+5k}\}_{k=1}^{3} = D\!\left(X_t,\, c_t;\, o_{t:t+15},\, a_{t+1:t+15}\right) \]
\(E\) 是以视觉和动作为条件的逆动力学编码器，\(z_t\) 是 4 个潜向量，\(\mathrm{VQ}\) 是向量量化（每个 token 一套含 16 个向量的独立码本），\(c_t\) 是 4 个 4-bit 索引，\(D\) 是前向动力学解码器。大白话：编码器「看着答案把题目压缩成 16 bit」，解码器「只拿这 16 bit 加上当前触觉，把三个未来差值重建出来」。整个设计的信息瓶颈就在 \(c_t\)——解码器在 t 之后看不到任何触觉，所以想重建残差，只能把残差塞进这 16 bit 里。这就是「结构保证语义」的典型写法。
④ 码预测损失：四个分类头的平均交叉熵
\[ \mathcal{L}_{\text{code}} \;=\; -\frac{1}{4}\sum_{s=1}^{4} \log p_s\!\left(c_t^{(s)} \,\middle|\, h_s\right) \]
\(h_s\) 是第 s 个 code query 在最后一层的隐状态，\(p_s\) 是它给出的 16 类分布，\(c_t^{(s)}\) 是压缩器为这条演示打好的标签。大白话：让四个 query 各自猜自己那 4 bit，标准答案由离线压缩器提供。这里有个易被忽略的细节：码是「离线打好」再拿来当监督的，所以这套方法多了一道预处理工序——每条演示都要先过一遍 tokenizer 打码，这不算推理成本，但算工程成本。
⑤ 总目标：主损失 + 两个按比例配平的辅助项
\[ \mathcal{L} \;=\; \mathcal{L}_{\text{flow}} \;+\; \lambda_{\text{contact}}\,\mathcal{L}_{\text{contact}} \;+\; \lambda_{\text{code}}\,\mathcal{L}_{\text{code}} \]
\(\mathcal{L}_{\text{flow}}\) 是 VLA 原本的流匹配损失，\(\mathcal{L}_{\text{contact}}\) 来自一个接触状态预测头（预测接触面积、剪切、压痕深度等），它存在的原因是：新息是相对当前接触状态的偏差，得先把「当前状态」这个基准定住，偏差才有意义。两个 \(\lambda\) 的设定方式是「让训练开始时每个辅助损失等于主损失的 15%」——这是经验配平，不是理论推导，也是这类多任务训练里最不好复现的一环。

Worth价值与局限：它把「要不要触觉」换成了「触觉该报什么」

它真正贡献了什么

  • 把问题从「融合方式」挪到了「监督目标」。过去视触觉 VLA 的改进大多在改融合结构（怎么拼 token、怎么对齐模态），而这篇指出瓶颈不在结构，在标签：你拿冗余的信号当目标，结构再精巧也学不到接触动力学。这个诊断比它的方法更值钱，因为它解释了「为什么加触觉的收益一直不稳定」这个长期困扰。
  • 用信息瓶颈代替损失约束。「只让码携带残差」不是靠一个惩罚项逼出来的，而是靠「解码器在 t 之后看不到触觉」这个结构断掉旁路实现的。这类「结构保证语义」的做法通常比加权惩罚稳得多——惩罚项会被模型用各种方式绕过，断掉的通路绕不过去。
  • 把条件设成「未来视觉」是一个可迁移的判断。它明确了触觉的职责边界：触觉不该报告「已经会变成可见的东西」，只该报告「可见性到来之前的那段先行信号」。这个判断对任何多模态机器人系统都成立，不限于触觉。
  • 推理零成本。压缩器和两个辅助头部署时全扔，线上只多一条 60 token 的触觉分支。对比那些「推理时多跑一个模块」的方案，这类做法的工程存活率高得多。
  • 它给出了触觉依赖的硬证据。触觉关闭测试（把输入换成固定无接触帧）：TacInno-VLA 在易拉罐任务上成功率从 88% 掉到 0%，而多数基线只掉一部分、FTP-1 甚至在某任务上还涨了。这是「模型真的在用触觉」最直接的证据，比任何融合结构的对比都硬。

必须打的折扣

  1. 「只有 37% 不可解释」这个数字，既是立论也是天花板。它的意思是：63% 的触觉信号被明确判定为冗余并丢弃。如果任务恰好落在那 63% 里（比如大面积贴合、准静态按压），这套方法能提供的新信息就非常有限。而论文没给出「按任务看这个比例如何分布」——平均值 37% 掩盖了任务间的巨大差异。
  2. 残差的定义依赖「未来视觉可用」，遮挡场景下前提就松了。接触发生在手指背面、袋子内部、料箱深处时，那个条件拿的是无效信息，残差会退化成「全部触觉变化」，等于退回无条件化的 62.0% 那一档。而真实产线上，遮挡恰恰是触觉最该发挥作用的场合——这套方法在最需要触觉的地方，理论基础最薄。
  3. 依赖一个特定底座，泛化性未验。全部实验都建在 π0.5（PaliGemma 视觉语言骨干 + 300M 动作专家 + 流匹配）上。换到扩散策略、换到别的 VLA 架构，这套「插 code query + 加掩码」的做法是否同样有效，论文没有回答。而「辅助任务插进动作专家」这件事本身对架构相当敏感。
  4. 数据规模偏小，且每任务独立训练。仿真每任务 100 条演示（策略只用前 50 条）、真机每任务 50 条遥操作演示，是「每任务一套策略」而非一个跨任务通用策略。87.5% / 70.5% 的成绩在这个规模下是可信的，但它不能推广成「触觉新息让通用 VLA 变强」。
  5. 70.5% 的真机成功率，离可用还有距离。四个任务里最容易的（扶正易拉罐）在触觉关闭时掉到 0%，这个反差说明策略对触觉形成了强依赖，而这既是优势也是脆弱性——传感器一旦漂移、污染、或换型号，性能可能不是缓慢下降而是骤降。论文没有做传感器扰动下的鲁棒性实验。
  6. 多了一道离线工序，工程上不算零成本。每条演示都要先过 tokenizer 打码才能训练策略。这意味着数据管线多一个环节、多一份一致性要求（打码用的 tokenizer 和策略训练用的必须是同一份）。在数据规模上到几十万条时，这个环节的运维成本会显性化。
  7. λ 的配平方式是经验值，复现门槛藏在细节里。「训练开始时辅助损失各占主损失 15%」是个说明清楚但不好迁移的设定。换数据集、换底座、换动作维度，这个 15% 是否还成立，论文没给敏感性分析。这类多任务辅助损失的实际收益，对权重相当敏感。
  8. 作者自己承认概念没推广。原文写得很老实：innovation 这个概念并不专属触觉，扩展到其他模态留作未来工作。换句话说，这篇只证明了「触觉这一个模态存在大量冗余」，而「哪些模态组合里还存在同类冗余」仍是开放问题。
一句话总结：它没有让触觉变强，它让触觉不再说废话。而这件事的意义比涨点更大——它把「多模态融合」这个笼统命题，拆成了一个可以逐模态追问的具体问题：这个传感器，有多少信息是别人已经说过的？对触觉，答案是 63%。这个数字一旦问出来，很多「加了传感器却不涨点」的困惑就有了统一的解释路径。更值得记住的是它的手法：想逼模型学某样东西，最好的办法不是给它加权，而是把其他所有能解释答案的通路全部堵死。
