💡 第一性原理核心立论

跨具身学习一直卡在一个假前提上：以为要让不同身体共用经验，就得先把它们的动作对齐成同一种表示。但人的五指和机器人的两指夹爪本来就没有共同的"关节语义"，硬对齐只会得到一个谁都不像的平均身体。EgoX 换了切法：不去统一身体，而是把每个身体拆成功能对应的部件——躯干、左右腕、末端关键点，各部件配各自的编码器，只在中间留一条共享主干；再补一条只在训练时存在的"做梦"损失，逼主干从当前画面猜出这个身体下一刻的画面特征和关节特征。这样主干学到的是"身体怎么动"，而不是"画面长什么样"。

What是什么：把"统一身体"换成"统一部件的接口"

先说清楚它要解决的那个具体麻烦。机器人操作的数据有三个来源：人拍的视频（量大、场景杂、没有动作标签）、真机遥操作（有动作、但一个机器人一种格式）、仿真（可控、但和真机有差距）。三者的价值是互补的，但它们的"身体"完全不同：

差异维度人类人形机器人桌面机械臂 / 四足
外形双手五指，身高 1.7 m双手五指或三指，身高 1.3 m单臂或腿上挂夹爪，工作空间只有半米
感知头戴相机，视角随头动头部主相机 + 腕部相机常常只有一路主相机
本体感受几乎没有（只能反解手腕位姿）全身关节角 + 手部关节角6~7 个关节角 + 夹爪开合
动作接口没有（视频里只有结果）关节目标 + 末端位姿 + 底盘速度末端位姿 + 夹爪

EgoX 的做法是不去消除这些差异，而是把差异关进"接口"里，让中间那段共享。整个框架就三件事：

① 统一的模态表 + 统一的自我中心坐标系：把每个身体的观测和动作拆成"命名模态"——主相机图、本体关节、躯干位姿、左/右腕位姿、左/右末端关键点。位姿一律换算到三个规范系里（根部系、主相机系、腕部系），关节角则保留各自的原生空间。
② MXT+：每个模态一个编码器，每个动作模态一个专家，中间一条共享主干。共享主干是唯一跨身体的东西，其余全是"这个身体专属"的。
③ 具身做梦（embodiment dreaming）：一条只用于训练的辅助损失，从当前共享表征去预测这个身体未来时刻的潜表征（画面特征 + 关节特征），逼主干把"身体动力学"编码进去。

Why为什么：跨身体真正不变的，不是关节，是"部件的角色"

这条推演链有五环，每一环都是被上一环逼出来的。

第一步：数据缺口是硬约束，绕不过去
机器人数据的采集成本是"人站在设备前遥操作"，一小时几十条轨迹；人拍视频的成本约等于零。所以只要人类视频能被用上，数据量就多一个数量级。这不是"想不想要"的问题，是"不这么做就永远缺数据"的问题。仿真是第三条腿，但仿真到真机还有落差。
第二步："统一动作空间"这条路，从数学上就不成立
通行的做法是把不同身体的动作拼成一个固定长度的向量，缺的补零。但补零是有代价的：零不是"没有这个关节"，零是一个具体数值。模型看到 30 维里 24 维是零，会把"零"当成"这个关节保持不动"的信号，于是学会了"大部分时候什么都别动"。更根本的问题是维度语义不对应——人类第 3 维是食指弯曲，机器人第 3 维可能是底盘的横向速度。把两者放进同一个坐标轴，等于宣告"食指弯曲"和"横移"是同一个方向的两种强度。这是范畴错误，不是精度问题。
第三步：那就找真正跨身体不变的那个量
不变的是什么？不是关节，而是几何关系与任务阶段：躯干相对地面在哪、腕相对相机在哪、指尖相对腕在哪。这些量在任何人、任何机器人身上都有，且语义一致——"指尖碰到杯柄"这件事，在五指手和两指夹爪上是同一个物理事件。所以正确的切分不是"按关节编号切"，而是"按功能角色切"：躯干一类、腕一类、末端点一类。切完之后，每个身体提供自己有的那几类，缺的留空而不是补零。
第四步：但共享主干会偷懒——这是设计里最隐蔽的坑
一旦把编码和解码都做成"每身体专属"，主干就面临一个诱惑：它只需要学"共性的浅层"，把每个身体的动力学差异全部推给各自的编码器。这样动作损失照样能降，因为编码器可以替主干把活干了。主干退化成一个路由器——参数是共享了，知识没有共享。论文的消融其实抓到了这个现象：粗粒度版本（所有相机共用一个编码器、所有动作共用一个专家）在预训练后反而掉分，甚至在厨房清理任务上直接归零。因为它把"速度指令"这个只占 51 维里 3 维、但对移动操作生死攸关的模态，淹没在了合并后的动作空间里。
第五步：所以要有一条损失，专门逼主干学动力学
行为克隆只监督"动作"，从不要求模型"预判身体会怎么变"。于是主干可以完全不懂动力学，照样把动作拟合出来（因为当前帧已经足够决定下一步该干嘛）。补一条预测未来的损失就堵住了这个漏洞：要预测未来，主干必须先在内部建立一个"这个身体受这个动作会怎么演化"的模型。这就是做梦的全部动机——不是让模型生成画面，是让主干没法再偷懒。
五环串起来：数据永远不够 → 硬统一动作空间在语义上不成立 → 改按功能部件切、按规范系对齐 → 但共享主干会退化成路由器 → 所以加一条"预测未来潜表征"的损失逼它学动力学。
这条链里没有一个模块是"为了显得先进"加进去的，每一个都是被上一个约束逼出来的。这是判断一篇系统论文是否扎实的最简单标准。

为什么"做梦"预测的是潜表征，而不是像素

最直觉的版本是让模型预测未来的画面（世界模型那条路）。论文明确避开了：重建像素会把容量花在纹理、光照、背景上，而这些东西跟"身体怎么动"几乎无关。改预测一组压缩后的潜表征（8 个 token），等于把"要预测什么"这道题的答案收窄到"语义与几何的变化"上。而且预测潜表征不需要解码器、不需要在部署时算未来帧——训练完这条支路就可以整个扔掉。

为什么要用 EMA 教师 + 停止梯度

如果学生自己和自己的目标一起动，这条损失会退化：把目标往预测值上拽，损失瞬间归零，什么也没学到。这是自监督学习里非常经典的塌缩。论文用 JEPA 家族的标准解法：目标的编码器是学生编码器的指数滑动平均（更新极慢），且目标一侧停止梯度。等于给学生一个"缓慢移动、不会跟着你跑"的靶子。

为什么值得信：它量了表征，不只量了分数

GW（Gromov-Wasserstein）距离衡量的是两个分布内部的距离结构有多像——不是比两个向量的绝对位置，而是比"谁和谁近、谁和谁远"这张关系表。用它来比"人类舀猫砂"和"机器人舀猫砂"的表征分布，是在问：同一个任务，在两种身体上被编码成了相似的几何形状吗？

结果是：预训练让它降了 21.30%（10 对里 9 对），而"做梦"单独让它降了 38.52%，10 对全降。这条数字比成功率更能说明问题——因为成功率会被控制器调参、试验初始位形这些噪声污染，而 GW 直接读的是表征本身。一篇论文愿意补这类指标，通常说明作者自己也在怀疑"分数涨了是不是因为别的原因"。

How怎么做：三处设计，一处反直觉

决定一：按功能部件对齐，不按自由度对齐

每个身体被拆成命名模态，每个模态配一个专属编码器，编码结果投到同一个 token 空间。关键在于坐标系的规范：

量表达在哪个系为什么
躯干位姿、底盘速度指令根部系（脚下/身下地面投影）和"身体站在哪"绑定，跨身体可比
左右腕位姿、腕部目标主相机系（自我中心）和"我看到什么"绑定，天然对齐视角
末端关键点位置各自腕部系描述手本身的几何，而不是关节角——这是让五指手、夹爪、固定铲子能互通的关键
关节角各身体原生关节空间不强行换算，保留本体感受的差异

第三行是这套设计里最要紧的一格。末端关键点（指尖、夹爪接触点）描述的是"手能碰到哪"，而不是"关节转了多少度"。所以一个 22 自由度的灵巧手和一个 2 指夹爪，在"关键点位置"这个模态上是可以直接对话的——它们说的都是三维空间里的点。

决定二：模态级拆分，粗粒度合并会崩

论文专门做了粗粒度对照：相机视图合并成一个编码器、位姿和本体感受拼在一起、所有动作模态共用一个专家。结果很有说服力：

场景粗粒度 + 预训练模态级 + 预训练说明
Z1 固定铲子（模态最少）有提升有提升差距小——模态少，拆不拆无所谓
xArm7 舀取掉分多数提升预训练反而有害
仿真厨房清理（双臂 + 移动）任务进度直接 0保持可观水平速度指令只占 51 维里 3 维，合并后被淹没

这张表是全文最有工程价值的一张。它说明"共享"不是越多越好：当某个模态的信息量小但对任务生死攸关（3 维速度指令决定机器人能不能走到桌前），把它和 48 维的关节目标拼在一个专家里，梯度会被大模态主导，小模态学不到东西。模态级拆分的真正作用是给小模态一个不被淹没的通道。

决定三：做梦只在训练时存在，部署零开销

这是设计上最省的一笔。训练时：学生编码器处理当前观测 → 主干 → 做梦专家输出未来 k 个时刻的潜 token → 和 EMA 教师处理真实未来观测得到的潜 token 对齐。部署时：做梦专家、EMA 教师全扔掉，只留学生编码器 + 主干 + 动作专家。不需要未来帧、不需要额外前向、不需要生成任何像素。

对比一下世界模型那条路：预测未来画面意味着推理时也要跑一遍生成，每步几十毫秒到几百毫秒，控制频率直接被压到 5 Hz 以下。EgoX 把"训练期的特权信息"用在了训练期就结束，没有把它变成推理期的债。

训练流程：预训练求和，微调只算目标身体

阶段数据损失更新谁
① 跨具身预训练人类 + 多个机器人 + 仿真，每身体一个小批次各身体损失相加（动作 + 做梦）主干吃所有身体的梯度；各身体的专属模块只吃自己的数据
② 目标身体微调目标身体 + 目标任务的演示动作 + 做梦全部（含目标身体的专属模块）

有个细节值得记下来：预训练时每个身体采等量的一个 mini-batch。这保证了小数据集（人视频量大、某个四足机器人数据少）不会被大数据集压死，代价是小数据集的样本被反复复用，容易过拟合——作者自己把这个写进了局限。这是"公平采样"和"不过拟合"之间的硬取舍，没有免费的解法。

规模与口径（读数字前必须知道的）

  • 5 个任务 × 6 种身体 = 13 个任务-身体对；6 种身体里 5 个真机 + 1 个仿真人形（G1 仿真）。
  • 真机每个对跑 20 次（13 次分布内 + 7 次分布外），仿真每对跑 50 次。同一套初始条件对所有方法一致。
  • 评价指标是归一化任务进度，不是纯成功率——把中间阶段也计分，避免长任务全是 0 分看不出差别。
  • 潜表征取主干输出里"右腕位姿"那一组 token，池化成 512 维向量来算 GW 距离（因为舀取任务里右腕是唯一跨身体都活跃的末端）。

Formula核心公式

① 策略的三段式分解：共享的只有中间那一段
\[ \pi^{e} \;=\; \Psi^{e}\,\circ\,G_{\theta}\,\circ\,\Phi^{e}, \qquad \Phi^{e}=\{\phi^{e}_{m}\}_{m\in\mathcal{M}^{e}_{\mathrm{obs}}}\cup\{\phi^{e}_{\mathrm{dream}}\}, \qquad \Psi^{e}=\{\psi^{e}_{m}\}_{m\in\mathcal{M}^{e}_{\mathrm{act}}} \]
\(e\) 是某个身体，\(\phi^{e}_{m}\) 是这个身体第 \(m\) 个观测模态的编码器，\(\psi^{e}_{m}\) 是第 \(m\) 个动作模态的解码专家，\(G_{\theta}\) 是所有身体共用的主干。\(\mathcal{M}^{e}_{\mathrm{obs}}\)、\(\mathcal{M}^{e}_{\mathrm{act}}\) 是这个身体实际提供的模态子集。
大白话：两头各说各的方言（身体专属编码器/专家），中间那个翻译官（主干）说普通话。公式里唯一带 \(\theta\) 的、唯一跨身体共享的，就是 \(G_{\theta}\)——所有别的模块都挂着上标 \(e\)。
为什么这么切：如果把编码器也共享，等于要求"人的手部图像"和"夹爪的手部图像"进同一个编码器后输出同一种东西——这在像素层面根本不成立。共享必须发生在语义已经对齐之后，不能在原始信号上强行共享。
② 动作块预测：一次出一整段，按模态分别解码
\[ \hat{\bm{A}}^{e}_{t}=\pi^{e}\!\left(\bm{o}^{e}_{t}\right)=\left(\hat{\bm{A}}^{e,m}_{t}\right)_{m\in\mathcal{M}^{e}_{\mathrm{act}}}, \qquad \hat{\bm{A}}^{e,m}_{t}=\left(\hat{\bm{a}}^{e,m}_{t+k}\right)_{k=0}^{H-1}\in\mathbb{R}^{H\times d^{e}_{m}} \]
\(\bm{o}^{e}_{t}\) 是当前观测（一组命名模态的元组），\(H\) 是动作块长度，\(d^{e}_{m}\) 是这个身体第 \(m\) 个动作模态的维度。
大白话：不是一步一步出动作，而是一次吐出未来 \(H\) 步的整段轨迹，每个模态（躯干、左腕、右腕、左手、右手）各出一条。分模态输出而不是拼成一条长向量，是上面那个"3 维速度指令被 48 维关节淹没"问题的直接解法。
缺模态怎么处理：观测缺的补零 token，动作缺的直接不进损失——这一点很重要，补零进损失会让模型学会"预测零"，等于主动教它别动。
③ 做梦的目标：用"慢半拍"的教师去标注这个身体的未来
\[ \bm{Y}^{e}_{t+k}=\mathrm{sg}\!\left[\,\bar{\phi}^{e}_{\mathrm{dream}}\!\left(\left[\,\bar{f}^{e}_{m}\!\left(\bm{o}^{e,m}_{t+k}\right)\right]_{m\in\mathcal{M}^{e}_{\mathrm{dream}}}\right)\right], \qquad \bar{w}\leftarrow\alpha\,\bar{w}+(1-\alpha)\,w \]
\(f^{e}_{m}\) 是模态编码器里"聚合之前"的特征提取段（含位置编码），\(\phi^{e}_{\mathrm{dream}}\) 用 8 个可学习查询通过交叉注意力把这些特征压成 8 个潜 token；带上划线的 \(\bar{\phi}\)、\(\bar{f}\) 是它们的 EMA 教师副本；\(\mathrm{sg}[\cdot]\) 是停止梯度；\(\alpha\) 是衰减系数。
大白话：学生看现在，教师要它去猜"未来那一刻，这个身体的画面特征和关节特征会被压成哪 8 个向量"。教师要"慢半拍"是因为——
不慢半拍会怎样：学生和教师一起追着预测值跑，目标自己往预测值上滑，损失几秒内归零，模型什么也没学到。这是自监督里的塌缩。EMA 相当于把靶子钉在地上，只允许它极缓慢地挪。停止梯度则是防止梯度从目标反流回去继续帮着塌缩。
④ 做梦损失：只对齐方向，幅值单独管
\[ \mathcal{L}^{e}_{\mathrm{dream}}=\frac{1}{|\mathcal{K}|L_{\mathrm{dream}}}\sum_{k\in\mathcal{K}}\sum_{j=1}^{L_{\mathrm{dream}}}\Big[\,1-\cos\!\left(\hat{\bm{y}}^{e}_{t+k,j},\ \bm{y}^{e}_{t+k,j}\right)\;+\;\beta\,\ell_{\text{smooth-L1}}\!\left(\left\|\hat{\bm{y}}^{e}_{t+k,j}\right\|_{2},\ \left\|\bm{y}^{e}_{t+k,j}\right\|_{2}\right)\Big] \]
\(\mathcal{K}\) 是采样的未来时间偏移集合，\(j\) 遍历 8 个潜 token，\(\beta\) 是幅值项权重。
为什么用余弦而不是均方误差：余弦只管方向，不管长度。潜空间里向量的绝对长度没有物理意义（可以被整体缩放而不改变语义），但方向承载了"这个状态往哪走"的信息。用 MSE 会逼模型去匹配一个无意义的长度，把容量浪费掉。
那长度真的完全不用管吗：也不。长度可能承载"变化有多剧烈"这类信息，所以论文留了一个轻量的幅值项（只比两个向量的模长，用 smooth-L1），\(\beta\) 控制它的分量。这是"主对齐方向、副对齐强度"的分工。
⑤ 总目标：单身体损失、预训练求和、微调只算目标身体
\[ \mathcal{L}^{e}(\mathcal{D})=\mathbb{E}_{\mathcal{D}}\!\left[\mathcal{L}^{e}_{\mathrm{act}}+\lambda^{e}_{\mathrm{dream}}\,\mathcal{L}^{e}_{\mathrm{dream}}\right], \qquad \mathcal{L}_{\mathrm{pre}}=\sum_{e\in\mathcal{E}_{\mathrm{pre}}}\mathcal{L}^{e}(\mathcal{D}_{e}), \qquad \mathcal{L}_{\mathrm{ft}}=\mathcal{L}^{e^{\star}}\!\left(\mathcal{D}^{\mathrm{task}}_{e^{\star}}\right) \] \[ \mathcal{L}^{e}_{\mathrm{act}}=\sum_{m\in\mathcal{M}^{e}_{\mathrm{act}}}\lambda^{e}_{m}\,\ell_{\mathrm{act}}\!\left(\hat{\bm{A}}^{e,m},\ \bm{A}^{e,m}\right) \]
\(\mathcal{L}^{e}_{\mathrm{act}}\) 是各动作模态的 smooth-L1 加权和（动作先标准化）；\(\lambda^{e}_{\mathrm{dream}}\) 是做梦项的权重；\(\mathcal{E}_{\mathrm{pre}}\) 是参与预训练的身体集合；\(e^{\star}\) 是目标身体。
大白话：每个身体算自己的账（动作 + 做梦），预训练时把所有身体的账加在一起，微调时只算目标身体那一本。
一个容易漏掉的关键约束：预训练时目标身体在目标任务上的演示必须排除在外。否则"预训练涨了多少"这个问题根本无法归因——你会分不清是跨身体迁移起了作用，还是模型早就见过这些演示。论文明确写了这条排除，这属于实验设计的基本功。
⑥ 表征层面的证据：用 GW 距离量"两种身体的表征几何像不像"
\[ \mathrm{GW}\!\left(\mu_{e_{1}},\mu_{e_{2}}\right)=\min_{\pi\in\Pi}\ \mathbb{E}_{\pi}\!\left[\,\big|\,d_{e_{1}}(i,i')-d_{e_{2}}(j,j')\,\big|^{2}\,\right] \]
\(\mu_{e_{1}},\mu_{e_{2}}\) 是两种身体在同一个任务（舀取）上、主干输出的 512 维表征分布；\(d_{e}(\cdot,\cdot)\) 是分布内部两个样本的距离（用中位数归一化）；\(\pi\) 是两个分布之间的耦合（软配对）。
大白话：它不比较"人类的第 1 个样本和机器人的第 1 个样本离多远"——那没有意义，两个空间的绝对坐标本来无关。它比的是关系表：在人类空间里 A 和 B 挨得很近，那在机器人空间里对应的一对是不是也挨得很近。比"形状是否相似"，不比"位置是否重合"。
为什么这个指标值钱：任务成功率受控制器、初始位形、试验次数影响，噪声大且不能直接说明"知识迁移了"。GW 是直接读表征的，它降了，才说明主干真的把两种身体编码成了同一种结构，而不是下游策略恰好凑出了好分数。

Worth价值与局限

核心价值：它把"跨具身"从"统一表示"改写成"统一接口"。
① 问题的切法变了：过去几年跨具身的主流思路是"把动作空间做大、把缺失维度补零"，本质是在赌"不同身体的动作可以对齐到同一个坐标系"。EgoX 直接放弃这个赌，改按功能角色切分。这个转向不依赖任何新模块，只依赖对"什么是不变量"的重新判断——这是最有复用价值的部分。
② OOD 增益（+0.24）远大于 ID 增益（+0.17 平均口径下的差）：这个不对称本身就是证据。如果只是"多学了点外观相似的东西"，ID 应该涨得更多；OOD 涨得多，说明迁移的是"怎么动"，不是"长什么样"。
③ 做梦是"免费监督"：不需要额外标注、不需要额外数据，只用已有的未来帧就能造出一条逼主干学动力学的损失，且部署时零开销。这条思路可以搬到任何"行为克隆学得太表面"的场景。
④ 补了表征层面的证据：GW 距离 21.30% / 38.52% 这两个数字，让"经验真的共享了"从主张变成了可测量的现象。而且它揭示了一件反直觉的事——做梦对几何靠拢的贡献（38.5%）比预训练本身（21.3%）还大。
⑤ 粗粒度消融有普适的工程含义：小模态（3 维速度指令）在大模态（48 维关节）旁边会被梯度淹没。凡是做多模态融合的人，都该拿这条对照检查自己的拼接方式。

批判性审视

  • "6 种身体"这个数字被高估了：其中 Z1-Tool 是固定不动的铲子（无驱动末端），G1-Sim 是仿真。真正形态差异大的其实只有 4 种（人形五指、桌面四指、轮式夹爪、四足前腿夹爪）。"跨六种身体"听起来很强，但多样性并没有数字那么宽。尤其 Z1 那对任务（舀猫砂）本质是"把一个刚体按轨迹移动"，难度远低于灵巧操作。
  • 加一个新身体仍要人工写映射：作者自己承认，扩展到新身体仍需手动指定模态对应关系和坐标变换、并集成专属控制接口。也就是说这套框架解决的是"训练时怎么共用"，没有解决"接入时怎么自动化"。而实际部署中，接一个新机器人的工程量往往比训练还大。"通用了"这个说法要打折扣。
  • 等量采样是个未解的矛盾：每个身体采同样大小的 mini-batch，保证公平但让小数据集被反复过采样（作者点名 LocoMan-Dex2）。这意味着"跨具身收益"里可能混进了"小数据集过拟合"的噪声，而论文没有给出按数据量调整采样比例的对照。
  • 真机每对只有 20 次试验（13 ID + 7 OOD）：7 次 OOD 试验的置信区间极宽——一次翻转就是 14 个百分点。OOD 从 0.53 涨到 0.77 这个结论，是靠"13 对全涨"的方向一致性撑起来的，不是靠单对数字。单看某一对的 OOD 提升没有意义，论文也没逐对给误差棒。
  • 13 对里 ID 有 2 对没提升，论文没解释：只在正文写了"11/13 提升"。没提升的那 2 对是哪两个、为什么？这恰恰是最有信息量的部分——如果是模态太少（像 Z1），说明框架对极简身体无益；如果是数据太少，说明有数据量门槛。缺了这个分析，"什么时候该用跨具身预训练"这个问题就没法回答。
  • 所有数据都是自己团队采的：作者把它列为局限（规模受限），但更值得注意的是数据分布的一致性——同一套采集协议、同一批场景、同一个团队的操作习惯。这种情况下人类视频和机器人视频的"语义对应"天然更干净。换成公开的、风格杂乱的野外人类视频，模态对应关系还能不能手工标得对，是未知的。
  • 基线只有 ACT 和 π0.5，且调参预算没交代：π0.5 是从预训练 checkpoint 微调的，但微调多少步、用什么学习率、在什么数据上都没细说。ACT 是很老的基线（2023），拿它做对照说服力有限。真正的对手应该是同样做跨具身预训练的方法（如 HPT、RDT 这类），论文里没有直接对比。
  • "做梦"学到的可能不是任务相关的动力学：预测未来潜表征没有指定"预测哪些方面"。它完全可能把容量花在手臂惯性、相机抖动、背景运动这些与任务无关的动力学上——这些也确实"帮助预测未来"。论文用 GW 距离证明了表征变像，但没有拆解"变像的那部分是不是任务相关的那部分"。这是这套方法最需要补的一块证据。
  • GW 距离只在一个任务上算：所有 GW 数字都来自"舀猫砂"的右腕 token。选它是因为右腕是唯一跨身体都活跃的末端，合理但局限——一个任务的表征几何靠拢，不能推出所有任务都靠拢。尤其双手协同任务（厨房清理）里，单看右腕可能完全看不到关键变化。
  • 推理延迟完全没报：模态级拆分意味着前向时要跑多个编码器（主相机 + 可能两路腕相机 + 若干本体流），主干还要处理拼接后更长的 token 序列。模块化在训练时是好事，在推理时是负担。真机控制频率是多少、能不能跑到 30 Hz 以上，论文一个字没提。
