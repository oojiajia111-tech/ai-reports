一句话 63% 的失败不是动作做错，是把工具调用预算耗光了
💡 第一性原理核心立论

业界默认"机器人 agent 的能力在权重里"，想变强就换更大的模型。这篇论文的实测把这个假设拆开了：能力其实分成两截——装在权重里的推理，和装在外围脚手架（工具接口、反馈、记忆、失败恢复）里的信息通路。同一个脚手架从 H₁ 演进到 H*，180B 教师涨 30.2pp，完全没训练过的 4B 也涨 26.6pp（14.6%→41.2%）——斜率几乎一样，说明脚手架的收益跟模型规模无关，它是"加在谁头上都加"的公共品。于是顺序可以反过来：先让大模型把脚手架进化到收敛，再把结果蒸馏进小模型。而消融给出了更锋利的一句：271 个"学生成功、未训练模型失败"的回合里，171 个（63%）是对手把工具调用预算用光了——小模型缺的不是动作精度，是"什么时候该换招、什么时候该认输"。

What是什么：把"改权重"换成"改外围"

先看清被挑战的对象。今天让机械臂干活的主流做法是端到端 VLA：图像 + 指令进，关节角或动作块出。它的隐含承诺是——只要模型足够大、数据足够多，中间的一切都会被隐式学会。

TinyAstral 换了一条完全不同的问题定义。它把系统劈成两半，并且规定只有一半允许变：

组件管什么本文里能不能动
Planner（规划器 π）做什么：哪个物体、物体的哪个部位、以什么参照、哪只手、什么顺序、何时结束❌ 权重全程冻结
Harness（脚手架 H）怎么做：工具接口、执行反馈、任务记忆、失败恢复；以及底层感知（SAM 3 分割→深度点云）、抓取/放置几何、无碰撞运动规划、闭环校正✅ 唯一变量

关键约束写得很死：模型从不输出关节角或坐标，除非工具显式要求。也就是说，那个 180B 的大家伙干的活儿，本质上只是"看图、想、选一个工具、读返回值、再想"——它是个会看会想的调度员，不是控制器。

在这个前提下，论文做了一件很朴素但很少人做的事：把"让机器人变强"这件事，从"换个更强的脑子"改写成"修那个脑子用的工具和反馈"。修的人是 frontier LLM agent 集群（论文叫 master M），修的依据是被冻结教师跑出来的失败轨迹。

一句话概括方法
冻结教师 → 让 LLM 集群读它的失败、改它的脚手架（改动必须过统计闸门）→ 脚手架定稿后不再改 → 用这个定稿系统采数据 → 蒸馏进 0.8B/2B/4B 学生 → 学生塞回同一个脚手架里干活。

Why为什么：五条公理，把"能力在权重里"逼到墙角

公理一：Agent 的失败有两种，一种是不会想，一种是不会看

这两件事被混在一起讨论太久了。一个"抓空了"的回合，可能是模型判断错了物体（不会想），也可能是工具返回的深度图本身糊了、或者抓取位姿的几何算错了（不会看）。前者要更大的模型，后者要更好的代码——而代码是免费的。

论文把失败强制归到 10 个类别（偏靶放置、假完成、缺原语、任务记忆错误、实例识别错误等）。分类这个动作本身就是一次归因：它逼着系统回答"这一条到底该怪谁"。

推论 1
如果大部分失败落在"不会看"这一类，那"换更大模型"就是在用最贵的方式解决最便宜的问题。而这类失败在数据里的占比，是可以被数出来的。

公理二：长在脚手架上的能力，跟权重无关，所以能跨模型迁移

这是全文最硬的一手，也是唯一一个能证伪"能力全在权重里"的实验设计：固定一批 episode，只换脚手架，看不同规划器的收益斜率是否一致。

PlannerH₁H₇H₁₆H*增益
Qwen3.8-Flash-Next（教师，180B）33.449.460.463.6+30.2
DeepSeek-V4.1-Flash（552B）32.845.057.663.4+30.6
Qwen3.5-4B，完全未训练14.628.633.841.2+26.6
TinyAstral-4B（蒸馏后）36.249.860.062.8+26.6

同一批 500 个 RoboTwin episode，前三行的权重一个都没动，唯一变的是 H₁→H*。三个规划器的斜率分别是 +30.2 / +30.6 / +26.6——几乎是平行的三条线。

这组数字里藏着一个更容易被忽略的事实：那个完全没训练过的 4B，光靠脚手架就从 14.6% 爬到了 41.2%（+26.6pp）。而蒸馏带给它的只有 21.6pp（41.2→62.8）。脚手架一个人贡献的，比蒸馏还多。

推论 2
脚手架的收益是可加的：它修的是"眼睛和手"，不是"脑子"。所以它既能叠在大模型上，也能叠在小模型上——这正是"先让大模型摸索、再把结果搬给小模型"这个顺序能成立的全部理由。

公理三：脚手架只能"长"出来，设计不出来——因为失败是长尾的

为什么不让工程师直接写一套好工具？因为你不知道会在哪里坏。整个 RSI 过程提了 296 个候选能力，跑了 7 个整合周期，最终阶段 7 个候选里只接受 3 个，版本线从 H₀ 经 H₁₆ 走到 H*。

这些候选改的东西很碎：加一个新工具或原语、把工具返回值改得"更诚实"（比如不说"抓到了"而说"接触力 3.2N、指间距离 4.1cm"）、修感知、加失败处理分支、局部修正任务记忆。它们都不是架构级的洞察，全是贴着具体失败长出来的补丁。

推论 3
这类补丁只能靠"跑—看—改"闭环获得，靠读论文想不出来。所以真正稀缺的不是想法，是"能自动判断这个补丁到底有没有用"的闸门。

公理四：没有闸门的自我进化会骗自己，而且骗法有三种

这是整篇论文工程上最重的部分，也是最值得抄的部分。自动改代码 + 自动评测，几乎必然滑向三种作弊：

作弊方式表现论文的堵法
背答案直接按任务名硬编码"这个任务就抓左边那个"代码不得按任务名分支；最终整合阶段 system prompt 与已有工具描述必须与父版逐字节相同；记忆只许改目标任务
拆东墙补西墙目标簇涨了 5pp，别的地方悄悄掉 4pp，平均看还挺好未触发的其余配对集合 U 上，只要回退 ≥2pp 且双侧 95% 上界 <0，直接否决
运气当能力跑了 20 个种子，恰好掷出好结果就收工预注册配对检验 + 任务聚类 bootstrap 下界 + 评估种子全程不进接受测试（编号 ≥100000，与训练/选择种子不相交）

还有两条很讲究的设计：

  • 触发器 + 逐字节等价审计。每个新组件必须靠一个显式触发器激活，并在日志里打专属标记；再由独立的代码审计验证"触发器不触发时，候选版本与父版本逐步行为完全一致"。这是把"我不小心改了别处"变成可机器验证的事实。
  • 中途就停。跑到一半时，如果 J 上净增益已不为正、或条件功效掉到 10% 以下，直接以"徒劳"终止——不烧完预算。配对数量是事先固定的，不许看了结果再加样本。
这套东西的本质，是把"科学方法"编译成了流水线：预先注册假设（哪个失败簇要被修）、固定样本量、配对比较、报告效应量的下界而不是点估计、拒绝看结果改设计。它防的不是模型笨，是研发过程本身的自欺——而这恰恰是所有"自动科研"里最难自动化的一环。
推论 4
脚手架进化的速度，上限不在"能提出多少改动"，而在"能多快地否掉无效改动"。296 提、121 采纳、最终 7 选 3 —— 分母极大、分子极小，这不是浪费，这是闸门在工作的证据。

公理五：蒸馏要搬的不是答案，是"想的过程"和"摔倒的过程"

脚手架定稿后，教师在里面跑，采出来的轨迹被筛了三道：

  • 只留严格成功：必须以 done 结束且 benchmark 的终态谓词成立；"曾经成功、后来又搞砸了"的回合被直接丢弃。失败种子最多重试 2 次（温度 0.7，提示不变），主回合一律温度 0。
  • 保住推理：每个样本同时监督 <think>…</think> 里的 rationale 和随后的那个工具调用。抹掉推理，LIBERO-PRO 掉 19.3pp。
  • 造"摔倒"样本：从成功回合重放前 k 次调用（用记录的结果，不查模型），在分叉点注入扰动——RoboTwin 上是"抓取滑脱"或"目标物体在下一次抓取前移动 6–10cm"。只有扰动确实生效、重放复现了每一个 result code、且教师仍然成功，这条分支才保留。RoboTwin 上下采样到主回合样本的 20%（3,471 条分支 / 13,857 条主回合）。

为什么要专门造失败？因为真实部署时 90% 的时间都花在"出事了怎么办"上，而成功轨迹里几乎没有这类决策。从头到尾都是"抓到了、放好了"的数据，教不出"抓空了该退回去重抓还是换一只手"。

推论 5
"只留成功"和"造失败分支"看起来矛盾，其实是一件事：只用成功的结果定标，但要用失败的过程定策。前者保证标签干净，后者保证策略完整。

How怎么做：两阶段，中间夹一道统计闸门

Stage 1：让脚手架自己长（权重不动）

系统里只有三个角色：冻结教师 πT、脚手架 H、master M（一组 frontier LLM agent，负责读轨迹、提案、写代码、互相审计）。人类在开跑前只做两件事：定规则、定预算。之后每一轮是固定的三步：

① 读轨迹
当前 Hk 在 development seeds 上跑，master 检查记录的图像、工具调用、工具返回、教师推理，把每个失败归进 10 类之一。
② 提改动
针对失败簇写候选组件：新工具/原语、更诚实的工具返回、感知修复、失败处理、任务记忆的局部修正。改动必须通用（不许按任务名分支）。
③ 测并裁决
候选 H′ 与当前 H 在同一批 (task, seed) 对上配对比较，由预注册的统计闸门自动接受/否决/提前终止。这就是下面的式 2。

跑完的账：296 个候选能力、7 个整合周期、最终 7 选 3，版本线 H₀ → H₁₆ → H*。测了其中四个快照（H₁、H₇、H₁₆、H*）。

Stage 2：把定稿系统蒸馏成小模型

H* 冻结后不再改，教师在里面采数据。最终训练集 83,753 个决策样本，其中一半来自仿真（41,877 条仿真样本：RoboTwin 13,857 / Guava 9,054 / LIBERO 11,159 主回合，加 3,471 / 2,048 / 2,288 条恢复分支），其余来自公开真实数据集（AgiBot World、Open X-Embodiment 里的 Fractal / BridgeData V2 / DROID / Berkeley UR5），做成三个辅助任务：状态与失败判断 27,918 条、子目标规划 4,187 条、下一工具调用 9,771 条。

训练配置值
底座Qwen3.5-4B（同配方训出 0.8B / 2B / 4B 三个尺寸）
可训参数全部语言模型参数；视觉编码器与 projector 冻结
损失位置只加在最后一条 assistant 回复上（即 think + 那次工具调用）
超参2 epoch，lr 1e-5 + cosine 衰减 + 5% warmup，全局 batch 32，最长 12,288 tokens
部署塞回同一个冻结脚手架，单卡 bf16，不量化、不投机解码

Math三个公式：评分口径、进化闸门、蒸馏目标

式 1｜严格成功（Strict Success）：为什么这个指标不能糊弄
\[ S(\tau)=\mathbb{1}\!\left[\,e_\tau=\texttt{done}\ \wedge\ \varphi_{\text{bench}}(s_T)=1\,\right],\qquad \text{ever}(\tau)=\mathbb{1}\!\left[\exists\,t\le T:\ \varphi_{\text{bench}}(s_t)=1\,\right] \]
大白话：\(\tau\) 是一个回合，\(e_\tau\) 是它的结束方式，\(s_T\) 是最后一帧的物理状态，\(\varphi_{\text{bench}}\) 是 benchmark 自带的成功谓词（比如"物体 b 在物体 a 上"）。
这个式子的全部重点在那个 \(\wedge\)：光"最后东西放对了"不算，必须是模型自己喊停的。机器人常见的一种假成功是——它没做完，但工具调用预算耗尽、环境被迫终止，凑巧东西歪在正确位置。
另一条更狠的规则：模型调 done 时要自己说出它认为成立的谓词（如 on(a,b)、upright(a)、lifted(a,cm)），脚手架用相机和夹爪传感器去验；验不过就驳回并把实测值返回给它（"你说 lifted 10cm，实际 4.2cm"）。连驳两次之后，下一次 done 不再检查、直接结束——这个细节很关键，它既逼模型学会"报得准"，又不给它无限重试的漏洞。
还有一条常被忽略的隔离：环境自己的成功标志，从来不进入模型输入。模型永远看不到"我这一把成了没有"，只能靠传感器读数自己判断。这才让"自主终止"成为一个真问题。
对照指标 ever success = 任一时刻达成即算，两者之差就是"做对了但没收好"的比例，也就是模型对自身状态的判断误差。
式 2｜进化闸门：一个改动凭什么被接受
\[ \Delta_{J}=\frac{1}{|J|}\sum_{(i,s)\in J}\Big[\,S_{H'}(i,s)-S_{H}(i,s)\,\Big],\qquad J=\mathcal{C}_{\text{target}}\ \cup\ \{\,p\in U:\ \text{marker}_{H'}(p)=1\,\} \] \[ \boxed{\ \text{Accept}(H')\iff \mathrm{LCB}^{\,97.5\%}_{\text{cluster-boot}}\!\left(\Delta_{J}\right)>0\ \ \wedge\ \ \Delta n_{\mathcal{C}_{\text{target}}}>0\ } \] \[ \text{Veto}(H')\iff \Delta_{U}\le-2\,\text{pp}\ \ \wedge\ \ \mathrm{UCB}^{\,95\%}\!\left(\Delta_{U}\right)<0 \qquad\quad \text{Stop}_{\text{futility}}\iff \Delta_{J}\le 0\ \vee\ \pi_{\text{cond}}<0.10 \]
大白话（先看 \(J\) 是什么）：\(J\) 是"这次改动声称要管的那批配对"= 目标失败簇 \(\mathcal{C}_{\text{target}}\)，再加上所有"虽然不在目标簇、但候选的触发器真的被点火了"的配对。后半截是关键——它防止一种自欺：你说你只改 A，但你的改动其实在 B 上也生效了，那 B 的表现也得算进你的账里。剩下的没被点火的就是 \(U\)。
接受要同时满足两条：
① \(\mathrm{LCB}^{97.5\%}(\Delta_J)>0\)：对 \(J\) 上的配对增益做按任务聚类的 bootstrap，取单侧 97.5% 下界，要求它为正。注意是下界，不是均值——均值涨 3pp 但下界是 −1pp 的改动，一律不算数。用聚类是因为同一个任务内的 episode 高度相关，把它们当独立样本会把置信区间算窄、显著性吹高。
② \(\Delta n_{\mathcal{C}_{\text{target}}}>0\)：目标簇上的"净胜数"（赢的配对减输的配对）必须为正。这条是防"大赢几个、小输一片"：均值被几个大改善拉起来，但其实是拿一堆小回退换的，净胜数会告诉你真相。
否决是另一套口径：在没被点火的 \(U\) 上，只要回退达到 2pp 且双侧 95% 上界都落在 0 以下，就直接毙掉。这里用的是上界——"确实变差了"和"可能变差了"被区别对待，宁可保守。
中途停止（futility）：跑到一半，如果 \(J\) 上净增益已不为正，或条件功效 \(\pi_{\text{cond}}\) 掉到 10% 以下，就认定"再跑也救不回来"，提前掐掉。配对数量事先固定、不许看结果加样本，这是防 p-hacking 的最后一道锁。
为什么这套东西值得单独拎出来：自动改代码的系统最怕的不是改错，是改错了还自以为改对了。这个闸门把"我觉得有用"翻译成了"下界为正、净胜为正、别处没坏"三句可以机器判定的话。
式 3｜蒸馏目标：只学最后一步，但要学两种最后一步
\[ \mathcal{L}(\theta)=-\!\!\sum_{i\in\mathcal{D}_{\text{main}}}\!\!\log\pi_\theta\!\left(y_i^{(T_i)}\mid x_i\right) \;-\;\lambda\!\!\sum_{j\in\mathcal{D}_{\text{rec}}}\!\!\log\pi_\theta\!\left(y_j^{(T_j)}\mid x_j\right), \qquad \lambda\ \text{由 20\% 下采样实现} \]
大白话：这就是标准的逐 token 交叉熵，但有三个不标准的地方，每一个都值钱。
① 只算最后一个 assistant turn。\(y^{(T)}\) 是那条回复的最后一个 token 位置，不是整条轨迹。前面那些工具返回、图像描述、环境文本都是输入 \(x\)，不产生损失。理由很实在：那些内容不是模型该学会"生成"的，是它该学会"读"的。把损失压在整个上下文上，等于让模型去模仿传感器的输出格式，纯属浪费容量。
② 那条回复里同时含 <think> 和 tool call。所以这一项交叉熵实际上在同时教两件事：怎么想（rationale 的每个 token）和怎么动（那个调用）。这就是为什么抹掉推理会掉 19.3pp——不是格式丢了，是把"想"这一半的监督信号整个删掉了。
③ 两个数据集分开加权。\(\mathcal{D}_{\text{main}}\) 是正常回合，\(\mathcal{D}_{\text{rec}}\) 是从成功回合分叉、注入扰动后教师仍然成功的恢复分支。\(\lambda\) 靠把分支下采样到 20% 实现（RoboTwin：3,471 分支 vs 13,857 主回合）。为什么不能等权？因为恢复分支只覆盖"出事之后"这一小段决策，等权会让模型以为整个世界都在出事。20% 是个经验配比，论文没做这个比例的扫描——这是一个可以继续挖的口子。

Worth价值与局限：数字很硬，但口径要看清楚

第二行最刺眼：去掉真实机器人数据，仿真成功率几乎没变（甚至涨了），但真机上的下一调用准确率从 0.923 崩到 0.235。这是一个非常干净的"指标隔离"证据——真实数据的价值不在提分，在于让离线决策对得上真实的观测分布。仿真指标根本测不出这件事。

第一行也值得细看：推理主要在"多步规划"的地方起作用。LIBERO-PRO −19.3pp 最惨，RoboTwin 只 −0.4pp。差异的原因是脚手架——RoboTwin 上物体级原语很强（抓、放、验证、恢复都现成），模型"看一眼就知道该调哪个"；LIBERO-PRO 更依赖把几步串起来，一旦没有 think，链条就断。

还有一条藏得比较深但可能是全文最有用的观察：300 个 LIBERO-PRO 回合里，没有推理时 49 个把 40 次工具调用预算耗尽了，完整配方只有 7 个。再看零样本：271 个"学生成功、未训练 4B 失败"的回合中，171 个（63%）是对手把调用预算用光的。
——小模型的差距，主要不是"动作做不对"，是"不知道该停、该换招、该认输"。它在那儿反复调同一个工具、反复抓同一个位置，把预算烧完。而 think 的训练，本质上教的是"预算管理"。
这条对工程上的启示比"参数少 45 倍"更直接：如果你的 agent 老是在超时，先别急着换模型，先看看它是不是不会收手。

它的真正价值

1. 它给了"能力在哪个容器里"一个可测的答案。固定 episode、只换脚手架、看不同规划器的斜率——这个实验设计比任何论证都硬。结论是脚手架的收益可加、可迁移、与规模基本无关，于是研发顺序可以彻底改：先用大模型把"世界接口"摸清楚，再把接口交给小模型，而不是让小模型自己去摸。

2. 那套统计闸门是可复用的资产。"预注册 + 配对 + 聚类 bootstrap 下界 + 未触发集合的回退否决 + 固定样本量 + 中途停止"——这套东西不只适用于改脚手架，任何"自动优化 + 自动评测"的闭环都该有。它解决的是自动科研里最难自动化的一环：判定自己有没有自欺。

3. 触发器 + 逐字节等价审计，是个很聪明的工程发明。它把"这次改动只影响它该影响的地方"从一句承诺，变成了可以机器验证的性质。代价是牺牲了"非局部改进"的可能性（见下），但换来的是可控。

4. 成本账是真的。单卡 bf16 vs 教师 4 卡 FP8 TP4：25.3 vs 123.8 Accel·s/episode，约 4.9×；vs DeepSeek-V4.1-Flash 8 卡 249.6，约 9.9×。而且同样 20 个 episode 上学生成功 14/20，教师 12/20——学生没输。

要打问号的地方

  1. "五分之一加速器时间"和"墙钟时间"是两个口径，差得不少。4.9× 是按 Accel·s 算的（4 卡 × 55.0s = 123.8 对 1 卡 × 25.3s）。按中位墙钟算是 55.0 → 25.3，只有 2.2×。摘要写"约五分之一"没错，但读者很容易读成"机器人反应快了 5 倍"。真正的含义是"同样的活少占 4 张卡"，是成本叙事，不是延迟叙事。25.3 秒一个回合，对一个 30 次工具调用的闭环来说依然是慢的。
  2. "脚手架收益与规模解耦"在 0.8B 上明显衰减，但摘要只报 4B。看表：教师 +30.2、4B +26.6，差 3.6pp 还算能接受；但 0.8B 在 LIBERO-PRO 只有 54.7（教师 80.0），掉 25.3pp，而 4B 只掉 1.7pp。这说明"脚手架是公共品"这句话有尺寸下限——模型太小，连"读懂工具返回值"这件事都做不到，脚手架给得再好也用不上。论文把 0.8B/2B/4B 三个尺寸都训了，但主结论是从 4B 那行下的。
  3. RoboTwin 用了 task memory，其他五个 benchmark 都没用——而 RoboTwin 恰好是最好的那个数字。说明里强调记忆只有一句"任务终态说明"、不含动作轨迹、评估时冻结只读。但它是50 条按任务写的、人类/agent 维护的先验。这跟"代码不得按任务名分支"这条规矩在精神上是紧张的：H* 在 RoboTwin 上的能力，有多少来自脚手架、多少来自那 50 条笔记，论文没有做"去掉 task memory"的消融（Tab.3 只消了推理和真实数据）。
  4. "触发器不触发就逐步等价"只保证了不改别处，没保证触发器本身合理。每个新组件必须靠显式触发器点火、并打日志标记，审计再验"没点火时行为一致"。但触发条件是 master 自己写的——写一个"只要画面里有杯子就触发"的宽触发器，效果上等于全局改动，而审计查的是等价性、不是触发器的宽窄。这是一个能被绕过的口子，论文没有讨论触发器粒度的约束。
  5. 跨域迁移没测，只有跨模型迁移。"脚手架可迁移"的证据是：同一个 H* 换了三个规划器（教师、DeepSeek、未训练 4B）都涨。这是跨模型。但三个零样本 benchmark（SimplerEnv ×2、VLABench、EB-Manipulation）用的是同一个脚手架——所以它测的是"这套原语在新场景里够不够用"，不是"这套原语能不能搬到新域"。而 H* 是在 50 个 RoboTwin 任务的失败分布上长出来的，它的形状带着那个分布的指纹。换到柔性物体、人形全身、力控装配，这套"物体级抓放原语"可能是整层失效而不是部分失效。
  6. 真实机器人闭环是全文最薄的一块。论文在 SO-ARM101 上报了三个闭环任务，但正文主要拿离线下一调用准确率（0.923 vs 0.235）来证明真实数据的价值。"离线决策对 ≠ 闭环能做"这个 gap，恰恰是具身智能里最贵的那一段。而恢复分支的扰动量（滑脱、移动 6–10cm）也是仿真里的手设参数，真实世界的失败模式要脏得多。
  7. 20% 这个分支配比没有任何依据。恢复分支下采样到 20% 是个超参，论文只说"subsampled to 20%"，没扫、没解释。而这个比例直接决定学生有多重视"出事之后怎么办"——考虑到上面那条"63% 的失败是预算耗尽"，这个比例可能比学习率重要得多，却没被当成研究对象。
  8. 那 121 个被采纳的候选，最后的账对不上。296 提、121 采纳、7 个整合周期里最终 7 选 3——116 个被采纳的改动去哪了？原文提到有些被接受的改动落在"从未并入主线的侧枝"上。这意味着一大半"被证明有效"的改动，其实没进 H*。这个信息很重要（说明闸门单独看有效、合起来不一定），但被放在很不起眼的位置。

一句话收尾

这篇论文最锋利的地方不是"4B 打赢 180B"，而是它把"能力"这个东西按容器拆开了：一部分在权重里，能靠蒸馏搬；另一部分在脚手架里，本来就搬得动。而它顺手给出的那个 63%，比任何成功率都更值得记住——小模型不是不会做，是不知道该停。如果这条成立，那么今天大部分"机器人 agent 不够聪明"的问题，可能有一半其实是接口设计问题，而不是模型容量问题。
