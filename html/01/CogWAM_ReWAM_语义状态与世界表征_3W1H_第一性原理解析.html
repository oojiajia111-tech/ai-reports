💡 第一性原理核心立论

两篇工作表面上一个管"理解"、一个管"表征"，其实问的是同一个问题的两半：世界动作模型该把什么装进内部状态，以及用什么标准来装。

CogWAM 问的是"该记什么，什么时候该改"。长时序操作里，"任务完成了多少"这个量并不是连续变化的——它在做一步的过程中基本恒定，只在跨阶段时跳变。如果每帧都重新估计它，得到的是一堆围绕真值的噪声抖动，而不是更准的估计。所以它用事件驱动的 KEEP/UPDATE 机制：默认保持不变，只在关键转换时刻更新。这不是省算力的小技巧，而是对"任务进度是分段恒定"这一物理事实的正确建模。

ReWAM 问的是"该按什么标准装"，而且它一开口就掀了桌子："世界模型重建得越好，机器人就一定越强吗？"答案是未必。因为视觉重建优化的目标是像素保真——包括背景纹理、光照、无关物体；而控制需要的是动作相关的可区分性。这两者可以冲突：一个能把木纹重建得纤毫毕现的表征，可能对"手指是否已经夹住"这种十几个像素的位移完全不敏感。所以 ReWAM 干脆不用为重建设计的 Video-VAE 潜空间，改用预训练 DINO 感知特征，并让动作目标反向塑造表征。

合起来是一条判断：世界动作模型的内部表征，服务对象是决策，不是还原。这句话听起来像常识，但现有做法（直接用 Video-VAE 潜空间、每帧重估语义状态）恰恰都在按"还原世界"的标准设计。

两个共同的背景判断值得记下来：

  • WAM 的定位：联合学习"未来世界状态预测"与"机器人动作生成"，目标是让机器人不只会执行，还能理解物理世界如何变化。
  • 两篇的分工：CogWAM 处理"语义认知"这一层（理解当前该做什么），ReWAM 处理"物理表征"这一层（在什么空间里学动态）。文章末尾的收束很准确——"如何让机器人既理解当前应该做什么，又能在有利于控制的表征空间中学习世界动态？"

Why为什么两个流行前提都站不住

前提一：任务进度应该被持续、密集地估计

这个前提的诱惑在于"信息越多越准"，但它忽略了一个结构性事实：

任务进度是分段常值函数，不是连续信号
\[ \text{progress}(t) = s_k \quad \text{当 } t \in [\tau_k, \tau_{k+1}) \]
在第 \(k\) 步执行期间，进度保持不变；只有跨过 \(\tau_{k+1}\) 才跳变。对这样一个信号做高频估计，得到的是围绕常数 \(s_k\) 的估计噪声——不是更多信息，是更多抖动。而这些抖动会同时污染世界预测和动作生成两条通路。

所以"KEEP/UPDATE"的正确读法不是"省计算"，而是把更新时机对齐到信号的真实变化点。这与信号处理里的采样定理是同一件事：对带宽有限的信号，超过必要频率的采样只会引入噪声。

原文给出的动机也是这个方向："通过高效的 KEEP/UPDATE 机制避免冗余的语义状态更新"，"保留执行历史，并在关键任务转换时高效更新"。

前提二：视觉重建质量高 = 控制能力强

这是 ReWAM 那记直拳要打的东西。把两者的优化目标写出来，冲突就一目了然：

两个目标函数优化的根本不是同一个量
\[ \mathcal{L}_{\text{重建}} = \big\| x - \hat{x} \big\|^2 \quad\text{（逐像素保真，背景也算分）} \]
\[ \mathcal{L}_{\text{控制}} = \text{任务成功 / 动作可分性} \quad\text{（只关心与动作耦合的那部分变化）} \]
一个表征可以在这两者之间严重错配：房间的窗帘摆动、桌面反光、背景里走过的人，都会主导重建损失；而"指尖与物体之间多了 3 毫米的挤压"在像素空间里贡献极小，在控制上却是决定性的。重建越强，越可能把容量花在与动作无关的细节上。

于是"直接用 Video-VAE 潜空间"就成了一个未经验证的默认

原文的描述很准确：现有 WAM "通常直接使用为视觉重建设计的 Video-VAE 潜在空间进行世界预测与动作学习"。这是一个继承式的选择——因为视频生成模型好用，就顺手拿它的潜空间，而不是因为该潜空间对控制友好。

ReWAM 的做法是换掉这个默认：以 DINO 感知特征为基础。理由可以推一下——DINO 这类自监督特征是在判别性目标下学出来的（区分不同图像/区域），而不是在重建目标下学出来的（还原每个像素）。前者天然更接近"可区分"，后者天然更接近"可还原"。而控制需要的是可区分。

How怎么改：三个模块各治一种病

CogWAM：把语义状态做成"稀疏事件"

事件驱动的语义接口
持续维护一个 Semantic State，把它同时接入世界预测和动作生成两条通路。关键在于"同时"——如果只喂给动作生成，世界模型就不知道任务进展，预测出的未来可能与任务无关（比如预测出"手继续悬停"而不是"手该去拿下一个物体"）。
KEEP / UPDATE
两种动作：保持不变，或在关键转换点更新。这个二值决策本身就是"事件检测"——判断当前是否发生了任务阶段切换。比"每帧重新回归一个进度标量"更省，也更稳。
要验证的三件事
原文列出的实验方向：长时序操作、指令遵循、跨场景泛化。这三项恰好对应"记得住阶段""听得懂指令""换场景还能认出阶段"——都在检验同一个东西：语义状态是不是真的在追踪任务进度，而不是在拟合视觉外观。

ReWAM：把表征从"可还原"扭向"可控制"

模块作用（据原文摘要）它对应解决什么
Feature Calibration校准预训练 DINO 特征通用视觉特征不是为机器人任务学的，需要对齐到目标任务分布
Temporal Representation Bottleneck（TRB）时序表征压缩逐帧感知特征不直接等于动态表征；压缩掉与动态无关的变化，留下随时间演化的部分
AGRSAction-Grounded Representation Shaping，非对称梯度优化让动作目标塑造表征、同时让世界模型学动态——两个目标不是平等合作的

"非对称梯度"这个词值得单独说

AGRS 用"非对称梯度"是全文技术味最重的一处，也是最容易被忽略的设计。它意味着动作损失对表征的梯度与预测损失对表征的梯度，权重或路径不同。

为什么需要非对称？因为两者的可靠程度不一样：动作是有监督标签的（示范数据里真实存在），而未来的视觉预测在接触场景里极难准确（物体形变、遮挡、接触力都拍不到）。如果让两者平等地塑造表征，不可靠的预测目标会稀释可靠的动作信号。

原文的表述是："让动作目标决定表征应该编码什么，让世界模型学习这些表征如何随时间演化。"——注意这两句的主语不同：表征由动作决定，动态由世界模型学。这是一个明确的主从关系，不是对等融合。

Worth价值与局限：问题提得比答案更值钱

两篇各自最值钱的一句话

CogWAM：任务进度是分段恒定的，所以它应该被事件驱动地更新，而不是被高频估计。

ReWAM："世界模型重建得越好，机器人就一定越强吗？"——这个反问拆掉了一个被默认继承的设计选择。

两个判断的共同点，是把"更多"换成了"更对"：更多语义更新 → 更对的更新时机；更强的重建 → 更对的表征目标。

为什么这两个问题在 2026 年被同时提出

因为它们都是WAM 范式成熟到一定程度后才会暴露的问题。早期做 WAM，能用就行；等到要跑长时序、要跨场景泛化，才会发现：

  • 语义状态每帧抖，长任务就会"忘记自己在第几步"；
  • 表征按重建优化，控制精度就在关键接触处丢。

换句话说，这两篇是"WAM 从能跑到跑得久"阶段的必修课，而不是从 0 到 1 的创新。

必须打问号的地方

  1. 本文无可验证数据。原文是活动预告，只有摘要级描述，没有成功率、没有消融、没有基线对比。任何"效果更好"的期待都超出原文信息范围。
  2. "重建好 ≠ 控制好"这个论点，需要对照实验才能成立。逻辑上它完全说得通，但要证明"Video-VAE 潜空间确实拖累了控制"，需要同架构、同数据、只换潜空间的对照。这个实验是否做了、结果如何，原文没有交代。
  3. DINO 特征是否真的"更适合控制"，是假设不是结论。判别性特征更接近"可区分"，但它缺的可能是细粒度几何——DINO 擅长区分"杯子 vs 瓶子"，未必擅长区分"夹住 1 毫米 vs 3 毫米"。而这恰恰是接触任务最需要的。Feature Calibration 和 TRB 能不能补上这块，是关键未知。
  4. KEEP/UPDATE 的二值决策本身可能成为新故障点。如果事件检测漏判（该更新时没更新），语义状态就会长时间停在错误阶段，而且没有任何机制会自动纠正——因为"保持不变"是默认行为。这比"每帧估计但有小噪声"更危险：后者误差有界，前者可能持续跑偏。原文未提及如何检测这种漏判。
  5. "长时序"的尺度没有界定。多少步、多长时间算长时序？如果验证任务是几十步量级，那么"每帧更新"和"事件更新"的差别可能还体现不出来。这个量级决定了结论的适用范围。
读这篇最该带走的一句：世界动作模型里，内部状态的更新频率和表征的优化目标，是两个经常被顺手默认、却直接决定上限的设计选择。默认做法是"每帧更新 + 按重建优化"，而这两篇分别指出：前者在对一个分段常值信号做过度采样，后者在对一个不需要还原的世界做过度还原。把"更密"换成"更准"，是这两个方向共同的方法论。
