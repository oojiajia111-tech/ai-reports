一句话 机器人缺的从来不是数据量，是「这段经验里到底有多少动作能被当标签用」
💡 第一性原理核心立论

机器人要学的经验必须带动作标签，而带动作标签的数据只有真机采得出来——这是具身智能最贵的一道墙。所以真问题不是「模型做多大」，而是「一段人类经验怎样才算变成可训练的动作信号」。WALL-OSS-1.0 的解法是把数据按信息含量分层：动作可靠的就直接学动作，只有画面没有动作的就改成学「接下来画面会变成什么」，不硬造标签。这一刀切下去，成本结构就散了——贵的那部分只买必要的量，便宜的那部分可以大量往上堆。第二个立论更朴素：预训练的价值不在榜单分数，而在把一个新场景从一千小时现场数据压到十小时。它没有解决具身智能，它解决的是「怎样让每一小时真机数据更值钱」。

What是什么：它不是「一个模型」，而是一套「数据口径 + 模型家族 + 部署栈」

这篇是自变量机器人（X Square Robot）关于 WALL-OSS-1.0 的技术博客。它最容易被误读的地方在于：读者会以为这是一篇「我们又训了个更大的 VLA」。事实上全文的篇幅分配很说明问题——将近一半在讲数据怎么筛、怎么标、怎么混，只有三分之一在讲网络结构。这个配比本身就是结论。

把它的部件拆开，是三层：

  • 数据层：UMI 式手持夹爪采集（人拿着设备干活，机器人不用到场）+ 真机遥操作 + 策略执行中被人工接管纠错的片段 + 开源数据。四类数据不混着用，各自按「动作信息可不可靠」走不同训练目标。
  • 模型层：第一阶段做「语言 + 视觉语言 + 离散动作」的统一自回归训练（它叫 Native VLA），把动作 Token 化后塞进同一个序列；第二阶段在共享主干上加一个 Flow Matching 的 Action Expert 输出连续动作；另有一条 1.0-AR 路线全程走自回归解码。
  • 部署层：Lite（可反复微调）/ Nano（算力受限）两个小版本，配 XInfer 推理服务；上层再套一个 XR Harness 做长时程任务的规划—执行—反馈闭环。

一句话定位：它在回答的问题不是「VLA 怎么更强」，而是「一条人类经验，凭什么能变成机器人的训练信号」。全文所有设计——10:1 混采、20 项体检、四层标注、Ego 视频改走生成式监督、状态与控制命令解耦——都是这一个问题的不同侧面。理解这一点，后面那些看似零散的工程细节才会连成一条线。

Why为什么：五步公理链，从「数据很贵」推到「所以必须分层」

先别看它做了什么，先把约束条件摆出来。具身智能的成本结构是被三条硬约束决定的，任何方案都绕不开：

公理 1：动作标签只能从「真的动过」里来
模型要学的是「看到这个画面，我的手该怎么动」。这个「怎么动」的答案，只存在于真正执行过的记录里。视频里能看见手在动，但看不见电机收到了什么指令。所以有动作的数据 = 真机 + UMI，没动作的数据 = 海量人类视频。前者精确但每一小时都要人和设备，后者免费但缺最关键的标签。
公理 2：监督信号的精度必须匹配数据的可信度，否则就是在教模型学噪声
UMI 数据是「人手拿夹爪」采的，位姿靠视觉估计。一段看起来流畅的演示，位姿一旦跳变，记录下来的动作就跟真实运动对不上；轨迹超出目标机械臂可达范围，机器人根本复现不了。所以「无机器人采集」省下的成本，必然以「清洗成本」的形式还回来——这就是那 20 多项检查存在的原因，不是工程洁癖。而且噪声要分两类：场景和动作方式的自然变化是有益的（帮泛化），位姿跳变、错误动作、时间错位是有害的（教坏观测—动作映射）。一刀切地清洗会把前者也洗掉。
公理 3：动作要进大模型，就必须变成 token；一变成 token 就必然丢精度
语言模型能吃下整个互联网，是因为分词几乎不损失语义。机器人动作是连续数值，高频控制下一小段就包含几十个时间点 × 十几个维度。逐点逐维转 token，序列会长到没法自回归。所以必须压缩。但压缩率、重建精度、以及对多模态学习的友好度，三者互相拉扯——压得狠，精细动作没了；压得松，序列太长、机器人等不起。这是一个没有免费午餐的三角。
公理 4：语义和动作必须共享一套表征，否则「理解」和「执行」永远是两套系统
「把颜色相同的物体放在一起」这句话，模型得先认出物体、理解颜色关系、排出顺序，再控制机械臂和夹爪。如果视觉语言是一个模型、动作是另一个模型，中间那道接口就是所有误差的汇聚点。所以要把动作塞进预训练，让动作数据和图文数据一起去塑造同一套表征——这才是「Native VLA」和「VLM 后面接个策略头」的本质区别。
公理 5：具身模型的价值单位不是分数，是「达到可用水平所需的现场数据小时数」
买方不关心你在自建榜单上多少分，他关心「我这个车间要跑起来，还得再采多久数据、再花多少钱」。所以一切设计最终都要折成这个数。原文那句「10 小时 vs 1000 小时」之所以是全文最重的一句，就是因为它把技术叙事翻译成了采购语言。同理，「跨站点保留 90% 以上」也是同一把尺子在量迁移性。

推论：把这五条串起来，方案几乎是唯一的——数据必须按信息含量分层使用（对应公理 1、2），动作表示必须分层压缩（公理 3），动作与图文必须共享主干（公理 4），而所有设计都要能被「适配小时数」检验（公理 5）。WALL-OSS-1.0 的每一个具体选择，都能对应回上面某一条。反过来看，哪些方案会失败也就清楚了：只堆真机数据的（成本线性爆炸）、把人类视频硬转成机器人动作的（公理 2 的噪声问题无法回避）、把动作当外挂模块的（公理 4 那条接口永远是瓶颈）。

How怎么做：数据先分层，模型再分层，部署最后分层

一、数据侧：不是「多采」，是「按可信度分流」

四类数据各走各的路，这是全文最值得抄的工程决策：

数据类型有什么缺什么怎么用
真机遥操作图像 + 机器人状态 + 控制命令贵、场景受限直接动作监督；同时提供「状态↔命令」对应关系
UMI 手持夹爪夹爪位姿轨迹 + 开合 + 视频没有真实执行器的控制命令只学「运动状态」，不学「命令」；先过 20 多项体检
人工接管纠错失败前后的状态 + 人的修正动作只在策略卡住时才产生补「模型自己踩到的坑」，还从错误前同一状态额外采错误执行做对照
人类 Ego 视频丰富场景与行为没有可靠动作标签不走动作监督，改走生成式监督（预测未来画面）

其中两个细节特别值得停下来看：

  • UMI 和真机能混，靠的是「运动状态 / 控制命令」的解耦。UMI 记录的是夹爪走到哪、怎么走（运动状态），真机记录的是电机收到什么（控制命令）。同一段轨迹，改变「哪些量作为条件、哪些量作为预测目标」，就能拼出四种任务：只预测运动状态、状态与命令联合预测、给历史状态和命令预测未来状态（正向动力学）、给运动状态反推命令（逆向动力学）。一个 Action Expert，四套监督，同一份参数——这是把异构数据塞进一个模型的真正接口。
  • 人手持夹爪 ≠ 机械臂能到。人能靠身体和手腕调整姿态，机械臂有工作空间、关节限位、碰撞约束。所以 UMI 轨迹必须先验证逆运动学可行、运动平滑、无高频抖动、位姿连续、视觉质量与 6-DoF 精度达标。这一步不是可选项，它是「不用机器人采数据」这张支票的兑付条件。

标注也一样在解决「时间尺度对不上」的问题。一句「把纸装进信封」是目标，模型却要学会折纸、开信封、插入三个动作；只给目标，模型得自己猜语言和局部动作的对应；只给短动作，又丢了整体意图。所以做成 Task / Subtask / Action / Segment 四层：任务级给目标，动作级和片段级给每一步的落点。同一条轨迹因此既能教「要干什么」，也能教「这一步怎么动」。

二、模型侧：动作先当 token 学，再当连续量生成

训练分两个阶段，这个划分是整篇的骨架：

第一阶段：把动作变成一种「可以预测的符号」
用改进版 X-Tokenizer 把连续轨迹压成分层的离散码，然后和语言、图文数据一起做统一的自回归训练。关键设计有三个：①分层残差——第一层学粗粒度动作结构，后面几层只补重建细节，避免「一层量化把细节一次抹平」；②动作特征与同一时刻的视觉语言特征对齐，并预测下一时刻的视觉语言特征——这是逼动作 token 携带语义，而不只是数值；③联合训练时 Tokenizer 冻结——不让它在多任务里漂移，否则码本和主干的语义会互相拖。
第二阶段：在共享主干上加一个连续动作专家
主干继续吃图像和指令，Action Expert 通过共享注意力拿到这份上下文，用 Flow Matching 从噪声一步步生成一段连续轨迹（Action Chunk）。架构上叫 MoT（Mixture of Transformers）：理解归理解，生成归生成，但注意力是通的。同时保留第一阶段的自回归路径（1.0-AR：时间压缩 + 分层残差 + 因果解码器），两条路并行探索。

还有一个很巧的训练技巧：一份视觉语言上下文，服务多个轨迹训练块。先编码一次图像和指令，然后让多个轨迹块共享这份编码，每块独立采样不同的预测任务、历史长度、预测范围、动作前缀、以及流匹配所需的噪声与时间条件；块与块之间用注意力掩码互相隔离。大白话：一次读题，同时做几道不同的练习题。这直接解决了「异构数据怎么在一个 batch 里共存」——UMI 状态预测、真机状态+命令、不同长度的轨迹，都能塞进同一套框架。

三、部署侧：动作生成必须和「机器人还在动」这件事对齐

这是最容易被论文忽略、却决定能不能上线的一段。Action Chunking 一次生成未来一段动作，片长要权衡：太短要频繁推理，太长就按旧观测行动。真正的麻烦在片段交接处——模型生成下一段时，机器人还在执行上一段，等新片段算完，机器人已经走出去一段了。如果新动作不考虑这段已确定的运动，前后就会跳。

它的做法是：训练时就让 Action Expert 学会「根据长度可变、无噪声的动作前缀生成后续轨迹」；部署时这段前缀就是已经下发、还在执行的命令，前缀固定不动，只生成它后面的部分，新片段自然从前缀边界接着走。1.0-AR 则用增量解码，让「生成—解码—执行」三者重叠，一段准备好就先跑。

再往下就是把模型做小：Lite 面向需要反复微调的下游任务，Nano 面向算力受限场景。原文给的结果是 Nano 配 XInfer 后，单张 Blackwell 消费级 GPU 支持 18 台机器人。这句话的含金量在于它把「一个模型服务多机」变成了调度问题，而不是「再买一台 A100」的问题。

Formula核心公式：三个式子，对应「怎么生成动作」「动作怎么变成符号」「生成时怎么接得上」

① Flow Matching 目标：不猜答案，先学「从噪声走到答案的那条直线」
\[ \mathcal{L}_{\mathrm{FM}}(\theta)=\mathbb{E}_{t\sim U(0,1),\;a_0\sim p_{\text{noise}},\;c}\Big[\big\lVert v_\theta(a_t,t,c)-(a_1-a_0)\big\rVert^{2}\Big],\qquad a_t=(1-t)a_0+t\,a_1 \]
\(c\) 是视觉语言上下文（当前画面 + 指令），\(a_0\) 是一段随机噪声轨迹，\(a_1\) 是真实动作片段，\(a_t\) 是两者按时间 \(t\) 插值出来的中间点，\(v_\theta\) 是要学的速度场。大白话：别让网络一步猜出动作，而是告诉它「从噪声到真动作，这一小步该往哪个方向挪」。训练时方向是已知的（真动作减噪声，就是那条直线的方向），所以这是个有标准答案的回归题；推理时从纯噪声出发，按这个方向走几小步，就落到一段合理的动作轨迹上。为什么用这个而不是直接回归动作？因为一段动作可能有多种合理走法（绕过杯子左边或右边都行），直接回归会把它们平均成「从杯子里穿过去」；学速度场保留了这个多峰性，采样时走哪条由噪声起点决定。
② 分层残差动作 token：粗的用少码，细的用残差补
\[ a \;\approx\; \sum_{k=1}^{K}\mathcal{D}_k(z_k),\qquad z_k=\mathcal{E}_k\!\left(a-\sum_{j\(\mathcal{E}_k\) 是第 \(k\) 层编码器，\(\mathcal{D}_k\) 是对应解码器，\(z_k\) 是该层的离散码，\(K\) 是层数。大白话：第一层只记「手大致往哪个方向走」，解码出来先拼个大概；然后拿真轨迹减掉这个大概，剩下的是「差在哪儿」，交给第二层记；再减再记，一层层补。为什么要分层而不是一次量化？因为一次量化必须同时决定「整体形状」和「毫米级细节」，码本容量会被细节吃掉，粗结构反而失真。分层之后，粗结构用很少的码就能表达准确，细节按需追加——这正是「压缩率、重建精度、语义友好度」那个三角的一个折中点。另外它还顺手做了两件事：动作特征和同一时刻的视觉语言特征对齐、并预测下一时刻的视觉语言特征，逼这些码携带语义而不仅是数值。
③ 实时分块：前缀不许改，只续写后面
\[ a^{\text{new}}_{1:H}\sim p_\theta\big(\cdot\mid o_t,\;\ell,\;a^{\text{pre}}_{1:m}\big),\qquad a^{\text{pre}}_{1:m}\equiv\text{已下发但尚未执行完的命令} \]
\(o_t\) 是当前观测，\(\ell\) 是语言指令，\(a^{\text{pre}}_{1:m}\) 是机器人还在执行的那 \(m\) 步命令，\(H\) 是新片段的长度。大白话：机器人不会站着等你算完。它已经在跑上一段指令了，所以新算出来的这段必须承认「前 \(m\) 步已经定了、改不了」，只负责接在后面。这就是把「推理有延迟」这个物理事实写进条件里，而不是假装延迟不存在。不这么做会怎样？新片段从零开始生成，起点和机器人当前实际位置差了一截，接上去就是一次抖动或急停——在真机上表现为「动作抽一下」，在视频里几乎看不出来，但在产线上就是撞机风险。这也是 1.0-AR 那条路要用增量解码的原因：让生成、解码、执行三者重叠，把等待时间藏进执行时间里。

补充一个不进公式但很关键的实验：它固定动作表示和学习目标，训了一组 10M 到 1B 参数的自回归 Transformer 专门预测离散动作序列，不带任何视觉或语言输入，结果验证交叉熵随算力持续下降。这个实验的意义是排除了「涨点只是因为视觉语言主干变强」——动作预测这一件事本身，就能吃 scaling。这也解释了为什么值得把动作塞进预训练，而不是当成一个外挂头。

Worth价值与局限：它把「数据口径」提到了架构前面，但证据链是自证的

真正值得带走的三点：

  • 把「数据口径」当成第一性问题。绝大多数 VLA 论文的叙事是「我们的架构更好」，这篇的叙事是「我们先把数据分了层，架构只是顺着数据长出来的」。这个顺序更接近工程现实——数据决定了模型能学到什么，架构只决定学得多快。
  • 用「适配小时数」当价值单位。10 小时 vs 1000 小时、跨站点保留 90% vs 下降 90%，这两个数比任何榜单分数都更能回答「值不值得买」。这是买方视角，不是论文视角。
  • 两个可直接复用的工程 trick：一是分层残差 token（解决压缩率与细节的矛盾），二是状态/命令解耦（让 UMI 和真机在同一套监督下共存，还顺手把正逆动力学变成同一批参数的两个任务）。这两个跟具体架构无关，换任何 VLA 都能用。

但必须说清它的局限，而且这些局限不小：

证据链是自证的。这是厂商技术博客，没有 arXiv 号、没有开源权重、没有第三方复现。核心评测集 ManipArena 由团队参与构建，评测协议、对手（π0.5）的训练数据预算是否对齐、是否同等微调，原文都没有交代。语义类 78% 对 44% 这么悬殊的差距，在没有协议细节的情况下，更可能是「主干规模 + 数据配比」的结果，而不是「动作设计」的功劳——而原文没有做把这个因素拆开的消融。
  • 「10 小时 vs 1000 小时」缺分母。原文说的是「在该任务及其设定的可用水平下」——可用水平是多少成功率、多少节拍、允许多少人工干预，全都没给。只给倍数不给绝对值，无法判断这个 100 倍是稳健结论还是特定任务下的巧合。
  • 10:1 的混采比例是单点结论。这是特定任务、特定本体、特定夹爪下测出来的。换一个自由度更高的手、换一个需要力控的任务，无机器人数据能不能顶到 10:1 完全未知。原文自己也留了口子：「并不假设无机器人数据能够消除真机数据的作用」。
  • 开放任务的水位其实不高。377 次真机评估、平均 6.45/10、零样本成功率 55.1%，多步骤顺序执行 66.5%、双臂协作 57.7%。翻译一下：自由出题时，接近一半的指令是失败的，多步骤和双臂这两类离生产还差得远。前面 15 项里 14 项领先很好看，但那 15 项是设计过的。
  • Ego 视频那条路的收益无法验证。让没有动作标签的视频去学「未来画面怎么变」，本质是学视觉动力学，不等于学会了动作。这部分到底贡献了多少，只能靠内部消融，外部看不到。
  • 「通用模型也能生成动作」这一段暴露了真问题。原文提到 NVIDIA Astranomy 在 RoboLab 里测 Astra 直接生成动作，能承担抓放决策，但受限于推理延迟与成本。这其实是在问：如果通用大模型能直接出动作，具身基模的护城河到底在哪？原文给的答案是「连接本体、连续动作、物理反馈」——这个答案合理，但它是定性的，没有实验支撑。
怎么读这篇最划算：把它当工程决策记录读，不当性能证明读。值得抄的是「数据按可信度分流」这套口径、以及 UMI 数据必须先过体检这条纪律；不必抄的是它的排名和倍数——那些需要等第三方复现，或者等你自己的场景实测。如果你想判断它对你有没有用，别看 ManipArena 的 1500 分，去看两件事：你的场景里有没有「只有画面没有动作」的存量数据（有的话第二条路对你有效），以及你换一个新工位要采多少小时（这才是它真正卖的东西）。
