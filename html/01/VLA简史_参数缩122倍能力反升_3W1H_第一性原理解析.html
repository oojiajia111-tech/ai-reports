第一性原理核心立论

这篇「简史」真正记录的不是一次 Scaling 故事，而是一次接口重写：从 RT-2 的 55B 到 SmolVLA 的 450M，参数缩了 122 倍，而每一步能力都在涨。所以 VLA 的瓶颈从来不在模型容量，而在「动作怎么被表示出来」——离散 token、Diffusion、Flow Matching、显式空间轨迹，四套接口依次上桌，每一套都解掉前一环留下的物理约束。这也反过来解释了文章开头那句「机器人领域至今未就 Scaling 方向达成共识」：不是大家没找到方向，是这条赛道的瓶颈本来就不在参数量上。但文章在关键换挡处（Diffusion 为什么要换成 Flow Matching）断了线，又漏掉了全程最重要的隐变量——Action Chunk 执行几步才重规划，而它直接决定所有成功率数字能否互比。

是什么：参数一路在缩 为什么：三个正交自由度 怎么做：作者的实验怎么读 哪里不对：四处断点 结论与判断清单

是什么这不是「模型变大史」，正相反——参数一路在缩

文章按时间线排了九代模型，读起来像一条「越来越强」的上升曲线。但把参数量单独抽出来看，这条曲线的方向是向下的：

模型年份参数量相对上一代动作接口

\[ \frac{55\text{B}}{450\text{M}} = \frac{55{,}000}{450} \approx \mathbf{122.2\ \text{倍}} \] \[ \text{OpenVLA 对 RT-2-X：}\ \frac{55}{7} \approx 7.86\ \text{倍参数差，成功率反而高 } 16.5\ \text{pp} \] \[ \text{SmolVLA 对 OpenVLA：}\ \frac{7000}{450} \approx 15.56\ \text{倍} \]
原文说 SmolVLA「大约只有 OpenVLA 的十六分之一」，精确值是 15.56。这个「大约」用得没问题，但把 55B 与 450M 并排放在一起，118 到 122 倍的跨度已经是三个数量级里的一大半，而这条线是下降的。

更值得盯住的是 RT-2-X 与 OpenVLA 那一组对比：55B 的 RT-2-X 在 29 项任务上被 7B 的 OpenVLA 反超 16.5 个百分点，而 OpenVLA 只有对方约七分之一的参数。原文对这件事的解释只给了一句——因为 OpenVLA 只用机器人数据微调、丢了互联网知识的保留——那是在解释 RT-2-X 在 Taylor Swift 这类语义泛化任务上为什么还能赢，并没有解释七分之一的参数是怎么在操作任务上反超的。这个空白比它看起来大：如果参数量不是决定因素，那 122 倍的缩减就不是妥协，而是去掉了冗余。

把这条线倒过来读，整篇文章的论点会清晰得多：VLA 不是在「做大模型」，而是在给同一个 VLM 换更省的动作接口。接口一换，参数就能砍，砍完还能更强。文章开头自称「机器人领域至今未就最值得 Scaling 的方向形成共识」，其实答案已经埋在它自己的表里——这条赛道不需要在参数量上达成共识，因为它本来就不靠这个。

为什么四代接口各自解掉了一个物理约束，而不是各自堆了一个新模块

把九代模型按「动作怎么表示」重新分组，四次换挡的动机各不相同的，而且每一次都精确对应前一代留下的硬约束：

第一挡：离散 token —— 解决「能不能复用 VLM 的词汇表」

RT-1 把连续动作切成每维 256 个 bin，动作预测就退化成分类问题；RT-2 更进一步，把这些 bin 映射到 VLM 词表里已有的 token 上（PaLI-X 本来就有 1,000 以内整数的 token，PaLM-E 则复用词表里最低频的 256 个），于是机器人动作直接变成「另一种语言」，可以走现成的 next-token prediction，不需要新造一个回归头。代价是自回归要按顺序吐 8 个 token，推理延迟随维度线性上涨——原文自己点出「顺序生成也会增加推理延迟」。

RT-1 里还有一处被低估的设计：486 → 48 的信息瓶颈
六帧图像 × 每帧 81 个视觉 token = 486，TokenLearner 把每帧压到 8 个，总数降到 48。压缩比 10.125 倍（486 ÷ 48）。原文评价是「小物体或精确的空间细节可能会丢失」——这句是准确的，但真正的代价不在这里：每帧 8 个摘要 token，等于每帧只允许 8 个独立的注意力落点。抓取任务里「夹爪是否对上把手」这种判据需要的是空间精度而不是语义摘要，8 个 token 装不下。RT-1 在背景变化时成功率掉到 59%（已见任务 97%），这个跌幅和瓶颈形状是对得上的。

第二挡：Diffusion —— 解决「一个指令对应多条正确轨迹」

这是全文里唯一一处把数学动机讲清楚了的地方：抓障碍物后的杯子，可以左绕也可以右绕；用 MSE 训练，模型会对两条路径取平均，结果预测出一条直接穿过障碍物的轨迹——平均值不是解之一，平均值是一个错误答案。Diffusion 学的是分布，去噪一次只吐一个样本，于是「多峰」被保住了。

Octo 还有个工程细节值得单独记：Transformer 每次预测只跑一次，反复去噪发生在小得多的 Action Head 内部，不需要每个去噪步都重跑主干。这是 Diffusion 能上机器人的前提——否则推理成本会被去噪步数整个乘一遍。

第三挡：Flow Matching + Action Expert —— 解决「语义知识在 3B 里、控制精度在别处」

π0 的做法是并置：PaliGemma 3B 负责理解，一个 300M 的 Action Expert（沿用 Gemma 架构、宽度更小、随机初始化）负责出连续动作，两者靠 Attention 对齐。

Action Expert 的容量占比
\[ \frac{300\text{M}}{3\text{B} + 300\text{M}} = \frac{0.3}{3.3} \approx \mathbf{9.1\%} \]
不到一成的参数承担了全部连续动作生成。「理解」和「控制」被显式分账了——这是 VLA 从「一个 VLM 硬扛」走向「两个专家分工」的分界点。SmolVLA 更激进：只取语言解码器前半截的层，每张图压到 64 个 token，不等完整语言模型跑完就取中间特征出动作。

第四挡：显式空间中间量 —— 解决「不可检查」

MolmoAct 走的是另一条路：先预测深度（用 Depth Anything V2 + VQ-VAE 压成离散 token 网格），再预测最多五个图像空间点描述末端路径，最后才出 8 个离散动作的 chunk。原文给出的价值判断很准——「现在我们可以直接检查模型预测的深度信息和预期运动轨迹，而不再只能观察最终生成的动作」。这是可解释性第一次落在中间张量上，而不是落在事后可视化上。

但原文也自己承认两条代价：生成中间 token 增加延迟；而且一条看起来合理的轨迹，不保证机器人能正确执行。后一句其实很重——它意味着 MolmoAct 的中间量是「人类可读的旁路」，不是「执行路径上的必要条件」。深度错了但动作对了是完全可能的，这时候可解释性提供的信心是假的。

四挡合起来看，有一条被忽略的替代关系：chunk 取代了历史帧。RT-1 用六帧历史图像来推断运动趋势（原文明确写了），RT-2 改成只用当前帧（原文也明确写了「与 RT-1 使用六帧历史图像不同」）。时序信息没有消失，它被搬进了动作表示里——一次预测未来 50 个动作，等于把「过去发生了什么」替换成「接下来会发生什么」。所以 chunk 不只是省通信，它是历史帧的等价替代物。这个视角能解释为什么 RT-2 敢砍历史：不是它不需要时序，是它换了一种方式携带。

怎么做作者那三个自制实验，真正的价值不在结论而在口径

原文夹了三个作者自己的实验（843 条 LIBERO 动作的离散化、SmolVLA 的语言条件、chunk 执行步数），前两个写了结果，第三个明确说「之后会在另一篇 Blog 分享」。第一个实验值得细读，因为它是全文唯一有可复现数字的部分。

实验一：离散化的误差到底由什么决定

做法是从三个 LIBERO 示范轨迹里取 843 条动作，把每个分量量化到 16/32/64/128/256 个均匀 bin，比较两种取值范围策略：Full Range（观测到的最小到最大）与 Clipped Range（第 1 到第 99 百分位）。

Bin 数Full RangeClipped Range谁更好
16RMSE 较大略优Clipped（细间隔补偿了截断）
256基准RMSE 约高 5.5 倍Full（反超）

作者的解释是对的：bin 多了之后，Clipped 换来的额外精度已经补不上丢掉极端值造成的损失。但这句话可以算得更硬。量化误差的方差正比于 bin 宽的平方，RMS 误差正比于 bin 宽：

为什么 5.5 倍的 RMSE 差意味着尾部很重
\[ \text{RMSE}_{\text{full}} \approx \frac{R}{256\sqrt{12}}, \qquad \text{RMSE}_{\text{clip}} \approx \frac{0.98R}{256\sqrt{12}} \] \[ \text{若只算内部点，两者只差 } \frac{1}{0.98} = 1.02\ \text{倍} \] \[ \text{实测差 } 5.5\ \text{倍} \;\Longrightarrow\; \text{差额全部来自尾部}\ f\ \text{的截断误差} \] \[ \text{RMSE}_{\text{clip}}^2 = (1-f)\left(\tfrac{R}{256\sqrt{12}}\right)^2 + f\,\mathbb{E}[\delta_{\text{tail}}^2] \] \[ \text{反解：}\ f\,\mathbb{E}[\delta_{\text{tail}}^2] \approx \frac{(5.5^2-1)R^2}{12\cdot 256^2} \approx \frac{R^2}{26{,}214} \]
取 f = 2%（恰好是 Clipped 丢掉的尾部比例），得 \(\mathbb{E}[\delta_{\text{tail}}] \approx 0.044R\)：只要尾部动作平均超出 4.4% 的动作全幅，就足以解释这 5.5 倍。换成人话——这 843 条 LIBERO 动作的分布尾部很重，被截断的那 2% 不是噪声，是真实的极端动作。
于是出现全文最该被追问的一处矛盾：作者的实验结论说 256 bin 时 Full Range 更好 5.5 倍，而实际部署里 OpenVLA 与 RT-2 用的恰恰都是 Clipped（第 1 到第 99 百分位）。原文两处都写了——「这些分量使用第 1 至第 99 百分位数构成的范围，被离散化为 256 个 Bin」——但从来没有把这两句话放在一起看，也没解释为什么主流选择与自己的实验结论相反。

一个可能的解释是：Clipped 换来的是标注一致性而非精度——不同机器人、不同数据集的动作幅值差得很远，统一裁到 1–99 百分位能让 bin 的物理含义跨具身可比，而 Full Range 会让每个数据集有自己的 bin 宽。如果这个解释成立，那作者的实验其实测出了一件事：为了跨具身可比，主流方案系统性地牺牲了尾部动作的精度。这是一个真实的取舍，不是一个错误——但文章把它当成了两件互不相关的事。

实验一的第二个发现比第一个更有价值

原话是：「单步误差更小，并不总是意味着最终偏差也更小，因为不同误差可能相互叠加，也可能相互抵消。」这句话是可以形式化的，而作者只停在定性：

长时程误差的两条分支
\[ \text{终末偏差} = \sum_{i=1}^{n} \varepsilon_i \] \[ \text{独立误差：}\ \mathrm{Var}\!\left(\sum \varepsilon_i\right) = n\sigma^2 \Rightarrow \text{偏差} \propto \sqrt{n} \] \[ \text{反相关误差：}\ \mathrm{Var}\!\left(\sum \varepsilon_i\right) \to 0 \Rightarrow \text{偏差可自我抵消} \]
这就是「Bin 数加倍、RMSE 减半，长时程任务却不见得好」的机制：离散化精度只压住了 σ，压不住 ε 之间的相关性。而相关性由策略的闭环反馈决定——如果策略会根据误差修正，单步误差就会被吸收；如果是开环执行 chunk，误差就会沿 n 线性累积。这直接把问题引向了第四条断点。

哪里不对四处断点，其中一处会让全文所有成功率不可比

断点一：两个「unseen」被并排放了，其实不是同一个分布

RT-1 一节写「已见任务 97%，未见过的指令 76%，有视觉干扰物 83%，背景变化 59%」；RT-2 一节紧接着写「在此前未见过的场景中，成功率从 RT-1 的 32% 提升到 62%」。

两句都没错，但读者极易把「76%」和「32%」当成同一个指标在退步——它们测的是两个不同的分布：前者是语言组合的泛化（新指令、老场景），后者是环境配置的泛化（新场景、老指令）。原文没有明确标出这个切换，而这两个数相差 2.4 倍，正好落在「读起来像矛盾」的区间里。这不是原文的错误，是**相邻排列造成的错觉**，但值得在转载时补一句限定。

断点二：Diffusion 为什么被换成 Flow Matching，全文没有一句解释

这是整条演进线最关键的换挡，而它落在空白处。文章为 Diffusion 花了整整一段论证动机（多峰分布、MSE 取平均会穿墙），但到 π0 与 SmolVLA 时，只写了「使用 Flow Matching」「与 π0 一样使用 Flow Matching」，没有说明 Flow Matching 解决了 Diffusion 的什么问题。

按常理推断，答案在推理成本：Diffusion 需要几十步去噪，Flow Matching 学的是从噪声到数据的直线路径（常微分方程），同样的精度下可以用更少的积分步。如果这个推断成立，那么「Octo → π0」的换挡和「RT-1 486 token → SmolVLA 64 token」是同一个动机的两次表现——都在压推理延迟。原文明写了一句相关的：「与 RT-1 和 RT-2 使用离散动作 token 不同，Octo 通过 Diffusion 预测连续 Action Chunk」——它对比了离散 vs 连续，却没对比 Diffusion vs Flow。

一篇自称「追溯这一演进过程」的 Blog，在唯一一次动作生成器换代的地方缺了理由，这是结构性缺陷。读者读完会以为 Flow Matching 只是 Diffusion 的一个口味变体。而实际上如果它是「为了少跑几步去噪」，那它是四代接口里第一次为了延迟而换算法，重要性远超一个实现细节。

断点三（最重要）：Action Chunk 执行几步才重规划，是全文的隐变量

原文在 π0 一节里写了两句话，隔得很近：

原文两句
「π0 预测一个包含未来 50 个动作的 Action Chunk」
「一次预测 50 个动作，并不意味着每个动作都使用了最新的观测。因此，在下一次预测之前，究竟执行 Action Chunk 中的多少个动作，也成为一个需要考虑的设计选择。我围绕这个问题做了一些有意思的实验，之后会在另一篇 Blog 中分享。」

这两句合起来意味着：所有 VLA 的成功率都不是一个标量，而是 (模型, chunk 执行步数) 的函数。同一个 π0 权重，执行 1 步就重规划与执行 50 步才重规划，会是两个完全不同的系统——前者每 20 ms 看一次世界，后者用一张旧图管一整秒。

把「执行几步」换算成物理时间
\[ \text{若控制频率 } f_c = 50\ \text{Hz},\quad 50\ \text{步 chunk} = \frac{50}{50} = 1.0\ \text{秒} \] \[ \text{执行比例 } k\ \text{（每 } k \text{ 步重规划）：观测龄期} = \frac{k}{50}\ \text{秒} \] \[ k=1 \Rightarrow 20\ \text{ms},\quad k=25 \Rightarrow 500\ \text{ms},\quad k=50 \Rightarrow 1000\ \text{ms} \]
控制频率原文未给，此处按 50 Hz 常见值推演。同样的权重，观测龄期在 20 ms 到 1,000 ms 之间摆动 50 倍。而这恰好与实验一的形式化结论接上了：k 越大，闭环修正越少，单步误差越容易沿 n 线性累积。「chunk 越短越准但越慢」与「chunk 越长越快但越飘」是同一个变量的两端，而不是两个独立的工程问题。

由此可以推出一个对读者最有用的判断：不同论文报告的成功率，只要 chunk 执行步数不同，就不能直接相比。而本文通篇在用成功率做代际比较（RT-1 97% → RT-2 62% → RT-2-X 75.8% → OpenVLA +16.5pp → Octo 72%）。这些数字横跨离散单步、Diffusion chunk、Flow chunk 三种执行范式，分母不同。（严格说大多数报告会附自己的设置，问题在于本文没有把它们并列时标出这个自由度。）

SmolVLA 那一节其实已经撞上了同一个变量，只是没被认出来：「异步推理……机器人在执行当前 Action Chunk 的同时，请求生成下一个 Action Chunk。这种方式大约能把吞吐量提高一倍」——但紧接着一句自己打了折：「排队等待执行的动作仍然基于较早的观测，并不是每一步都使用最新图像生成的。」异步推理是用观测龄期换吞吐，和 k 变大是同一件事，只是实现层不同。文章把它们分两节讲，读者会以为是两个独立优化。

断点四：Pi Zero 是全文唯一没有数字的一次比较

原文在 Physical Intelligence 一节写：「你可能会猜测团队通过扩大模型规模来超越 RT-2，但实际上，Pi Zero 的模型规模更小。」

这句话承载着全文最核心的论点（不是靠 scaling），却是九代模型里唯一一个既没给参数量、也没给任何具体对比的地方。前面 RT-2 给了 5B/12B/55B，Octo 给了 27M/93M，π0 给了 3B+300M，SmolVLA 给了 450M，唯独 Pi Zero 只有形容词「更小」。论点最需要的那个证据，恰好是唯一缺席的那个。

四处断点合起来的性质不同，要分开算：断点一是表述排列问题（补一句限定即可）；断点二是论证缺口（需要补一段 Diffusion → Flow 的动机）；断点三是度量问题——它不影响任何单个数字的正确性，但掏空了所有跨代比较的可比性，是唯一一处会改变读者结论的；断点四是证据缺口（一个数量词的缺位）。

结论带走三句话，和一份自检清单

第一句：VLA 的十年不是参数曲线，是接口曲线。55B → 450M 的 122 倍缩减里没有一次性能倒退，而每一次能力跃升都对应动作表示的一次换代：离散 token 让 VLM 词表能复用、Diffusion 保住多峰、Flow Matching 压掉去噪步数、显式空间中间量换来可检查性。瓶颈在接口，不在容量。

第二句：chunk 是历史帧的替代品。RT-1 用六帧换时序，RT-2 砍掉历史、改用一次预测多个未来动作。时序信息没有消失，只是从「看过去」搬到了「猜未来」。理解了这一点，「RT-2 为什么敢只用单帧」就不再是设计偶然。

第三句：成功率不是标量。它是 (模型, chunk 执行步数, 控制频率) 的函数。本文所有跨代成功率比较，都缺这个自由度的标注——这是全文唯一一处会影响结论的缺口，而作者自己已经意识到，只是把讨论推迟到了下一篇。

读同类 VLA 报告时的自检清单

  1. 动作接口是哪一挡？离散 bin / Diffusion / Flow Matching / 显式中间量——不同挡的推理成本和精度特性不可互推。
  2. chunk 执行几步才重规划？没写这个数，成功率不可与其它工作相比。
  3. Clipped 还是 Full？若用 1–99 百分位，尾部动作被系统性牺牲；若用 min–max，跨数据集 bin 宽不可比。两者只能选一个。
  4. 互联网数据保留了吗？co-fine-tuning 与否决定了「操作强」和「语义泛化强」是两条互斥的路线（OpenVLA 反超 RT-2-X 16.5pp，却在 Taylor Swift 类任务上输）。
  5. 视觉 token 预算多少？RT-1 每帧 8 个、SmolVLA 每帧 64 个；token 数直接决定「夹爪有没有对上把手」这类空间判据能不能被表达。
最后回到文章开头那句自问——「究竟发生了哪些变化？又是哪些架构设计让这些系统真正发挥作用？」按它自己给出的证据，答案是：让系统真正发挥作用的是把语义理解与控制精度分账（π0 用 9.1% 的参数做 Action Expert），并且把时序信息从输入搬进输出（chunk 取代历史帧）。至于模型规模，它在这条路上唯一的作用，是被一路砍掉。
