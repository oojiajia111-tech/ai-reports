一句话 它把"采集一个动作"的边际成本，从一台机器人降到了一双手
💡 第一性原理核心立论

机器人数据一直有个死结：想采一个动作，必须同时凑齐一个操作员、一台机器人、一个工位。三者绑定，边际成本极高，所以全行业的数据量卡在几万小时上不去了。AIRoA-0 干的事情非常朴素：把机器人从采集环节里拿掉，只留一个人和两个夹爪。于是数据量从"随机器人数量增长"变成"随愿意记录的人数增长"——一口气做到 16,151 小时、1065 万个子任务、一百多名操作者、一百多个任务，而且零机器人数据。代价是三个：没有关节角只能看夹爪、没有全局视野只有两个手腕相机、没有失败样本只有成功示范。这三个缺口分别用锚定相对位姿、两级语言 + 阶段预测 + 本体感知记忆、Visual Evidence Budget 补上。结果是十项双臂任务平均 78%，而 π0.5、XR-1、GR00T N1.7、MolmoAct2 在同样示范上 post-training 后最强只有 27%——并且 A-0 十项任务共用一套 recipe，那四个模型是逐任务搜过最佳超参的。它证明的不是"数据多就赢"，而是数据形态对了，规模才转得动。

What是什么：一套"从人手到机器人"的完整流水线

AIRoA-0（简称 A-0）由四个互相咬合的部分组成，缺一个都不成立：

环节做什么关键设计

接口的输入输出极其克制：两张手腕图像、一条指令、本体感知状态，在 20 Hz 网格上输出未来 32 个动作。没有头部相机、没有场景相机、没有地图。

  • 同一套权重跑通 双臂 Franka、TX-G2 人形、OpenArm、一对 UR，四种本体、零重训、零调参。

Why为什么：五条公理，把"数据瓶颈"从硬件挪到了人

公理一：采集的边际成本，才是数据规模的真正天花板

算一笔账。遥操作采一条数据，需要：操作员在场、机器人空闲、工位搭好、环境布置好、有人盯着别撞。这五件事同时满足才能采一小时。所以机器人数据的增长速度，被"机器人的数量"锁死了。

手持夹爪把这个式子改了：操作员双手各持一个夹爪，去干一件真事，数据就出来了。不需要机器人、不需要工位、不需要场地——在任意地点，像平时一样完成任务即可。

推论 1
这条约束一旦解开，数据量就不该按"机器人台数 × 运行时长"估，而该按"人数 × 每人愿意记录的时长"估。16,151 小时 / 一百多名操作者 ≈ 人均 150 小时，这个量级一个人一两个月就能录出来。数据规模化从"资本支出问题"变成了"人力组织问题"。

公理二：要让手持数据能直接喂机器人，状态和动作的定义必须"不依赖本体"

这是全文最核心的一处技术设计，也是最容易被一句"用了 UMI 的相对轨迹"带过的。

先想清楚矛盾在哪：人手和机械臂没有共同的坐标系。没有共同的底座、没有共同的关节、没有共同的世界原点。如果你用"关节角"当动作，人手的示范根本没有关节角；如果你用"世界坐标系的绝对位姿"当动作，人手持和机器人携带时"世界原点"压根不是一回事。

解法是锚定（anchored）相对位姿：

锚定动作表示
\[ a_i^{(k)} \;=\; T_{\text{grip}}^{-1}(t)\ \cdot\ T_{\text{TCP}}^{(k)}(t+i),\qquad i=0,1,\dots,H-1 \]
符号翻译：\(T_{\text{grip}}(t)\) 是拿到当前这张观察时夹爪的位姿；\(T_{\text{TCP}}^{(k)}(t+i)\) 是未来第 \(i\) 步夹爪工具中心点该到的位姿。整个动作块里的每一个动作，都是相对于"此刻夹爪在哪"来表达的目标位姿。
大白话：不说"去世界坐标 (1.2, 0.3, 0.9)"，只说"从你现在的位置往右前上方挪 12 厘米、转 30 度"。这么一说，人手和机械臂就站在同一条起跑线上了——谁都不需要知道自己在地球上的绝对位置。
每条臂 10 个数：平移 3 + 6D 旋转 6 + 夹爪开合指令 1，双臂共 20 个数。状态是"一只夹爪在另一只夹爪坐标系中的位姿 + 两个夹爪的开合度"，共 11 个数。

这个表示还顺带解决了两个工程问题：

  • 误差不累积：每个动作都是独立的绝对目标，不是"在上一个动作基础上加一点"的增量。所以前面一步有小偏差，不会滚雪球。
  • 控制器频率可以不同：动作块描述的是一串目标位姿，机器人底层的控制器可以按自己的频率去跟踪它——策略的 20 Hz 和执行层的 100 Hz 解耦了。
推论 2
"跨本体"不是靠适配层做出来的，是靠表示层做出来的。只要状态和动作都定义在夹爪上，换一条机械臂就只是换一个跟踪器——所以四种机器人能用完全相同的权重。反过来，任何含底座、关节角、世界坐标的表示，都会在换本体的那一刻失效。

公理三：只有两个手腕相机，就必然丢失"我在任务第几步"这个信息

这一点是手持路线的天然缺陷，必须正面补。两个手腕视野加起来大概能看到工作台的局部，但看不到全局进度：你面前有一个零件，你怎么知道"该去拿了"还是"已经拿过了要放下"？同一个画面，可以对应好几个不同的子任务。

如果只给一条任务指令，这个歧义只能在动作分布内部硬解——等于让策略去猜。A-0 选择把它显式拆开，用三层机制：

  1. 两级语言（预训练）：每条示范都有"任务指令"（换扫地机器人部件）和"子任务指令"（取下第一块用过的拖布并放入盒子）。预训练时让语言主干去预测当前子任务文本。这个预测只用于训练、不进 Action Expert——它的作用是强迫表示里编码"进度"，因为你不说出当前步骤，就没法从两个局部视野里推出进度。
  2. stage head（post-training）：把任务划成若干阶段（每组连续子任务），执行前先预测当前阶段，以语言形式传给 Action Expert。用交叉熵训练，标签直接来自示范里的子任务标注，不需要额外标注。
  3. 本体感知记忆：保存最近 10 个本体状态 + 每个状态距现在多久，用 4 个 query 压成 4 个 token 塞进 prompt。解决"单帧看不出刚才干了什么"。

记忆这块有个细节很讲究：不同机器人查询策略的频率不一样，如果按"步数"索引历史，同样 10 步在不同机器人上对应的时间跨度完全不同。所以训练时按 5–15 Hz 随机采样历史、并显式编码每个状态的真实时间年龄，让同一策略能适应这个范围内的任意频率。而且训练中有四分之一的时间干脆不给历史，逼它既能用记忆、也能不用记忆。

公理四：手腕视野里大部分像素与任务无关，而"无关部分"恰好是地点之间变化最大的

这条公理直接引出 Visual Evidence Budget。逻辑链条是：

  • 手腕相机看到的东西远多于任务需要——桌面纹理、背景墙、房间其他区域；
  • 而不同采集地点之间，变化最大的恰恰就是这些无关区域；
  • 所以如果策略平等对待每个像素，"换一个地方"就会带来巨大的分布偏移。

结论："看哪里"必须是学出来的，不能用固定裁剪，也不能靠人工标注意注区域（标不起，1065 万个片段）。A-0 的做法是给一个"预算"，让模型自己在预算内决定保留哪些 token——不给答案，只给约束。

公理五：数据规模的价值，必须能在一个可测的曲线上体现出来

如果 16,151 小时只是"很多"，那这篇论文就只是一个工程报告。它必须证明"再多一点会更好"，否则没人会继续投人力去录。所以作者做了两组 scaling 实验：把预训练数据切成 50% / 25% / 12.5% / 6.25% 分别训，然后看两个指标——预训练的 action loss，和同样 16 组任务数据 post-training 之后的 loss。

推论 3
关键在第二个指标：预训练数据多带来的优势，能不能穿过 post-training 活下来？如果不能，那预训练就是在做无用功——反正最后都要用目标任务数据微调。作者实测：能，而且前 1,000 步之后差距不再缩小。这一条才是"值得继续采数据"的真正依据。
公理链收口：采集成本卡住规模（公理一）+ 表示必须不依赖本体（公理二）+ 局部视野丢失进度（公理三）+ 无关像素随地点漂移（公理四）+ 规模价值必须可测（公理五）= 「手持夹爪 + 锚定动作 + 两级语言 + 视觉预算」是一套彼此咬合的最小设计。抽掉任何一块，整条链路就断：没有锚定动作就没有跨本体，没有两级语言就没有长程，没有视觉预算就换不了地点，没有 scaling 曲线就没人继续投人力。

How怎么拆：四个零件与三个数字

零件一：YUBI 夹爪——让"示范"等于"执行"

YUBI 的设计目标只有一个：让记录下来的内容和机器人将来看到、执行的内容完全一致。为此它做了三件事——

  • 手指驱动：手指闭合，夹爪就闭合。所以人操作时的手感就是夹爪的手感，不需要额外控制器；
  • 手腕处装相机：视角在人手中和机械臂上是同一个物理位置；
  • 跟踪 6 自由度运动：所以能算出夹爪位姿，进而算出锚定动作。

同一个夹爪可以直接装到机械臂上做末端执行器。这是整条路线成立的前提：采集工具 = 执行工具。

零件二：Visual Evidence Budget——用预算逼出注意力

这部分是全文技术含量最高的一处，值得把式子摊开看。

gate 打分 + token 缩放
\[ p_j=\sigma\Big(f\big(\text{token}_j,\ \bar{c}\big)\Big),\qquad \tilde{x}_j=\big(\phi+(1-\phi)\,p_j\big)\cdot x_j \]
\(f\) 是一个小网络，输入是某个图像 token 和指令的池化摘要 \(\bar c\)——也就是说"这个位置重不重要"是相对当前指令判断的，不是绝对的。\(\phi\) 是 floor，保证每个 token 至少留一点信息痕迹（不至于被完全抹掉）。
所以这个 gate 不是"硬裁剪"，而是按重要性做软缩放：重要的 token 保持原样，不重要的被压小。
budget loss：只约束平均值，不告诉它看哪
\[ \mathcal{L}_{\text{budget}}=\Big(\frac{1}{N}\sum_{j=1}^{N}p_j-\tau\Big)^2 \]
这就是全部的监督信号：一个视野里 N 个 token 的平均保留概率，要接近目标值 \(\tau\)。没有 mask、没有 box、没有任何区域标注。
精妙之处在于两个损失的分工：budget loss 管"总量"（你不能全都看，也不能全都不看），action loss 管"怎么分配"（在总量固定的前提下，看哪里能让动作更准）。约束总量、放开分配——这是"无监督注意力"能work的关键。

实测效果很干净：在 25 个子任务上，gate 都更关注夹爪本身和它正在操作的物体，而桌面、背景、房间其他区域的权重下降。也就是说，它自己学会了"注意力应该跟着手走"——而这恰恰是迁移到新地点时最需要的性质。

post-training 阶段还多了一层用法：把 gate 也作用到 attention 上。做法是停止 keep probability 的梯度、把它投影成符合预算的形式，构造一个先验，加进 Action Token 对 Image Token 的注意力分数里，权重在前 500 步内从 0 升到 1。所以 gate 有两个身份——输入端缩放器和注意力的先验，两者在部署时都保留。

零件三：Non-uniform Streaming Decoding——让两个 slot 就够用

这部分解决的是"怎么能既连续又跟得上变化"。先把标准做法和它的毛病讲清楚：

  • 标准 Flow Matching 推理：每个动作块都从纯噪声重新生成，跑 10 次网络。缺点：块与块之间没有连续性，接缝明显；
  • Streaming decoding（FlashVLA 引入 VLA）：维护一个 \(M\) 个 slot 的 buffer，每个 slot 处在不同噪声水平，不同块之间用因果注意力。每次查询只把最前面那个块推到干净并执行，新的噪声从尾部进。这样每个块会在连续 M 次观察中被逐步细化，还能用上前面的上下文。

但等距噪声有个两难：

两难
slot 少 → 每次更新幅度大 → 执行前最后一次修正是"猛改" → 出现接缝；
slot 多 → 每个块早在很久之前的观察下就基本定形了 → 场景变了反应不过来。本质是"平滑"和"响应速度"在抢同一个预算。

A-0 的解法是让更新幅度取决于"离执行还有多远"：只用 2 个 slot，噪声水平从 1 直接大步走到 0.1，然后在执行前只做 0.1 → 0 的小幅修正。

非均匀噪声 schedule
\[ \text{进入 buffer}:\ 1\ \longrightarrow\ 0.1\ \ \text{(大步粗化)},\qquad \text{执行前}:\ 0.1\ \longrightarrow\ 0\ \ \text{(小步精修)} \]
大白话：新来的块先被"大概画个草图"（大步去噪），之后只用最新一次观察做细微调整（小步修正）。因为每个动作都锚定在"查询时刻的夹爪位姿"上，所以每次小修正都是相对最新位姿的，不会和已经发生的动作打架。
训练时每个 slot 的噪声水平从对应区间采样，同时覆盖 steady-state 和 cold start。decoder 不增加任何参数——噪声水平通过 Action Expert 本来就有的时间条件输入进去。也就是说这是一个零参数成本的改动。

收益有两块：动作在块与块之间连续，同时还能及时响应场景变化；以及算力——观察只编码一次，steady state 下 Action Expert 只评估 2 次（标准要 10 次），H200 上单次查询约 60 ms。

零件四：stage EMA——防止一次误判带偏整段

阶段预测每次查询都重新做一次。这意味着一次错判，Action Expert 就可能收到"下一个步骤"的指令，动作立刻跑偏。而真实的阶段转换是渐进的（拖布取下来了，但还没开始装新的）。

所以用阶段预测概率的指数移动平均选最高概率阶段。效果：孤立的错误预测几乎不改变结果（被历史平均掉），真实的阶段转换则会随着过程展开被跟上。而且查询频率变化时不需要重新调参——这是 EMA 相对"固定窗口"的天然优势。

scaling 那条曲线的拟合形式是这样的：

预训练数据量与 post-training loss 的幂律关系
\[ \mathcal{L}_{\text{post}}\ \propto\ N^{-\alpha},\qquad N=\text{预训练时长（小时）},\ \ \alpha\ \text{使数据翻倍时 loss 下降约 }2.4\% \]
读法：这是典型的幂律收益——不是"越多越好"的线性，而是"每次翻倍只能换来一个固定小比例改善"。从约 1,000 小时到 16,000 小时（四次翻倍），累计下降约 9%。方向对，斜率低。

那个最有意思的失败案例

作者专门测了一次"执行中被打断"：A-0 正把绿色零件送往绿色格子时，操作者把整排格子推向一侧，让红色格子来到夹爪下方。机械臂原本在向下运动，但它在一个连续动作里转向了绿色格子的新位置，并把零件放进去。之后又交换绿黄格子，A-0 依然跟着新的绿色走。

这个行为由两个零件共同支撑：策略根据视觉观察判断该放哪（不是记住格子原来的位置），非均匀流式解码让每次新观察都能更新预测、同时保持运动连续。注意这里没有任何"重新规划"的显式步骤——没有地图、没有规划器，场景一变，预测跟着变。

Worth价值与局限：78% vs 27% 是真的，但这个比较有一半是"数据的胜利"

它真正证明了什么

1. 它把"数据规模化"从一句口号变成了一条可执行的路径。"人均 150 小时 × 一百多人"这个结构，是任何实验室都能复制的——不需要一百台机器人。而且它把整套东西都开放了：数据、预训练权重、post-training recipe、YUBI 硬件设计和采集软件。这是"数据基础设施"级别的工作，不是一篇模型论文。

2. 锚定动作这个表示，是全文最值得抄的一招。它用一句"相对于你现在的位姿"就同时解决了跨本体、误差不累积、控制频率解耦三个问题。好的表示设计就是这样——一个决定，三个收益。

3. Visual Evidence Budget 是"无监督注意力"的一个漂亮范式。约束总量、放开分配、用动作损失来教它分配——这三句话可以搬到任何"有冗余输入、缺区域标注"的场景里（比如长视频理解、多传感器融合）。

4. 零参数成本的 streaming 改进。只改噪声 schedule（2 个 slot、1→0.1→0），就把计算量从 10 次评估降到 2 次，还顺手解决了接缝问题。这种"改调度不改结构"的思路，在部署侧价值很高。

需要打问号的地方

  1. 78% vs 27% 这个对比，混淆了"数据规模"和"方法设计"。A-0 用的是自己 16,151 小时预训练出来的 checkpoint，四个对比模型用的是各自的公开 checkpoint。所以这 51 个百分点里，有多少来自"数据多了几个数量级"，有多少来自"锚定动作 / 两级语言 / 视觉预算"？论文没有做消融来分离这两者——比如用同样 16k 小时数据、但关掉 visual budget 训一个 A-0 变体。诚实地说，它证明的是"这条路线能走通"，不是"这套架构更优"。作者给对手搜了动作时域 4–16、多种频率、6/8/10 万步，算是尽力了，但数据这个变量没法对齐。
  2. 成功率口径要看清：15 次试验、部分完成给部分分。"部分完成的任务获得部分分数"意味着 78% 不是"完整完成率"，而是一个加权完成度。这在长程任务评测里是合理做法（有些任务要跑两分钟，全或无太粗），但它让"78%"读起来比实际更好。对比模型的 27% 很可能也是同一口径，所以相对差距可信，绝对水平要打折。
  3. 没有任何失败 / 恢复示范，这是路线级隐患。论文明确说"数据中没有机器人动作、失败或恢复的示例"。所以策略学的是"人是怎么成功的"，从来没见过"抓空了怎么办"。它靠视觉闭环硬扛扰动，但抓取失败和"格子被推走"是两种完全不同的扰动——后者还在演示分布附近，前者已经完全出界了。真机上抓空一次之后它怎么恢复，论文没给。
  4. 那个放错桌子的错误模式，暴露了最本质的弱点。最主要的失败是"把托盘放回起点桌而不是目标桌"——因为两张桌子外观完全相同。这说明模型没有持久的空间记忆，所有空间知识都在当前两张手腕图像里。两张一样的桌子，它就分不清自己站在哪。这不是调参能解决的，是表示层缺了一个"我在空间中的位置"的变量。有意思的是，同期 Mobile DVA 撞在同一堵墙上（见另一篇解析）——两个团队、两条路线，同一个短板：缺一个显式的自我定位量。
  5. 2.4% 这个幂律斜率，意味着这条路的尽头不远。数据翻倍只降 2.4% loss，四次翻倍才累计 9%。要再降一半 loss，需要的数据量是天文数字。换算成人力：现在是一百多人录 1.6 万小时，翻四倍就是四百多人录 6.4 万小时。这条路能走，但走不到"通用机器人"那么远。作者把这条曲线如实报出来，是负责的；但读者不该把它读成"继续堆数据就行"。
  6. "跨本体"是最容易高估的一条。四种机器人都装 YUBI 夹爪，所以"换本体"实际上是"换一个能精确跟踪同一串位姿的底座"。它证明了表示层的本体无关性，但没证明"任意机械臂"。一旦机械臂够不到示范里人手能到的地方（窄缝、深处、高架），锚定动作依然成立，但可达性不成立——这是手持路线一个没被讨论的隐含假设：人手能到的，机械臂也得到。
  7. 评测地点"零训练数据"是优点，但"地点"数量没说清。文章强调"在测试地点，训练数据没有一条来自该地点"，这很好；但十项任务是在几个地点测的？如果只有一个测试地点，那"泛化到新地点"这句话的证据强度就有限。换地点这件事，样本量比成功率的绝对值更重要。
  8. 4 小时 post-training 这个数字容易被误读。它是"8×H200、单节点、<4 小时"——按当前市价这一轮训练不是小钱。而且这 4 小时的前提是你已经有 16k 小时预训练出来的 backbone。拿这个数字去比"传统方法要调试两周"，是不对等的比较。

一句话收尾

这篇的真正贡献不在 78%，而在它把一句话变成了工程现实：想让机器人数据变多，别去造更多机器人，去让更多人愿意戴上夹爪干一件真事。为了兑现这句话，它必须在三个地方同时补洞——用锚定动作抹掉本体差异、用两级语言补回进度信息、用视觉预算扛住地点漂移。这三个补丁彼此不独立，是同一个约束（"只有人手和两个手腕相机"）在三个方向上的投影。至于 78% 里有多少是数据的功劳、有多少是设计的功劳——论文没拆，这也是它最该被追问的地方。但有一件事已经很清楚了：那条"数据翻倍降 2.4%"的曲线，说明这条路的天花板不在方法上，在"还能动员多少人去录数据"上。
