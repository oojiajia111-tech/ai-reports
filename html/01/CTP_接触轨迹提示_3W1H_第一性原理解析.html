💡 第一性原理核心立论

全文最值钱的是论文给出的那一句区分："执行时感受到力"与"从示范中知道该怎样用力"，作用不同。这句话把控制论里两个常被混为一谈的东西重新分开了——测量值（measurement）和设定值（setpoint）。力传感器只给前者：它告诉你此刻指尖压了多大，但绝不会告诉你"这次该轻擦还是重擦"。而现有 in-context 方法的参考示范只编码了位置轨迹，等于只给了路径的设定值，接触维度的设定值是空的。机器人于是陷入一个尴尬处境：它能感觉到自己用力过猛，却不知道自己本来就该用多轻。

CTP 做的事，就是把参考从"位置轨迹"扩成"位置＋接触的联合时序"。两个物理事实决定了这件事的难点：其一，力不能直接命令，它由动作和物体共同决定，所以力只能进条件空间、不能进动作空间；其二，接触的时间常数远短于轨迹，均匀抽帧会把"轻碰一下"直接漏掉，所以采样必须按力变化走。理解了这两条，就能理解它为什么要用非均匀抽样的时序编码器——那是个被物理约束逼出来的设计，并非调参调出来的。

What是什么：一次示范 = 一条带接触的时间序列

CTP 属于 in-context robot learning（ICRL）：策略训练完成后参数冻结，测试时读一条新的参考示范就能执行，不必为这条示范再训练。它要改的是参考的内容——从图像／机器人状态／动作轨迹，扩到包含接触记录。

一条 CTP 参考包含三路同步信号：

  • 机械臂末端位置；
  • 左右指尖的力与力矩；
  • 触觉形变。

关键在组织方式：它不是在轨迹后面附一串力值，而是保留"动作进展 ↔ 双指接触变化"的时序对应——接触何时开始、过程中怎么变、何时结束。这个对应关系才是被编码的东西。

编码：非均匀采样 + 时序编码器
一部分按时间均匀取样；另一部分专门挑力／力矩状态差异大的时刻。原因是短暂的接触变化会被均匀抽帧漏掉——轻碰一下可能在两帧之间就完成了。训练时编码器还通过重建运动与接触记录来学，逼它保留两者随时间变化的关系。
执行：参考只编码一次，参数全程冻结
策略同时读当前图像、机器人状态、双指力触觉，从 prompt 里提取与当前交互阶段相关的内容，生成下一段动作。参考编码一次后不再变，机器人边执行边更新观测。这样参考里的接触要求能用到新场景，又不会退化成对旧轨迹的机械回放。

实验覆盖三类任务，每类三个未参与策略训练的测试物体：

任务成功判据
擦拭覆盖目标区域，并维持工具与表面的接触
旋转按参考指定的方向转到目标角度
插入完成接触、对齐，并达到目标深度

评测协议：每个测试物体用 4 条参考，每条参考执行 3 次，单次执行只输入其中一条参考。注意论文特意澄清了 one-shot 的含义——"用一条目标物体的示范指导一次执行"，不是未经训练就学会全新任务类别。

Why为什么必须补接触：位置参考丢掉了什么

反例比定义更清楚

文章开头那个例子是整篇的缩影：用板擦沿花瓶表面走同一条路线，轻擦和重擦的动作看起来可能差不多，指尖受力却明显不同。也就是说，两条示范在位置空间里几乎重合，在接触空间里截然不同。

如果参考只编码位置，这两条示范在策略眼里就是同一个输入。模型不可能输出两种行为——不是它学不会，是信息在传入之前就已经被丢掉了。

为什么"装了力传感器"救不了这个问题

力传感器的实时读数只反映当前接触。
它回答"我现在压了多少"，不回答"我这次该压多少"。

这是闭环控制里最基础的区分，但在具身策略学习里经常被模糊掉。用控制论的语言写出来就很清楚：

两个不同的量
\[ \text{误差} \;=\; r(t) - y(t) \]
\(y(t)\) 是测量值，来自力传感器，实时可得；\(r(t)\) 是设定值，必须由任务意图给出。只有在 \(r(t)\) 已知的前提下，误差才有意义。现有 ICRL 从示范里提取的是位置设定值 \(r_{\text{pos}}(t)\)，接触设定值 \(r_{\text{force}}(t)\) 从来没有被提取过。加力传感器相当于把 \(y\) 变准了，但 \(r\) 仍然是空的——误差因此无从计算。

为什么力不能直接写进动作空间

一个容易想到的偷懒方案是把"目标力"当成动作的一部分直接回归。这在物理上不成立：

  • 指尖感受到的力是动作 × 物体接触刚度 × 几何的联合结果，不是独立可命令的量；
  • 同样的动作在不同物体上产生完全不同的力——换一个花瓶，同一段轨迹的接触力可能差几倍。

所以力只能作为条件（condition）进入，由策略去间接实现。CTP 把这一点做对了：参考提供接触意向，策略自己负责在具体物体上把它变成动作。这也解释了为什么参考必须参数冻结、编码一次——如果允许为每条参考微调，模型就会去记住"这个物体对应这串力值"，而不是学"接触意向怎么转成动作"。

为什么采样必须非均匀

接触事件的时间尺度天生不均衡：整条轨迹可能持续几秒，但"接触建立"和"接触解除"这两个关键转折只占几十毫秒。均匀抽帧时，这两个时刻有很大概率落在采样点之间，而它们恰恰是整条参考里信息量最大的地方。

按力／力矩差异选点，本质是在做一次信息驱动的重采样：把采样预算从"时间均匀"挪到"状态变化剧烈处"。这不是工程技巧，是对接触信号统计特性的直接响应。

How怎么做：从记录到 prompt 到动作

第一步：把示范变成有序的 contact prompt

均匀采样点 + 力变化剧烈点 → 时间对齐 → 时序编码器压缩成一组有顺序的 token。训练目标里包含重建运动与接触记录这一项，作用是防止编码器把时序结构压丢——如果重建得回来，说明时序关系还在。

第二步：按当前阶段读参考

执行时用 cross-attention 从 prompt 里取"与当前交互阶段有关"的内容。这个设计很关键，论文用消融给了代价：把它换成平均池化，高度扰动下成功率从 94.4% 掉到 38.9%。平均池化把整条参考抹成一个向量，等于告诉策略"这条参考整体上大概这么用力"——阶段信息全没了，遇到"接触时机变了"的情况就无从判断。

第三步：靠在线接触观测处理现场偏差

参考能指定"该多大力"，但机器人还得判断"眼前碰到了没有"。论文把物体高度上移或下移 2 cm，直接改变接触时机，结果对照极其锋利：

配置成功率
CTP（参考 + 在线接触观测）95.8%
去掉在线接触观测20.8%

失败案例的共同点是"没能接触到表面"——位置参考本身没错，但物体不在原位了，而机器人不知道自己还没碰上。这一组说明参考与反馈不可互相替代，必须两条腿都站。

对比结果说明了什么

擦拭力度（行为条件）轻擦 91.7% / 重擦 83.3%（BPP：75.0% / 58.3%）换参考，行为跟着换；力度维度的优势最明显

最后一行是全文最有信息量的实验：把力信号硬拼进输入，只能拿到 52.8%；同一批数据换成会重建的时序编码器，跳到 94.4%。模态的加入方式，比模态本身更重要。

Worth价值与局限：哪几个结论硬，哪几个还软

硬的部分：机制性对照

95.8% vs 20.8%、94.4% vs 38.9% 这两组，样本量不大但差距悬殊到不可能由噪声解释。它们回答的是"接触参考有没有用""时序结构要不要保留"，这两问的答案很扎实。

还有一个容易被忽略的漂亮结果：训练示范只有轻擦和重擦，没有中等力度那一档；测试时插入"中等力度"的参考，模型在未见物体上仍执行出轻—中—重的正确顺序。这说明它学到的是连续的力度条件映射，不是两个离散档位的记忆。文章自己也做了限定——"中等力度实验说明模型能响应测试时才引入的参考档位，不等于能精确跟踪任意力曲线"，这个边界划得很诚实。

软的部分：主结果的显著性

  1. 13 个百分点的领先，在统计上站不稳。108 次执行（9 物体 × 4 参考 × 3 次）下，78.7% 的 Wilson 95% 区间约 [70%, 85%]，65.7% 约 [56%, 74%]。两区间重叠，所以"CTP 显著优于 BPP"这个说法不成立；能说的是"方向一致，8/9 个实例占优"。真正显著的只有上面那两组机制性消融。
  2. 四个基线里有两个偏弱。BPP 是公平对手——同样冻结参数、同样有力触觉输入。但 DP-FT 与 π0.5-FT 走的是用单条参考微调的路线，一条示范的微调本来就吃亏。40.7% 和 37.0% 更像是"这条路线不适合 one-shot"，而不是"CTP 比它们强 40 点"。
  3. 插入任务露出了短板。有一个实例 CTP 只有 33.3%，低于 BPP 的 41.7%。这很合理：插入的核心是几何精度（对齐到毫米级），接触参考补的是"该多用力"，补不了"位置偏了 2 mm"。这条负例的信息量比多数正例都大——它标出了方法的适用边界：力参考替代不了位姿精度。
  4. 测的不是法向接触力。文章明确说明图中画的是"减去握持基线后、单侧指尖三维力的大小，并非工具与物体之间的法向力"。这意味着换一个握持姿态、换一个工具，这个量就会漂移。作为"接触意向"的代理它够用，但作为可迁移的物理量它不干净。
  5. 规模仍是九个物体、三类任务。而且验证范围被限定在"已训练任务类别中的未见物体"。文章结尾自己承认"更复杂的物体几何及新的任务类别，还需要进一步检验"。这条限制很硬：它是物体级泛化，不是任务级泛化。
读这篇最该带走的一句：给机器人装力传感器，只是让它"知道自己现在多用力"；要让它"知道该多用力"，必须从示范里把接触的设定值提取出来并且按时序编码。这两件事之间隔着一整套表征设计——直接拼接原始信号只能到 52.8%，做成会重建的时序 prompt 才到 94.4%。在接触操作里，数据的组织方式比数据的模态更能决定上限。
