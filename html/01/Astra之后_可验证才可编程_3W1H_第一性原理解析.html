Astra之后,机器人还需要多少示范决定一个任务该写代码还是该学策略的，不是它难不难，而是它成功能不能被一个传感器判定 · 同一个 GPT-6，只把外壳从「直接控制夹爪」换成「写代码」，平均成功率从 22.48% 跳到 51.6% · 同一个机械臂，只加一个腕部力传感器并允许它失败后改代码，开抽屉从 10 次成 4 次变成 10 次全成 · Moravec 悖论在叠衣服上依然成立，在所有「传感器能验收」的任务上，今年秋天已经破了

第一性原理核心立论

机器人能力真正的分界线，不是「大脑 vs 双手」，也不是「简单任务 vs 复杂任务」，而是——这个任务的成功，能不能被一个传感器读到。

能读到的任务，本质上是一句可以被编译的承诺：agent 写代码，传感器当 test suite，失败了就改，收敛是必然的。所以大脑可以租（GPT-6 Astra），手也可以换（π0.5 换 InternW0-Δ，成功率 53.0% → 56.0%）。读不到的任务（叠衣服），没有任何信号能告诉程序"你错了"，只能拿人类示范当判据——这类任务才真的需要 learned policy。

作者把这件事压缩成一句话，也是全文最该被记住的一句：大脑和双手之间如果通过文字或代码通信，换大脑不用重训手；如果通过 embedding 通信，每次换大脑都要重训手。前者是契约，后者是共生。这句话比"GPT-6 能开抽屉"重要得多，因为它把"机器人该怎么搭"从品味问题变成了接口经济学。

到底发生了什么 公理链：可验证才可编程 接口经济学 值不值：它证到了什么

是什么先看四组数字，它们拼出同一件事

这篇文章不是一篇论文，是一篇观点长文（作者自己也在括号里注了「当然，这些数据是自报的」）。但它串起来的四组实验结果，确实指向同一个结论。我按"证据强度"从弱到强排：

① 一个通用的 chatbot 模型，没做过任何机器人微调，排到了第一

OpenAI 9 月 3 日发布 GPT-6 Astra，定位是 computer use 和 coding 的前沿模型。RoboDojo 把它塞进 42 个仿真任务里，不做任何 robot-specific 或 task-specific fine-tuning，只给它一个动作——移动夹爪，平均成功率 22.48%，超过了全部 40 个训练过的 robot policy。作为对照，同样只用这一个动作的 GPT-5.5 只有 0.88%。

这里有个容易被忽略的细节：仿真器在它思考时暂停。所以「76 秒的运动」对应「平均 55 分钟的计算」——43 倍于实时。这个数字后面我要拿回来用。

② 同一个模型，只换「外壳」，分数翻倍

几天之内，训练过的模型重新超过了它。然后 PyRUA-Lean 做了一件很朴素的事：不让 Astra 直接输出夹爪动作，而是让它生成代码。这个外壳既没有 recipes（任务描述提示），也没有 learned policy，平均成功率 51.6%，比当时排行榜第一名高 19 个百分点。同一个模型，只改外壳 + 提高 reasoning effort，性能提升一倍以上。

这是全文最硬的一个对照。模型权重完全没变，数据完全没变，变的只是「输出什么」。直接输出 8 维连续动作 → 22.48%；输出一段能操作夹爪的程序 → 51.6%。差的那 29 个百分点，不在模型的脑力里，在接口里。

③ 加一个 200 块钱的力传感器，10 次成 4 次变成 10 次全成

伊利诺伊大学 10 月的实验：摄像头对着一个透明抽屉，让一个 coding agent 写代码控制机械臂去开它，10 次成功 4 次。然后他们把腕部力传感器的数据也喂给它，让它在每次失败后迭代并修改 Python 程序——10 次全部成功。接着把 coding agent 拿掉，它写出来的程序自己还能开抽屉。

同样的结构出现在削黄瓜上：agent 用代码读腕部力传感器，100 Hz，把力度控制在 4.5~7.5 N，刀片一失去接触就停。相比只用摄像头的 agent，失去接触的比例从 40.6% 降到 2.2%——差 18 倍。

④ 一个上午，写出 1500 行，把一个工位级的活干掉

RAX 在 Franka 机械臂 + 空气炸锅上：72 分钟 inference 学会开、装、关，然后写出约 1500 行 Python。这段程序跑一次三分钟的活只要 18 秒计算。它跑了 9 次、改了 9 次，按它自己的度量，9 次里 4 次干净。全过程在某个上午 09:18 到 12:05 之间完成。

任务用什么当"错了"的信号学会了什么代价
开透明抽屉腕部力传感器（接触是否建立）一段能自跑的 Python10 次试错，一个上午
削黄瓜腕部力，100 Hz，4.5–7.5 N 区间接触保持策略失去接触 2.2%（视觉版 40.6%）
开-装-关空气炸锅程序内的 software check + 人工看结果1500 行代码72 分钟 inference，9 次迭代
叠衣服没有——布料的"叠好了"无法用单个传感器判定只能学 policy数千小时遥操作

而作为对照，2022 年的 SayCan 已经把这件事的另一半做完了：planner 能为全部 21 个涉及抽屉的用户请求规划出动作序列，但它的 visuomotor policy 只能执行其中约三分之一——尽管那个策略用了 68,000 条人类示范训练。规划早就会了，手不会。四年之后，手的问题被"写代码 + 传感器"绕过去了。

为什么公理链：为什么"可验证"就等于"可编程"

这篇文章没有公式，但它背后有一条很干净的逻辑链。我把它抽出来，因为这条链决定了你下次遇到一个新任务时，该选"教它"还是"让它写"。

公理 1　程序不是"聪明的行为"，是"一句可被检查的承诺"
写代码之所以能收敛，不是因为模型会写代码，而是因为写完之后有东西能判它对不对。没有判据，代码写得再漂亮也只是猜测。

所以"这个任务能不能交给 agent"这个问题，等价于"存不存在一个信号，能在每次试错后立刻告诉它错了"。这就是整篇文章所有实验的共用结构——UIUC 的力传感器、RAX 的 software check、PyRUA-Lean 的仿真器返回码，全都是同一件东西：一个 test suite。

式 1　可编程性的判据（本文的形式化，原文未写成公式）
\[ T\ \text{可交给 agent}\ \iff\ \exists\, v:\ \mathrm{corr}\big(v(\tau),\,\mathrm{succ}(\tau)\big)\ \text{足够高},\ \ \text{且}\ v\ \text{每次试错都可观测} \]
\(v(\tau)\) 是一次 rollout 上能读到的某个信号（力、位置、返回码），\(\mathrm{succ}(\tau)\) 是"人认为这次成功了吗"。
说人话：你需要一个"替人打分的东西"。它不用完美，只要和真实成功强相关、而且每次都能读到。
两个条件缺一不可：相关性不够 → agent 会朝着错误目标优化（reward hacking）；不可观测 → 它连自己错了都不知道，迭代无从谈起。叠衣服两个都不满足——"叠得整齐"没有传感器能读，人自己都得看一眼才知道。
公理 2　有判据 → 迭代必然收敛；没判据 → 只能用示范冒充判据
监督学习做的事，本质上是把"人类示范"当成一个间接的判据：跟人像 = 对。这是一种在没有 ground truth 时的替代品，代价是它永远不知道"像"和"成"之间的差别。

这一步解释了为什么 68,000 条示范只换来三分之一的执行率。示范教的是"人怎么做"，不是"什么算做成了"。而一个力传感器教的是"什么算做成了"，至于怎么做，让 agent 自己搜。前者是模仿，后者是搜索——搜索需要的样本量比模仿低一个数量级，前提是你能判分。

这就是那 29 个百分点的来源。22.48% 的 Astra 是在"没有判据、只能靠感觉输出动作"；51.6% 的 PyRUA-Lean 是在"有仿真器的返回码当判据、可以反复改"。同一个大脑，前者在猜，后者在解方程。
公理 3　可验证是"窄切片"，不是"任务属性"
一个任务往往有几十种失败方式，而你的传感器只测其中一两种。被判据覆盖的那一维，agent 能收敛；覆盖不到的，它照错不误。

这条公理是文章里唯一的"事故报告"，也是我认为最该被反复引用的一段：空气炸锅程序第一次跑的时候，一个不自然的机械臂姿态把摄像头撞了。RAX 里面有若干 software check，但没有任何一项检查能保护摄像头。

同一件事在削黄瓜上换了个形式：4.5~7.5 N 这个阈值是人写的。所以 agent 的闭环是"按人给的规格试错"，不是"自己发现什么叫切得好"。"无需示范"是真的，"无需人类知识"是假的——知识从"轨迹"搬到了"规格"（设定值、阈值、停止条件）。

公理 4　接口决定可替换性：契约 vs 共生
两个模块之间的接口如果是离散、有独立语义的（文字、代码、坐标），任何一方都能换；如果是连续、无语义的（embedding），只有训练它的那个网络能解，换一方就得重训另一方。
公理 5　所以产业价值会按"可验证性"劈成两半
可验证的任务，卖的是"程序生成能力 + 便宜的传感器"；不可验证的任务，卖的是"数据 + 示范"。这两条生意的最优规模、护城河、毛利结构完全不同。

作者对 VC 的那句建议就是这条公理的直接推论：「弄清楚客户付费的工作里，有多少比例可以由传感器验证，又有多少确实需要 learned model 来判断。」这句话比"机器人会不会取代人"有用一万倍——它是一个可以拿去做尽调的问卷题。

怎么做接口经济学：为什么"用代码通信"值钱

公理 4 看起来像一句工程品味，实际上可以算账。我把两条路线的成本摊到部署台数上：

式 2　两条路线，摊到每台机器人头上的固定成本
\[ \underbrace{\frac{k\cdot c_{\text{trial}}+c_{\text{eng}}}{N_{\text{deploy}}}}_{\text{写代码路线}} \qquad\text{vs}\qquad \underbrace{\frac{m\cdot c_{\text{demo}}+c_{\text{train}}}{N_{\text{deploy}}}}_{\text{采示范路线}} \]
\(k\) = 试错轮数（RAX 是 9 轮），\(c_{\text{trial}}\) = 一轮试错的成本（时间 + 撞坏的东西），\(c_{\text{eng}}\) = 写程序/改程序的成本；\(m\) = 示范条数（SayCan 是 68,000），\(c_{\text{demo}}\) = 采一条示范的成本，\(c_{\text{train}}\) = 训练成本。
说人话：左边是"试到能跑"的一次性编程费，右边是"采数据 + 训模型"的一次性数据费，两边都除以部署台数 \(N_{\text{deploy}}\)。
关键在 \(N_{\text{deploy}}\)：台数越大、任务越固定，左边的试错成本被摊得越薄，代码路线越赢——这也正是工业机器人过去四十年的做法（编程一次，跑 12~15 年）。反过来，如果任务是每台机器人、每个家庭都不一样的（叠衣服、收拾房间），那就没有"摊薄"这回事，右边的数据路线才成立。

把这个不等式代进文章里的数字，结论非常扎眼：RAX 一个上午（72 分钟 inference + 9 次试错）换掉的是"三名工程师迭代 547 个版本"。而另一边，Encord 卖给机器人公司的训练数据，客户需求从一年前的 1,000 小时涨到现在的 10,000 甚至 100,000 小时，需求是去年的 10 倍；Tesla 和 1X 招数据采集员起薪 25 美元/小时。

作者的结论因此很直接：「不要再收集一千条示范，先在腕部装一个力传感器。」因为一旦有判据，你的竞争对手就变成了"一个上午写出空气炸锅代码、主要成本只是 token"的 agent。

但"主要成本只是 token"这句话，被它自己的数据打脸了

前面那个数字现在拿回来：76 秒的运动，对应平均 55 分钟的计算。这意味着如果真按实时闭环跑，算力成本是 43 倍于机器人本身的时间。所以"token 便宜"这个说法只在一种情况下成立——你算的是一次性编程费，不是运行费。

这是一个必须分清的口径。RAX 的模式是"72 分钟学一次，之后 18 秒跑一次"，摊到 12~15 年的部署寿命上，那 72 分钟约等于免费。但它同时意味着：这个方案不适合"每个场景都要重新想一遍"的任务。一旦任务每天都在变，那 43 倍的计算就成了常态成本，而不是一次性投入。
作者用"token 便宜"去对比"25 美元/小时的采集员"，其实是在拿一次性投入比经常性支出。账没错，但对象错位了。

接口那一侧的实证：手确实也能换，但换了不等于更好

文章给了一个我之前没见过的对照：在 EBench 上，让 Astra 把一部分步骤外包给 π0.5，成功率从 46.7% 提升到 53.0%，超过任何一个单独组件。然后把 π0.5 换成竞争对手的 InternW0-Δ，同一个大脑拿到 56.0%。

配置EBench 成功率读法
Astra 单独46.7%大脑很强，但不会动
Astra + π0.553.0%接了手，涨 6.3 个点
Astra + InternW0-Δ56.0%换个手，再涨 3 个点 → 手是可替换的
EBench 最佳 trained policy61.4%专用 VLA 仍然最高

这张表最值得注意的不是 56.0%，是最后一行。"手可替换"被证明了，"组合更优"没有被证明。混合方案在被专门为 VLA 设计的榜上，还差 5.4 个百分点。所以正确的读法是：接口解耦降低了对某一方的锁定，但没有立刻提高上限。这两件事经常被混着说。

值不值它证到了什么、没证到什么

先给价值：三条能直接拿去用

  1. 把"该教还是该写"变成一个可以问的问题。不要问"这个任务难不难"，问"成功能不能被一个 200 块的传感器读到"。答"能"，就上 agent + 代码；答"不能"，才轮到示范和策略。
  2. 接口选择优先于模型选择。大脑和手之间用代码/文字通信，你以后可以每年换一次大脑；用 embedding 通信，你换一次大脑就得重训一次手。这个决定在架构图上只有一条线，但它决定了你未来三年的迭代速度。
  3. 传感器的 ROI 高于示范的 ROI。2.2% vs 40.6% 这个对比（差 18 倍）不是算法改进换来的，是一个力传感器换来的。在预算有限时，先买传感器，再买数据。

再说局限：八条，按严重程度排

下面这些不是挑刺，是决定这套结论能不能搬到你场景里的前提。

  1. 两个头条数字互相矛盾。文章说 22.48% 的 Astra「超过了全部 40 个经过训练的 robot policy」；又说 PyRUA-Lean 的 51.6%「比当时排行榜第一名高出 19 个百分点」。后者反推出当时第一名约 32.6%——比 22.48% 高 9 个点。
    两句话不可能同时为真。要么"全部 40 个"指的是另一批模型/另一个时间点的快照，要么 22.48% 只是"超过多数"。这是全文的立论支点，却内部不自洽，而且是自报数据（作者自己在括号里承认了）。
  2. 「移除了 coding agent，程序仍然能开抽屉」这句被轻轻带过了，但它是全文最重要的一句。因为它说明产出的不是 policy，是工件（artifact）。工件是 per-task、per-scene、per-object 的——这和工业机器人编程同构，不是范式变化。
    真正的创新是编程成本从"工程师几周"降到"一个上午"，这已经足够颠覆（对照他们第一台机器人：三名工程师迭代到第 547 版）。但作者把它写成了"机器人不需要示范了"，这是把成本革命说成了范式革命。
  3. 验证器只覆盖它测量的那一维，而事故恰好发生在覆盖之外。空气炸锅程序撞坏了摄像头——RAX 有 software check，但没有一项保护摄像头。同理，力传感器能判"失去接触"，判不了"撞到旁边的杯子""线缆被勾住""物体被压坏"。
    所以"可验证"是一个窄切片，切片外的长尾正是 learned policy 唯一的存在理由。文章承认叠衣服不行，但没给出"哪些任务在边界上"的判据——而事前判断边界，恰恰是工程上最难的一步。
  4. 4.5~7.5 N 这个阈值是人给的，"无需示范"为真，"无需人类知识"为假。agent 的闭环是「测试 → 失败 → 改代码」，而 test oracle 是人写的规格。人的知识没有消失，只是从"轨迹"迁移到了"设定值 + 阈值 + 停止条件"。
    作者自己写了「这段代码我自己也能写出来」——这句话恰恰在证明：难点从来不是写代码，是知道该写什么规格。而规格的产能，仍然由人决定。
  5. 9 次里 4 次干净（44%），远谈不上可靠。这是 RAX 自己的度量，比它批评的 22.48% 好，但离"能交付"很远。真正的可靠性来自部署期工程——他们第一台机器人迭代了 547 版才能每月服务数千份餐食。
    换句话说：agent 把"从 0 到能跑"从几个月压到一个上午，但"从能跑到稳定"这一段，它几乎没帮上忙。文章没有区分这两段，而产业价值大部分在第二段。
  6. 任务全是"环境主动给你干净信号"的那一类。透明抽屉（视觉可以透视）、固定工位的空气炸锅（行程可复现）、削黄瓜（接触信号干净）。换成一个不透明的抽屉、手柄在视线外、需要靠触觉定位，这套流程会立刻退化。
    所以这篇文章证明的是"在信号干净的任务上，代码路线赢了"，而不是"代码路线赢了"。这个限定词被摘要吃掉了。
  7. 「手也可替换」是方向性证据，不是等价性证据。46.7 → 53.0 → 56.0，只换了一次手、一组数字、没有误差棒，而且两个混合体都低于 trained policy 的 61.4%。
    更关键的是：π0.5 之所以能被换掉，是因为它和大脑之间是分步/文本级的接口。如果手是一个和大脑联合训练的端到端模块，换手就没这么便宜了。这里"可替换"是接口带来的，不是市场带来的。
  8. 估值论证会自我拆台。作者用"手也可替换"去压 Physical Intelligence 的 200 亿美元估值，逻辑是"你既没有大脑，手也不是唯一"。但反过来问一句：为什么 π0.5 的手比别的型号好？因为它的数据好。那数据就是护城河，而数据正是 PI 的资产。
    作者真正的论点其实是"可验证任务的市场比不可验证任务大得多"，这个论点成立；但把它推成"PI 被高估"，靠的是"手可替换"这一条，而这一条恰好能被"手好的原因是数据好"反杀。结论可能对，论证路径不成立。
最后一条我认为最值得记住。文章说 Moravec 悖论"对于传感器能够检查的任务，今年秋天已经被攻克"。这句话在逻辑上是对的，但它悄悄地换掉了 Moravec 悖论的前提——Moravec 说的是"感知和行动"难，而"感知和行动"里最难的那部分，恰恰是没有明确判据的部分（接住一个球、叠一件衣服、在人群里穿行）。
被攻克的不是 Moravec 悖论，是被 Moravec 悖论遮蔽的那一半——所有"其实有判据、只是以前没人去装传感器"的任务。这一半有多大？作者没有回答。而这才是"机器人还需要多少示范"这个标题真正的答案：取决于有多少任务，其实一直藏着判据。

一句话总账

这篇文章最大的贡献不是"GPT-6 能开抽屉"，而是把"什么时候该学、什么时候该写"从一个信仰问题降级成了一个测量问题：去找那个能判分的信号，如果有，写代码；如果没有，去采数据。

它最该被质疑的也不是数据，是它把成本革命讲成了范式革命。写代码路线真正的杀伤力在于：它把每个工位的编程成本从"几周工程师"压到"一个上午"，这在工业场景里已经是天文数字的改善——不需要"机器人不需要示范"这种更大的话，就足够改变行业结构了。
