💡 第一性原理核心立论

数十亿参数的 VLA 里，真正需要从头学的部分小得出奇：视觉语义不必自己学——那是预训练大模型已经解决的事，蒸馏进来即可；动作生成本身只需要一个几百万参数的小头。把"知识"与"技能"分开对待，π0.5 就能缩到 10.5M 参数、在笔记本 GPU 上 25 分钟训完，LIBERO 拿到九成成功率。文中另一个反直觉发现同样重要：验证损失翻倍而机器人成功率几乎不降——动作模仿得像不像，不是任务完成与否的好代理。算力从来不是 VLA 的第一性约束，把每个字节和每毫秒花在哪里的清点才是。

What是什么：一台笔记本 GPU 上的完整 VLA 实验

先说清楚它要解决的那个具体的麻烦。现在的 VLA 模型——π0、π0.5 这一类——参数量都是数十亿级别，训练要大算力，推理连移动芯片都装不下。想亲手做实验、做消融、学推理优化的人，被算力挡在门外。这篇开发日志的做法和 nanogpt 一脉相承：不是"用小算力训小模型凑合"，而是把一个大模型的每个部件按"谁在贡献能力"逐个清点、逐个缩小，直到塞进一台笔记本。

具体做法是把 π0.5 缩到约 10.5M 参数。VLA 的输入是相机图像、语言指令和机器人状态，输出是控制机械臂的动作块；动作由 Flow Matching 生成——一个小得多的 Action Expert，看着前缀信息（图像 patch + 指令 + 状态）预测动作。

部件规模职责能力来源
视觉 Transformer4 层 · 1.9M把图像变成 patch 特征从 SigLIP 蒸馏（不从头学）
前缀 Transformer6 层 · 5.7M融合图像 + 指令 + 状态随动作训练
Action Expert6 层 · 2.3M预测动作方向（Flow Matching）随动作训练

整个项目分两半：前半段把训练跑通——玩具世界做合理性检查、发现并修复视觉瓶颈、上 LIBERO-Spatial 拿到 75/100，再经消融和改进把保留布局上的成绩推到 90%；后半段把推理瘦身——在 4GB 显存上跑真正的 3B 参数 π0.5，把单次推理从 1147 毫秒压到 662 毫秒，并逐 episode 验证"变快没有变笨"。

一句话概括这篇讲的事：VLA 的能力不是均匀长在参数量里的。视觉语义是"知识"，可以继承；动作生成是"技能"，必须自己练但规模很小。分清这两样，VLA 的门槛就从"一个集群"降到"一台笔记本"。

Why为什么：三个被实验逼出来的关键认识

这篇的价值不在最终数字，而在它用一组干净的对照实验，把三个通常被混在一起的问题拆开了。

认识一：动作损失教不会视觉——它是视觉的弱信号

第一版从零训练 ViT，损失正常下降，机械臂却什么都不会做。作者没有急着调参，而是做了一个对照：不给图像，把方块和盒子的真实位置直接作为 token 输入——其余架构完全不变。这个版本方向余弦相似度 0.86、夹爪开合正确率 93%，还能响应指令。结论被钉死了：瓶颈在视觉，不在动作链路。

原因想一层就明白：动作损失只告诉模型"你动得有点偏"，靠这一个间接信号，一个 1.9M 的小 ViT 要同时学会什么是方块、方块在哪、颜色怎么区分——这是弱信号学强语义，学不动。真正的 π0.5 也不是从机器人数据里学视觉的，它从预训练的 SigLIP 开始。视觉语义这件事，在预训练时代就已经被解决了，任何 VLA 都不该重做一遍。

认识二：验证损失与任务成功是两个指标

第二轮训练出现教科书式过拟合：验证损失从 0.135 升到 0.264，几乎翻倍。作者本以为后期 checkpoint 表现会崩，实测却几乎不掉。解释是：完成任务只需要一个足够好的动作，因为下一个动作块无论如何都会修正。验证损失衡量的是"动作与人类示范有多接近"，而这件事对任务成功没有那么重要。

这是一个必须记住的指标错位：模仿贴合度（回归损失）与任务成功率（闭环结果）在机器人学习里是两个不同的量。用前者监控训练，你会在它翻倍时错误地停手；用它选模型，你选中的可能不是最会干活的那个。

认识三：高成功率里可能藏着捷径

75% 的成绩不代表模型学会了任务——它可能只是学会了"从相同的起始位置执行相同的动作"。作者的对策有两层：每次移除一种输入再测，确认模型真的在使用每种输入；把每个 LIBERO 任务的 50 种初始布局分成 0–19（做决策用）和 20–49（藏到最后做终测），防止改进过程对评估集过拟合。最终 90% 的成绩是在从未参与过任何决策的布局上测出来的——这个数字才站得住。

How怎么拆：从零到 90% 的五步实验链

每一步都先建立一个可检验的小结论，再进入下一步。

第 1 步：缩架构——先回答"每部分多大才够"
把 π0.5 缩成 4 层 ViT（1.9M）+ 6 层前缀 Transformer（5.7M）+ 6 层 Action Expert（2.3M），合计 10.5M。缩比例的依据不是拍脑袋，而是后文的实验逐个验证：视觉走蒸馏路线，所以 1.9M 够；动作头在玩具世界和 LIBERO 上都被证明够用。
第 2 步：玩具世界做合理性检查——用最小问题验证配置
直接上 LIBERO 做检查太慢，先造一个 GPU 上的二维抓取放置环境（两个彩色方块、两个彩色盒子、"把红色方块放进蓝色盒子"）。损失下降但机械臂乱动 → 记录预测方向与专家方向的余弦相似度 → 发现视觉失灵 → 用"喂真实位置"的对照版本（0.86 / 93%）确认瓶颈。这一步的方法论价值不亚于结论：先隔离变量，再动手术。
第 3 步：蒸馏 SigLIP——把视觉"知识"灌进 1.9M 参数
两条路摆在一起：直接用 SigLIP（视觉部分膨胀到约 90M，违背初衷）或蒸馏。选蒸馏：动作训练开始之前，让小 ViT 的 patch 特征过线性层后，用余弦损失加 MSE 损失去匹配冻结 SigLIP 的 patch 特征；调整 SigLIP 输入尺寸让两者 patch 网格一致。只训 1,200 步就在从未见过的颜色组合上拿到 91.8%，还能遵循交换后的指令——说明模型在读指令而不是背动作。
第 4 步：上 LIBERO——先蒸馏后训练，再用消融和划分防自欺
LIBERO-Spatial：10 项任务、432 条人类示范、约 5.3 万帧、两个相机（场景 + 腕部），图像缩到 96 像素。先 SigLIP 蒸馏、再 8,000 步 Flow Matching，训练约 25 分钟，100 次 episode 成功 75 次，每个动作块推理 70 毫秒。之后是防捷径的输入消融、布局划分（0–19 决策 / 20–49 终测）、三轮改进（蒸馏 3,000 步、batch 32→64、EMA、颜色抖动；128 像素假设被数据否决——91 对 90 没有显著差异；Muon 优化器让拟合更猛、验证损失升得更快、机器人表现略升），终测 270/300 = 90%，对比第一版的 210/300。
第 5 步：推理瘦身——在 4GB 显存上跑 3B 的 π0.5
π0.5 约 3B 参数，bf16 下仅权重 6GB，笔记本只有 4GB。方案：视觉语言部分用 NF4 量化（4-bit，每块带缩放因子），Action Expert 保持 bf16（它小、且直接输出数值，精度要保）；在 PyTorch meta device 上只建形状再逐个填充张量，绕开"先在 CPU 建整个模型"的死路。拿到 1147 毫秒 / 3.22GB 后逐项清点：第三个相机槽是空白图却烧 256 个 token、最长指令只需 62 个 token 却填充到 200——前缀剪掉后 813 毫秒；性能分析发现前缀约 520 毫秒、每步 Flow Matching 只要 30 毫秒，步数 10→5 只省约 150 毫秒，最终 662 毫秒。最后在 LIBERO 仿真里逐 episode 对齐比较，确认变快没有变笨。

Formula核心公式：三个式子撑起整个项目

① Flow Matching：把"生成动作"化简成"指出方向"
\[ x_t = (1-t)\,\epsilon + t\,a, \qquad \dot x_t = a - \epsilon \ \ (\text{常数，与 } t \text{ 无关}) \]
\(a\) 是示范里的真实动作块，\(\epsilon\) 是同形状的随机噪声，\(x_t\) 是两者连线上 \(t\) 时刻的点。大白话：终点减去起点就是这条直线的方向，它在整条线上都不变——所以模型要学的只有一件事：站在直线上任意一点，指出终点在哪个方向。执行时从纯噪声出发，沿预测方向走几步就得到动作块。这就是那个 2.3M 的 Action Expert 全部的工作内容：不预测"动作是什么"，只预测"往哪边修"。
② SigLIP 蒸馏损失：把大模型的眼睛装进小脑袋
\[ \mathcal{L}_{\text{distill}} = \lambda_{\cos}\,\big[\,1-\cos\!\big(z,\ z^{\star}\big)\big] + \lambda_{\text{mse}}\,\big\lVert z - z^{\star}\big\rVert^{2} \]
\(z\) 是小 ViT 的 patch 特征（过线性层后），\(z^{\star}\) 是冻结 SigLIP 在同一图像上的 patch 特征。大白话：两项一起罚——方向要对齐（余弦），长度也要对齐（MSE）；再把 SigLIP 的输入尺寸调到 patch 网格一致，让小模型的每一个 patch 都拿到大模型对应位置看到的信息。要害是顺序：蒸馏在一切动作训练之前完成。视觉是先修课，动作是专业课——先让眼睛成熟，再教手。1,200 步就见效，因为这不是学视觉，是把已有的视觉"搬运"进来。
③ 推理时间预算：每一毫秒都要先问花在哪
\[ t_{\text{infer}} = t_{\text{prefix}} + k \cdot t_{\text{step}} \;\approx\; 520\,\text{ms} + k \times 30\,\text{ms} \]
\(t_{\text{prefix}}\) 是前缀（图像 + 指令 + 状态）的一次性编码耗时，\(k\) 是 Flow Matching 采样步数。大白话：前缀一项就占约 520 毫秒，每步采样只有约 30 毫秒——所以把步数从 10 减到 5 最多省 150 毫秒，而剪掉空白相机槽的 256 个 token 和无意义的 padding 却能省 334 毫秒。优化的正确顺序由这个式子决定：先看占比，再动手。同理显存侧：NF4 把视觉语言部分压到每参数半字节、Action Expert 保 bf16，配合 meta device 分块加载，3B 模型 3.22GB 就放下。凭直觉"减步数"是优化大忌，先测量再优化才是。
把三个式子连起来看：①定义了动作生成这项"技能"有多小（学一个方向）；②定义了视觉这项"知识"怎么便宜地获得（对齐特征而非重学）；③定义了推理优化的决策规则（按预算占比下手）。整个项目就是这三句话的工程化：把大模型拆开，分清哪些是知识、哪些是技能、哪些是浪费。

Worth价值与局限：它证明了什么，又没证明什么

三样真正值得带走的东西

第一，一条可复现的极简 VLA 路线。10.5M 参数、25 分钟训练、LIBERO 保留布局 90%、全部代码开源——它把"参与 VLA 研究"的硬件门槛从集群降到笔记本。对高校实验室和个人研究者，这是准入券。

第二，一套可以直接抄的实验方法论。玩具世界做合理性检查、"喂真实状态"的对照实验隔离瓶颈、蒸馏先于训练、输入消融防捷径、布局划分防评估过拟合、推理优化逐 episode 对齐验证——每一条都是花钱都难买到的坏教训的反面。

第三，两个反直觉的实测结论。验证损失翻倍而成功率不降（模仿贴合度不是任务指标）；128 像素对 96 像素几乎无差异（"更多像素帮抓取"的合理直觉被数据否决）。它们共同提醒：在机器人学习里，直觉必须被仿真验证之后才算数。

五处必须打折的地方

  1. 只在 LIBERO-Spatial 上验证。这个 benchmark 的结构是"物体固定、位置变化"，90% 的成绩不能外推到长程任务、多样物体、动态干扰。它证明了路线可行，没证明通用。
  2. 验证损失与成功率脱钩是双刃剑。它解放了"别被损失吓停"，但也意味着训练监控部分失灵——过拟合程度无法从损失曲线判断，只能频繁跑仿真评估，而这在大任务上并不便宜。
  3. 量化的语义损失没有被单独评估。NF4 只压视觉语言部分、Action Expert 保 bf16，但"量化后 VLM 语义退化了多少"没有独立的消融数字，只有逐 episode 的整体对比。
  4. Muon 等结论是单点观察。没有多种子方差、没有置信区间，"机器人表现略有提升"的幅度和稳定性都未知——作者自己也定位为"近期想做更多消融"。
  5. 推理耗时的测量场景与真实部署有差距。耗时在保存的图像帧上测得，仿真验证是"尽量对齐"作者设置；换到真机、更低算力的移动芯片上，各项占比会重新洗牌，③式需要重测。

一句话收尾

这篇最值得记住的不是 90% 或 662 毫秒，而是它示范的一种思考顺序：面对一个"太大、太贵、训不动"的系统，先别问"怎么压缩"，先问"哪些部分在贡献能力、哪些在重做别人已解决的事、哪些干脆是浪费"。视觉语义是别人已解决的事，蒸馏即可；动作生成贡献核心能力但规模很小；空白相机槽和 padding 是纯粹的浪费。把这个顺序用在任何算力受限的场景里，"小算力做不了大模型的事"这个断言就会开始松动。对做具身智能的人，还有一层：闭环里最后修正一切的是下一个动作块——你的评估指标，应该长成闭环的样子，而不是开环的样子。
