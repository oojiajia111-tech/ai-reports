一句话 进化的载体不是权重，是可读、可组合、可回滚的程序
💡 第一性原理核心立论

"机器人自我进化"这句话，行业里默认指的是改权重——在线 RL、微调、持续学习。这条路有三个绕不过去的老毛病：灾难性遗忘、需要海量在线数据、以及最致命的一条——你改完之后不知道它为什么变强了，也不知道它什么时候会突然变弱。ASENA 换了一个载体：权重全程冻结，进化发生在"程序 + 笔记"上。智能体读传感器数据、写代码、执行、看录制结果、修 bug，把成功路径存成可复用的技能和笔记。同一批反复出现的 100 个任务，跑十轮之后 R2R 从 72% 涨到 98%、RxR 从 65% 涨到 89%，而模型参数一个都没动。它证明的不是"智能体很强"，而是进化的速度取决于你的经验存成了什么形态：存成权重，就只能靠梯度一点点挪；存成程序，就能被检索、组合、审查和回滚。

What是什么：把人形机器人当成一台"可编程设备"

先说明来源：这篇公众号文章本身是 AI椰青 Robotion 社群的一场分享会预告（11 月 6 日 10:00 直播，分享人郑安杰，UCSD 在读博士，师从 Xiaolong Wang，曾实习于 NVIDIA Research 与 Adobe Research，代表作 SpatialRGPT、NaVILA、GR3D）。技术实质来自同一篇论文：ASENA: Self-evolving Agents for Embodied Navigation（arXiv 2609.39207，NVIDIA GEAR，2026-09-30 首版 / 10-12 修订）。

ASENA 的定位不是"一个更强的策略"，而是一个统一的机器人执行外壳（robot harness）。它给通用 coding agent 四件事：

能力干什么为什么关键
读传感器把相机、位姿、本体状态暴露成可读的数据让"程序"能看见世界，而不是只能调用预设接口
写并执行程序agent 现场产出代码，直接驱动导航、操作、交互行为不再受限于预先定义好的技能库
检查录制结果回看执行过程，判断成功还是失败、错在哪这是"能修"的前提——没有回看就没有归因
修失败 + 复用笔记与可执行技能把改好的程序和结论存进持久工作区下一次同类任务直接调用，不再重新摸索

在这之上还挂了一个可选工具：ASENA-VLN，一个 4B 参数的单目导航策略。它输出机体坐标系下的轨迹，同时覆盖"长路线"和"短时行为"两种尺度；共享的视觉语言解码器在三种数据上联合训练——路线指令、视觉问答，以及一个新构造的「几何推导出的原子导航任务」数据集。

单独的 ASENA-VLN 就已经很强：R2R 68.7%、RxR 70.2%，均为当前最好水平（SOTA）。但论文真正想说的不是这个数字，而是把它当工具塞进 coding agent 之后发生了什么——成功率在两个 agentic 基准上各提升 11 个百分点，同时执行时间下降。

真机演示在 Unitree G1 上做，任务包括搜索、视觉检查、空间推理、合成手势，以及不依赖预建地图的移动操作（取物 + 搬运 + 递交）。

Why为什么：四条公理，把"进化"从权重里挪出来

公理一：权重里的一次更新，是不可读、不可组合、不可审查的

先把"学习"这件事拆到底层。梯度下降做的事情是：在几十亿维的参数空间里挪一小步，让某类输入的输出更接近目标。这一小步没有语义。你没法问它"你学会了什么"，也没法把"学会开门"这段更新单独摘出来，复用到"开抽屉"上。

这就导致三个后果，全是老问题：

  • 遗忘：新任务的数据会把旧任务的解压掉，因为参数是共享的；
  • 不可审查：出了问题，你拿不到"它当时是怎么想的"；
  • 不可组合：学会了 A 和 B，不等于会 A+B，因为两者的更新在参数里纠缠。
推论 1
如果"进化"的目标只是「下次遇到同类任务做得更好」，那它并不要求改权重。它只要求：这次的解法被以可复用的形态存下来。改权重只是实现这件事的一种手段，而且是最难控制的那种。

公理二：程序是"人类可读的中间表征"，所以能被复用、组合、回滚

这就是 ASENA 的全部赌注：把经验存成代码和笔记，而不是存成参数扰动。

代价和收益都很清楚：

维度存成权重存成程序/笔记（ASENA）
可读性无完全可读——就是几行 Python
可组合纠缠，难拆函数调用，天然可拼
可回滚要存 checkpoint删掉那个文件就行
可迁移到新本体要重训改接口适配层即可
泛化能力强——能隐式抓住没见过的相似情形弱——只覆盖被写下来的情形

最后一行是关键，也是这条路线真正的天花板：程序不会泛化，只会积累。它靠"见得够多"来覆盖，不靠"举一反三"。

推论 2
所以这条路线的性能曲线必然是「在重复出现的任务上快速爬升，在全新任务上原地不动」。后面第四节会用这条推论去审它的实验设计——因为论文的评测恰好就是"十轮跑同一批 100 个任务"。

公理三：能修，必须先能看；能看，必须先有录制

ASENA 的循环里，"检查录制结果（inspect recorded outcomes）"这一步被放在执行之后、修复之前。这个顺序不能颠倒，理由很硬：失败归因需要证据，而证据只能来自过程记录。

如果只给 agent 一个"失败"的布尔信号，它只能瞎猜——换个方向再来一次。给了完整录制，它才能定位到"是在第二步转弯角度不够，撞到门框了"。这两者的修复效率差一个量级。

这一点和同期另一条技术线正好对上：机器人记忆系统正在解决的，就是"如何低成本取回任务执行时的那 8 秒画面"。会写代码的 agent + 能回看的记忆，是同一个闭环的两半。

公理四：进化的产出必须能"叠"，否则每次都要从零开始

论文里最硬的一组数字，是"持久工作区演化"（persistent workspace evolution）：让系统反复经过同一批 100 个任务的子集，共十轮，每轮用仿真反馈改工作区。

基准第 1 轮第 10 轮净增
R2R72%98%+26 pp
RxR65%89%+24 pp

十轮、26 个百分点，权重没动。这条曲线说明工作区里的东西是可累积的：第二轮不用重学第一轮的结论，直接站在上面。如果经验存成权重，这条曲线会更平——因为每一轮的新数据都会冲淡上一轮的更新。

推论 3
"可累积"比"学得快"重要得多。一个每轮涨 2.6pp 且不衰减的系统，十轮就翻倍；一个每轮涨 5pp 但会遗忘的系统，可能三轮后就原地打转。持续学习的真正指标不是单轮增益，是曲线有没有平台期。
公理链收口：权重更新不可读不可组合（公理一）+ 程序可读可组合可回滚（公理二）+ 修复依赖过程录制（公理三）+ 经验必须能叠（公理四）= "权重冻结 + 工作区进化"不是省事的权宜之计，而是在"可解释、可累积"这两个约束下的唯一解。代价是放弃隐式泛化——这个代价第四节要认真算。

How怎么拆：一个循环，两种进化

循环：读 → 写 → 跑 → 看 → 修 → 存

ASENA 的一轮任务是：agent 读传感器数据 → 写一段程序 → 执行 → 检查录制结果 → 如果失败就改程序再跑 → 成功后把这段程序和结论写进工作区。

注意这里有个和"调用技能库"的本质区别：程序是现场生成的，不是从固定集合里选的。所以它能做技能库里没有的事——论文真机演示里的"合成手势"就是这类，没有哪个预置技能会包含"比一个手势"这种指令，但写成代码就很自然。

进化之一：技能层——把成功路径固化成可执行代码

成功之后，那段程序进工作区。下次遇到相似任务，agent 可以直接调用、或改几行再用。这层的收益是减少试错。

它和 10 月 27 日那篇 Metatron 讲"技能是普通代码"看起来像，但层次不同：Metatron 说的是控制层——把"身体怎么协调"冻成执行层，把"任务要什么"写成代码，解决的是"一个新任务要不要重训策略"；ASENA 说的是智能体层——把"上次怎么把这件事干成的"写成代码，解决的是"同一个任务第二次还要不要重新摸索"。前者是架构分层，后者是经验积累。

进化之二：笔记层——把"世界知识"写成文字

除了可执行技能，工作区里还有笔记（notes）。这类东西不可执行，但能避免重复推理：某扇门往哪边开、某个房间在第几层、上次这个指令被理解偏了要换个说法。

两层加起来构成一个很朴素的记忆结构：可执行的存代码，不可执行的存文字。判断标准只有一条——它需不需要被"跑"一遍。

导航作为一个"可选工具"，而不是主控

这是设计上最值得学的一处。ASENA-VLN 没有被做进主控回路，而是被注册成一个工具，coding agent 需要时才调用。

结果是两个数字：导航接入后，两个 agentic 基准各 +11pp，且执行时间下降。为什么接入一个更强的导航反而更快？因为不用它的时候，agent 得靠"看一帧、想一下、走一步"的方式慢慢挪；把它当工具调一次，就能拿到一段完整轨迹直接执行。

这条设计的普适价值
不要把"学出来的策略"和"写出来的程序"做成主从关系，做成工具与被调用者。策略负责它擅长的（连续、高频、几何），程序负责它擅长的（长程、组合、条件判断）。谁也不用吞掉谁。

真机：不建图的移动操作

Unitree G1 上演示了搜索、视觉检查、空间推理、合成手势，以及结合取物、搬运、递交的移动操作，全程没有预建地图。这一条容易被忽略，但它才是"编程式"最实在的收益：传统导航栈要先建图再规划，而这里 agent 可以现场决定"先往那边走看看"。代价是效率——没有全局地图，路径一定不是最优的。

Worth价值与局限：那条 72→98 的曲线，口径要看仔细

它真正证明了什么

1. 给出了"不改权重也能持续变强"的干净证据。行业里"自我进化"喊了很久，但大多停留在概念或单轮 demo。这里给了一条十轮、跨两个基准、可复现形式的曲线（72→98 / 65→89）。曲线形态本身就是论据——它证明经验能叠、不衰减。

2. 把"策略"降级成"工具"这个做法，工程上非常对。它让学出来的模型和写出来的程序各干各的，不必强行统一。这个接口设计思路可以迁移到任何"模型 + agent"的混合系统。

3. 真机演示覆盖了"技能库之外"的行为。合成手势、无图搜索这类任务，靠预置技能库是做不出来的——这恰好是"现场编程"相对"技能检索"的核心优势。

需要打问号的地方

  1. 72%→98% 的前提是"同一批 100 个任务反复跑十轮"，这恰好是程序化路线最擅长的场景，也是真实世界最不常出现的场景。真实部署里任务是持续出现新分布的，不是同一百个任务循环十次。按公理二的推论，这条路线的强项就是"重复任务上的覆盖"，那这个实验其实是用最强项去考它——它没有回答"第 11 轮来了 50 个全新任务，涨还是掉"。论文没有这个"held-out 新任务"的对照曲线，这是最大的空白。
  2. 98% 是"任务成功率"，不是"任务完成质量"。导航类基准的成功判定通常是"到达目标附近且停止"，不考核路径是否合理、耗时是否可接受、有没有撞到东西。而程序化 agent 有个天然倾向：靠"多试几次、多绕几圈"来提高到达率。论文提到执行时间下降（接入 VLN 后），但没给"每任务尝试次数 / 总移动距离"这些能暴露"暴力搜索"的指标。
  3. ASENA-VLN 的 68.7% / 70.2% 是 SOTA，但和主系统的 98% 不是一回事，两个数字放一起容易被误读。前者是单次导航策略的离线指标，后者是"十轮迭代后、100 个见过任务"的在线指标。把它们并列会让人以为"导航从 68.7 提升到了 98"——完全不同的口径。
  4. "权重冻结"省掉了灾难性遗忘，但换来了另一种遗忘：工作区会膨胀。十轮之后工作区里堆了十轮的技能和笔记，哪些还有效？两条笔记冲突了信谁？某个技能因为环境改了（家具挪了位置）已经失效，agent 怎么知道？论文没有提工作区的清理、失效、冲突消解机制。这跟同期视频记忆系统撞上的是同一个问题——缓存在变强，也在变得越来越难以证伪。
  5. coding agent 的能力上限就是系统的上限，而这一点被当成了外部变量。"进化的速度取决于 coding agent 写代码的能力"。如果底座模型换代，整套系统的表现会跳变——这不是一个自洽的系统，是一个把进步外包给基座模型的系统。这在工程上完全合理（借力打力），但如果被包装成"机器人自我进化算法"，就名不副实了：进化的是工作区，不是智能体本身的能力边界。
  6. 真机部分全是定性演示。搜索、检查、手势、取物递交，描述到位但没有数字——没有成功率、没有次数、没有失败案例。这在具身论文里是常见做法，但意味着"真机能跑通"和"真机能稳定用"之间还差着整个可靠性工程。
  7. "+11pp" 的对照条件要看清。是同一个 coding agent、同样的工具集，只多了 VLN 这一个工具吗？如果是，那 11pp 的分量很足；如果同时还改了提示词或工具描述，那这个数字就说不清归因。论文摘要层面没有交代，需要看正文。

一句话收尾

ASENA 最值得带走的是那个判断：想让系统越用越强，先想清楚"经验要存成什么形态"。存成权重，你得到泛化但失去可控；存成程序，你得到可控但失去泛化。这篇论文选了后者，并且用一条 72→98 的曲线证明它在这个选择上能走多远——但那条曲线的横轴是"同一批任务重复了几次"，而不是"世界变了多少"。这两者的区别，就是 demo 和产品的区别。
