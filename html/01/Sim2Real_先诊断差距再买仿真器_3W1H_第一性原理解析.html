💡 第一性原理核心立论

在仿真里训练策略，本质上是让模型去学「仿真器这个世界的规律」，而不是真实世界的规律。所以 sim2real 失败从来不是一个笼统的「有差距」，而是四件不同的事：物理被简化了、传感器被理想化了、画面被简化了、环境被冻住了。这四件事要用四种完全不同的钱去补——买更好的物理引擎、加噪声模型、扫真实场景、采真实数据。搞不清主导项就上最高保真，等于把钱花在你不缺的那一块上。

是什么不是一种技术，是一份「差距诊断 + 预算分配」的操作手册

先把定位说清楚：这不是一篇提出新方法的论文，是一份写给一线团队的决策手册。它要回答的不是「怎么训得更准」，而是三个更前置的问题：

  1. 我这个项目到底卡在哪种差距上？（物理 / 传感器 / 渲染 / 环境）
  2. 该买哪种仿真器？（物理倾向 / 均衡 / 渲染倾向）
  3. 该花多少钱采真实数据？（500 条？5,000 条？还是别采，先随机化？）

它给出的主线顺序是「成本从低到高」：

顺序手段需要真实数据吗解决什么
0System Identification（可测量参数对齐）不需要，需要测量质量、摩擦、执行器响应、延迟
1Domain Randomization不需要把真实世界变成训练分布里的又一个样本
2RL 专项调优（PPO、循环策略、防漏洞奖励）不需要让策略在随机化环境里稳定收敛
3Domain Adaptation需要（特征对齐可无标签）对齐仿真与真实的特征分布
4完整 SysID + Meta-Learning需要让模型自己适应新环境

而判断「要不要往下走一层」的工具只有一个：在真机上跑 30–50 个标准化 episode，然后看失败长什么样。不是看 loss，不是看仿真里的成功率，是看真机上的失败类型。

四类差距，对应四种完全不同的钱

差距典型表现该花在哪
物理简化仿真里抓得稳，真机上滑；可变形物、颗粒物、接触密集型任务最严重更好的物理引擎 / SysID / 真实数据微调
传感器仿真仿真点云完美，真机有噪声、运动模糊、深色表面丢数据噪声模型 + 延迟建模（比提高画质更值）
视觉渲染换光照、换材质就失效；依赖不存在的统一纹理和缺失阴影渲染器 / 纹理管线 / 真实图像微调
环境变化静态场景能跑，有人走过、东西挪位就崩场景随机化 / 真实场景扫描

原文给了一条很好用的经验法则：接触密集型任务主要受物理精度限制，基于摄像头的导航主要受渲染限制，户外部署主要受环境变化限制。三条一句话就能定位自己该先补哪块。

为什么公理链：为什么「上最高保真」是错的

第 1 步：用仿真不是因为仿真真，是因为真机训练的成本结构不同
现实里碰撞会烧硬件，仿真里碰撞只烧电和一次重置；几千个并行实例能在几小时内产出几百万个 episode；危险场景可以按需构造。RL 恰恰需要几百万次交互。所以「用仿真」不是一个技术偏好，是一道成本方程的解。
第 2 步：但模型学的是仿真器，不是世界
原文这句说得很直白：「通过这种方式训练出来的模型，学到的是仿真器本身，而不是真实世界。」一个受控的到达（Reaching）基准里，除了完全随机化之外，其他所有训练策略在真机上的表现都明显低于仿真。这就是问题的形式：你优化的目标是仿真器分布上的期望，交付的战场是真实分布。
第 3 步：所以真正要保证的，是「真实落在训练分布里面」
这句话是整个 sim2real 的第一性表述：不要求仿真像真的，只要求真的被仿真覆盖。Domain Randomization 之所以是第一选择，不是因为随机化能提高保真度，而是因为它把「覆盖」这件事直接做成了训练目标——真实世界只是随机化范围里的又一个采样。
第 4 步：但覆盖是要付代价的——随机化过头，模型学不到东西
原文点出两个反向约束：一次性引入太多参数、或范围开太大，环境会变得过于不稳定，学不动；而且 2022 年 ICLR 的分析表明，有效的 DR 通常需要记忆——策略得能从当前观测推断「我现在处在哪一种变化里」，所以循环策略（Recurrent Policy）几乎是标配。这就解释了为什么「把参数全开到最大」在实践中经常不如「挑三个参数、范围开到刚好」。
第 5 步：既然覆盖不可能完美，就必须有一个「还剩多少没盖住」的测量手段
于是评估协议成了方法的一部分。zero-shot 与「少量真实数据微调后」的差值，是最有诊断价值的指标：一次微调就大幅提升，说明仿真漏掉了重要的变化因素；微调也不动，说明差距不在分布覆盖，而在模型容量或标签质量。这个指标之所以好用，是因为它不需要你知道漏了什么，只需要你测出「补上一点真数据能涨多少」。

五步走完，结论自然浮现：sim2real 是一个迭代循环，不是一次迁移事件。原文建议在项目计划里就为「仿真-真机之间的多轮诊断」预留预算，通常三到五轮——因为每一轮迭代只会暴露下一个主导失效原因。

怎么做选型 → 对齐 → 随机化 → 测 → 按失败类型分支

一、选仿真器：按主导差距选，不按功能数量选

类型代表强在哪什么时候选它
物理倾向MuJoCo、PyBullet接触、摩擦、刚体动力学依赖接触/力/操作的任务
均衡Gazebo、Isaac Sim物理 + 传感器模型 + 完整环境既要感知又要接触，如料箱抓取
渲染倾向Unity ML-Agents照片级图像与光照纯视觉导航/感知类策略

原文有一个很容易被忽略的提醒：选仿真器不只是工程决策，也是数据管线决策。因为仿真器决定了你会缺哪一类真实数据——选了物理精确但渲染粗糙的引擎，后面必然要补「真实光照下的图像标注」；选了画质好但物理近似的引擎，后面必然要补「力/接触数据」。

还有一个「几何不能靠仿真器解决」的点，值钱：通用厨房场景会让策略学到一个现实中不存在的厨房。做法是扫真实场景做数字孪生——LiDAR 保证几何测量精度、摄影测量重建单个物体，把房间布局从差距里彻底剔除，剩下的问题就只剩物体动力学和材料。原文引用 MIT 的 RialTo：真实场景扫成仿真孪生、在其中微调，八项操作任务平均成功率比基线高 67%。

他们也老实交代了扫描的坑：光照是最难的——提高 ISO 会增噪点破坏 ColMap 的帧匹配，开大光圈会让部分物体脱焦，长曝光要求相机完全静止；扫出来的环境是静态的，抽屉和柜门打不开。所以扫描之前要先列清「任务里哪些物体必须能动」。

二、Domain Randomization：先挑与主导差距直接相关的参数

  • 视觉任务：光照强度与方向、表面纹理、相机噪声。
  • 操作任务：摩擦系数、物体质量、阻尼、执行器增益。

顺序很重要：先把主导差距相关的那几个参数随机化，再逐步加别的。原文的两条实证：Tobin 等人只用「带非真实随机纹理」的仿真图训练，就做出了真机上 1.5 cm 精度的物体检测器；OpenAI 先靠纯 DR 让机械手完成方块重定向，再用 Automatic Domain Randomization（随能力提升逐步扩大随机化范围）解出了魔方。

还有一条防坑经验：Physics Exploitation——智能体学会利用仿真器的漏洞（比如过于宽松的碰撞检测）刷高分，到真机上完全不工作。对策不是改奖励函数，而是尽早在真机上验证，别等到项目最后阶段。

三、真实数据要多少：按用途给量级，不给标准

用途有标签样本量级说明
验证（Validation）500–2,000从实际部署环境采，必须独立于训练集
Domain Adaptation1,000–10,000专补仿真漏掉的那部分情况
完整监督微调10,000 以上原文说「这种情况并不常见」

原文对「数据质量 vs 数量」的态度很硬：5 万张高质量标注图像，可能优于 50 万张有标签噪声的图像。另一条同样硬的：一组覆盖不同光照、角度、物体状态的数据，比一组规模更大但全在同一条件下采集的数据更有用。

四、评估：30–50 个 episode，五步流程

  1. 定义标准化真机测试集：固定场景与受控条件，30–50 个 episode；
  2. 跑 zero-shot：不做任何微调；
  3. 给失败分类：感知 / 控制 / 环境不匹配；
  4. 必要时用带标签真机数据微调，在同一测试集上重跑；
  5. 对比 zero-shot、微调后、纯仿真三个结果。

为什么是 30–50 而不是 10？原文给了统计理由：20 个 episode 且成功率接近 50% 时，95% 置信区间约 ±22 个百分点；50 个时收窄到约 ±14 个百分点。换句话说，跑 20 次拿到 55% 和 65%，在统计上你根本分不出谁更好。

五、按失败类型分支修

失败类型症状修法成本
视觉失效仿真里认得的物体，真机认不出扩纹理/光照随机化 → 加传感器噪声模型 → 少量真图微调感知低
物理失效看得见，抓不住 / 插不进调摩擦/质量/阻尼/执行器随机化 → 用真机 rollout 或遥操作示范微调控制策略最高（要额外仪器化）
分布失效只在某些光照/布局下能跑从失败条件下采一小批真数据中

原文还有一句诊断力很强的话：如果模型在仿真和真机的成功率都是 80%，但两边失败原因不同，那它并没有完成 sim2real transfer。所以错误类型比总体成功率更重要——这也是为什么第 3 步「给失败分类」不是可选项。

公式原文没有公式，这三个是按它的流程与数字整理的形式化表达

标注：本节三个式子是按原文流程整理的形式化表达，非原文照抄。原文全篇为工程叙述，未写出任何数学公式；其中式 1 的常数可由原文给出的置信区间反推验证，式 2、式 3 是对原文定性的差距分解与覆盖条件的数学改写。
式 1　真机测试要跑多少次：二项分布的置信区间
\[ \hat{p}\pm z_{1-\alpha/2}\sqrt{\frac{\hat{p}(1-\hat{p})}{n}},\qquad n=20,\ \hat{p}=0.5,\ z=1.96\ \Rightarrow\ \pm 0.219 \]
\(\hat p\) 是真机上测到的成功率，\(n\) 是 episode 数，\(z\) 取 1.96（95% 置信）。
说人话：你只扔了 20 次骰子，就别声称自己知道骰子的准确胜率。算一下：\(0.5\times0.5/20=0.0125\)，开方 0.1118，乘 1.96 得 0.219 ——正好对上原文那个「±22 个百分点」；换成 50 次，得 0.139，对上「±14 个百分点」。
这就是「30–50 个 episode 是最低测试要求」的数学来源：不是经验，是采样误差。顺带一个实用推论——当成功率明显偏离 50%（比如 90%）时，同样的 n 下区间会变窄，所以「已经很好的策略」不需要跑那么多次也能分出差别；最难分辨的恰恰是 50% 附近。
式 2　四类差距的误差分解：总差距是四块的和，不是一块
\[ \mathcal{G}\;=\;\underbrace{\mathcal{G}_{\mathrm{phy}}}_{\text{物理简化}}+\underbrace{\mathcal{G}_{\mathrm{sen}}}_{\text{传感器}}+\underbrace{\mathcal{G}_{\mathrm{ren}}}_{\text{渲染}}+\underbrace{\mathcal{G}_{\mathrm{env}}}_{\text{环境变化}} \]
把「真机性能 − 仿真性能」这个总差距拆成四个可分别归因的部分。
说人话：这份指南的全部实用性都建立在「这四项可以分别攻」这个假设上。它没有给每一项怎么量化（这恰是它最大的空缺），只给了一条经验法则来定主导项：接触密集 → 看物理项；摄像头导航 → 看渲染项；户外 → 看环境项。
工程含义是反直觉的：把总差距当成一个数去优化，会导致你把预算投向「最容易改的那一项」，而不是「占比最大的那一项」。常见的浪费就是在一个物理受限的任务上拼命提升画质。
式 3　随机化要保证的事：真实分布被训练分布覆盖
\[ \mathrm{supp}\left(p_{\mathrm{real}}\right)\ \subseteq\ \mathrm{supp}\left(p_{\mathrm{train}}(\theta)\right) \quad\Longrightarrow\quad \mathbb{E}_{p_{\mathrm{real}}}\big[\ell\big]\ \lesssim\ \mathbb{E}_{p_{\mathrm{train}}(\theta)}\big[\ell\big]+\delta \]
\(p_{\mathrm{train}}(\theta)\) 是随机化参数 \(\theta\) 决定的训练分布，\(\mathrm{supp}(\cdot)\) 是它取值的支撑集，\(\delta\) 是覆盖内的残差。
说人话：sim2real 要的不是「仿真像真的」，而是「真的落在仿真练过的范围里」。随机化就是把训练分布的支撑集撑大，直到把真实世界装进去。
这个式子同时解释了随机化的两难：\(\theta\) 撑得越大，覆盖越可能成立，但分布越散、模型越难学（原文说「环境过于不稳定，模型难以学习」）。所以最优的 \(\theta\) 不是最大，而是「刚好把真实装进去」——这也就是为什么 Automatic Domain Randomization 要随能力提升逐步扩大，而不是一开始就开到最大。

值不值最有用的三条判据，和它没说清的三件事

值得直接抄进项目文档的三条

1. 「30–50 个 episode」是硬底线，而且能自己验算。20 次试验下 ±22 个百分点的区间，意味着很多团队引以为据的「A 比 B 好 10 个点」在统计上就是噪声。这条能省掉大量无效调参。
2. zero-shot 与微调后的差值 = 差距诊断器。不需要知道漏了什么，只要测「补一点真数据能涨多少」：涨得多 → 覆盖不足；几乎不涨 → 问题不在分布，在容量或标签。
3. 「错误类型一致」比「成功率一致」更重要。两边都 80% 但失败原因不同，等于没迁移成功。这条判据比任何单一指标都更能防止自欺。

必须打的三个问号

  • 它是一家数据采集服务公司的视角，结论天然偏向「多采真实数据」。原文在多个关键处把结论导向「与其继续改仿真器，不如采真实数据微调」，并且结尾直接写「如果你的策略需要真实世界验证集，可以告诉我们你需要采集什么数据」。这个建议在多数情况下是对的，但读者要知道它的利益位置。
  • 四类差距只有定性清单，没有可测量的分解方法。它告诉你「有四块」，却没说「怎么测出我这块占 60%」。实际项目里这恰恰是最难的一步——你只能靠经验法则（接触→物理、视觉→渲染）粗判，而这套法则在「既接触又靠视觉」的任务（料箱抓取、插装）上直接失效，原文只能用「考虑均衡型仿真器或拆分式管线」这种模糊说法带过。
  • 引用偏旧，2026 年的新东西基本没进来。核心引文集中在 2017–2022（Tobin 2017、Tan 2018、Peng 2018、Bousmalis 2018、Chen 2022），最新的也只有 RialTo（2024）和几篇 2025 综述。而 2025–2026 真正在改这个格局的是「视频生成模型造数据」和「世界模型当仿真器」两条线——原文只在「未来方向」里提了一句「Learned Simulators 与 Differentiable Simulators」和「仿真环境中的 Foundation Models」，没有展开，也没有给出任何量化对比。以 sim2real 这个方向的迭代速度，这是明显的缺口。
一句话结论：把它当检查清单用，价值很高——尤其是「先诊断主导差距」「30–50 个 episode」「zero-shot vs 微调差值」这三条，几乎是免费的项目体检。把它当技术路线图用则要小心：四类差距的分解不可测、引用停在 2022、结论带着数据服务商的立场。真正的顺序应该是：先用它的清单定位差距 → 再用当年最新的工具（生成式渲染、世界模型）去补那一块 → 最后才决定要不要买真实数据。
