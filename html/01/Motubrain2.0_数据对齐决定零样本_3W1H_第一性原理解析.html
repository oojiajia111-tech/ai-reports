💡 第一性原理核心立论

机器人想跨数据源学习，卡住它的从来不是数据不够，而是同一件事被记成了不同的样子：头一偏，同一段动作的标签就变了；人手五指，对不上夹爪的一个开合；动作塞进固定基坐标系，换个本体就没法比。Motubrain 2.0 的全部设计，都是在把「动作」换算成一种与头、与身体长相无关的语言，然后小心翼翼地不去惊动预训练视频模型已经学会的世界常识——一边换算，一边给旧能力装隔板。它最后把两件事彻底分开了：模型的物理手感冻结起来当硬件，系统的改法写成可编辑的代码。

是什么不是一篇论文，是「一个 20B 的手 + 一层可改的脑子」

先把最容易误会的地方拆掉：这不是一个模型，是两个东西拼起来的系统。

  • Motubrain 2.0-WAM：20B 参数的世界动作模型。输入多视角 RGB 加一句语言指令，同时输出两样东西——未来 24 步的动作块，和未来的多视角画面。底座用视频生成模型 Vidu 的权重初始化，四流 Transformer（文本 / 视频 / 动作 / 3D 几何）。
  • Motubrain-Harness：外层 Agent 系统。一个固定的规划 VLM（GPT-6.1-sol）+ 21 个工具 + 15 份书面技能，把冻结的 WAM 当作一个「动作工具」来调用，其余时间用几何工具和导航自己干活。

这个拆分本身就是主张：模型层的物理手感，和系统层的任务编排，是两种可以用完全不同方式改进的东西。前者要几百万小时数据、几千张 GPU；后者改的是文字和 Python，一台机器上改完推给整个机队。

为什么公理链：跨源学习的第一道墙是「标签不可比」

这份报告最值得抄的不是任何一个模块，是它推导问题的顺序。顺着往下走五步，你会发现每个设计都是被逼出来的，不是选出来的。

第 1 步：要泛化，就必须跨源；跨源的第一障碍不是分布差异，是坐标差异
sim-to-real、ego-to-robot、跨本体——这些说法听着像三种问题，其实是同一个：同一个物理交互，在不同数据源里被记成了不同的数字。分布差异可以靠数据量盖过去，坐标差异不能：它会让同一段动作产生两个互相矛盾的监督信号。
第 2 步：只要头会动，固定基坐标系就一定失效
他们点出的三个事实很硬：第一视角视频里人的头可以自由转，UMI 演示的操作者头也在动，Astribot S1 这类平台的头和躯干本身就是自由度。在固定 base frame 下，头姿一变，物理上完全相同的视觉-动作交互就会映射成不同的动作目标。更糟的是未标定的 ego 视频——它连 base frame 都定义不出来。所以动作标签必须相对「此刻的相机光轴」和「这个动作块的起点」表达。
第 3 步：本体差异不能靠「压缩到公共子空间」解决
把双臂人形和单臂夹爪压到同一个最小公共维度，等于把信息最丰富的部分先扔掉。正确做法是取并集：每个形态学部位（左臂/右臂/躯干/头/底盘）按整个语料库里的最大表示维度分配槽位，再给每个 step、每个维度打一个 0/1 有效性掩码。模型于是同时知道「这个通道存在」和「这一帧这个通道有真值」。
第 4 步：人手的五指协同，没法映射成一个夹爪开合
这是全篇最诚实的一处取舍。用 pinch distance（拇指到食指的距离）当夹爪开合的代理，看起来聪明，实际会灌进去大量标签噪声——同一个开合度，可能是捏、可能是扶、可能是托。他们的选择是：ego 数据只监督每只手 9 维末端位姿（3 维位置 + 6 维旋转），把夹爪那 1 维和所有机器人关节/躯干/底盘/头部维度全部 mask 掉。宁可少监督，不要假监督。
第 5 步：预训练视频先验是资产，也是易碎品
一个已经看懂世界的视频模型，你想让它学会「动作」，最直觉的做法是改结构、加分支、全量微调。但每一次侵入都会把原来的世界常识冲掉一部分。于是有了贯穿全文的设计原则：把新能力做成不打扰旧通路的插件——动作只能单向读视频，视频永远读不到动作；几何编码器整个冻住，只外挂一对可训练的 Key/Value 适配器；摄像机身份用零初始化的加法嵌入，初始化那一刻等于没加。

第五步之后，还有第六步，也是这份报告真正的落点：模型的能力有天花板，系统的能力没有。既然「什么时候调用模型、怎么组织指令、失败了怎么退回去」这些东西可以写成文字和代码，那就让失败轨迹去改代码，而不是去改 20B 的权重。两个数量级更便宜，而且一次部署覆盖整个机队。

怎么做五件对齐 + 三道隔板 + 一层可改的壳

一、数据对齐：五件套把五种数据摁进同一个坐标系

动作解决什么不做会怎样
Canonical55 统一维度 + 掩码异构本体的动作空间压缩到公共子空间 → 丢掉最丰富的那部分
夹爪极性统一（下界闭合、上界张开）不同驱动、不同 UMI 硬件的符号约定相反同一个「抓」在不同源里是 +1 和 −1
针孔坐标约定（+z 前 / +x 右 / +y 下）URDF、VIO、手部追踪三套局部轴不一致轨迹对齐全错，且错得看不出来
相机相对的 SE(3) 位移头在动导致的标签不稳定同一物理动作产生两个监督目标
手掌中心 + Savitzky-Golay 平滑（9 帧窗口、二阶）人手没有「末端执行器原点」，单目追踪有高频抖动动作原点漂移，抖动被当成了动作

还有一个细节值得单独拎出来：末端位姿和关节位置记录的是「测量到的本体状态」，而不是「遥操作下发的指令」。因为不同平台的追踪延迟和控制增益差异很大，用指令当标签，等于把每台机器人的控制器缺陷也一起教给了模型。夹爪相反——它记录的是离散的开/合动作，不是被柔性变形影响的实测开合宽度。

二、架构：三道隔板

  • 非对称注意力（第 7–24 层才开桥）：前 6 层，动作流自己做自注意力，看不到任何视觉和文本；第 7 层起，动作 Query 才能读视频、读语言、读几何。反向永远不通——视频 Query 和语言 Query 始终看不到动作 Token。这意味着动作学习不会反过来改写视频分支的表征。
  • 冻结的几何编码器：并行跑一个 Depth Anything 3 Large（304M），只取第 10/12/…/24 层这 8 个全局注意力层的特征，通过一对无 bias 的可训练适配器映射成几何 Key/Value，全程 stop-gradient。好处是不需要深度标签、不需要相机外参，也不用反向传播穿过几何主干。消融显示：冻结 12.94% 成功率，联合微调反而只有 12.54%。
  • 零初始化的视角嵌入：每个相机一个可学习向量，只加一次。初始化为零的意思是「初始化时这个操作等于没做」，预训练模型的输入特征一字不改。消融里这一项拿到 41.6%，比不加视角嵌入（38.7%）和像素拼接（39.5%）都高。

三、实时：30 步压到 4 步，再压内核

扩散/流匹配模型的原始推理是 30 步去噪，30 × 每步几百毫秒，闭环控制直接没戏。他们的做法是三层叠加：

  1. 步数蒸馏：DMD + PCM 正则 + 真值正则三项一起，把学生模型压到 4 步；
  2. 模型级缓存：速度场外推、AdaLN 缓存、观测条件缓存、文本嵌入缓存；
  3. 内核级：MXFP8 线性层（255 个 DiT 模块 + 72 个 DA3 模块）、SageAttention（QK 用 INT8、PV 用 FP8）、动作分支用 BF16 FlashAttention-2、DA3 走 CUDA Graph 重放。

结果：单次请求中位延迟 642.4 ms → 331.2 ms（降 48.4%），P95 645.9 → 335.1 ms。注意，这个数字是「固定四步欧拉采样、不含网络传输和仿真执行」的本地推理耗时，不能当成端到端控制周期。

四、Harness：让失败轨迹去改代码

外层壳的设计有三条原则，每条都在解决「LLM 调机器人为什么老是原地打转」：

  • 返回测量状态，不返回指令状态：每个运动工具回的是从编码器和相机读到的、机器人真正到达的位姿。Agent 于是不会「以为」自己到位了。
  • 把几何封在工具里：Agent 只说「抓那个红苹果」，分割、抬到 3D、规划路径全在工具内部。它不需要算逆运动学，也不需要读深度图。
  • 拒绝要带原因：目标超可达范围时，返回实测值 + 违反了哪条约束 + 建议下一步。这样 Agent 通常一个回合就能改路线。

RSI（Harness 级递归自改进）跑四步：整个机队并行跑当前版本 → coding agent 读每个 episode 的工具日志、把信号映射成原因码 → 只改工具/技能/指令三处（权重、任务定义、成功判定全部冻结）→ 推给全机队。诊断数据很能说明问题：691 个已诊断问题里，84% 靠改技能解决，16% 靠改工具；722 个问题里有 720 个至少在两台机器人上出现过——所以一台修好，全队受益；反过来说，单机跑发现不了大部分失败。

公式三个式子，分别对应「换算」「学动作」「改系统」

式 1　相机相对的动作标签：把「头动了」从标签里扣掉
\[ \Delta p^{c}_{t_k}=R_c^{\top}\left(p_{t_k}-p_{t_0}\right),\qquad \Delta R^{c}_{t_k}=R_c^{\top}R_{t_k}R_{t_0}^{\top}R_{c},\qquad k=1,\dots,H \]
\(R_c\) 是动作块起点时刻主相机的朝向，\((R_{t_0},p_{t_0})\) 是起点末端位姿，\((R_{t_k},p_{t_k})\) 是第 k 步的目标位姿，\(H=24\) 是预测步数。
说人话：别在世界坐标系里记「手往哪走」，改成记「相对我此刻视线，手往前、往右、往下走了多少」。
关键性质在论文自己点出的那句：旋转项等价于对局部相对旋转做一次共轭变换，只依赖相机的朝向，不依赖相机的平移。所以相机被举高、被人走两步，不影响标签。附带好处是消除了逐步累积的漂移，也对关节零位标定的偏移不敏感（因为关节通道也用「相对起点的位移」参数化）。
式 2　异步双时间步的流匹配：视频和动作各走各的噪声进度
\[ y^{q}_{s_q}=(1-s_q)\,y^{q}_{0}+s_q\,\epsilon_q,\quad u^{*}_{q}=\epsilon_q-y^{q}_{0},\quad \mathcal{L}_{\mathrm{WAM}}=\sum_{q\in\{\mathrm{vid},\mathrm{act}\}}\lambda_q\,\mathbb{E}\big[D_q(u^{\theta}_{q},u^{*}_{q})\big] \]
\(q\) 走两个模态：vid（未来视频隐变量）和 act（归一化动作）。\(s_q\) 是各自独立的扩散时间，\(\epsilon_q\) 是高斯噪声，\(u^*_q\) 是目标速度场。
说人话：训练时不要「整段视频和整段动作用同一个噪声等级」——视频可以从很糊到很清，动作不需要跟着一起糊。两条时间轴独立采样，模型就学会了在任何噪声组合下把两者一起还原。
两个实现细节决定了它不跑偏：一是动作损失只在有效维度上取平均（掩码为 1 的位置），假标签不参与；二是观测帧不参与噪声调度、也不算视频损失——条件帧永远是干净的，不然模型会去重建它已经看到的东西。
式 3　Harness RSI 的目标：只改代码，不改权重
\[ A^{\star}=\arg\max_{A=(T,S,P)}\ \mathbb{E}_{u\sim U,\ \tau\sim D}\Big[\,\mathrm{succ}\big(A,u,\tau\big)\Big] \]
\(T\) 是工具代码和工具说明，\(S\) 是技能库（一段段书面操作流程），\(P\) 是 Agent 指令（含什么时候调 WAM 的规则）。\(U\) 是机器机队，\(D\) 是任务分布，\(\mathrm{succ}\) 是任务成功。
说人话：把「机器人怎么干活」里所有不是权重的部分打包成一个可编辑对象 A，然后在真实机队上不断改它、测它、留下更好的那个版本。
这里必须看清约束：WAM 权重、任务定义、成功判定标准全部冻结。所以 44%→63% 的提升，来源只能是文字和代码的修改；这也意味着它优化不了「模型手感本身不够」这一类问题——报告自己在结尾承认，剩下的瓶颈是细粒度接触失败和分钟级的规划延迟。

值不值它把「对齐」提到了第一性的位置，但所有数字都是自己跑的

值得拿走的四条

1. 「标签可比性」优先于「数据规模」。破坏轨迹配对一致性后，六项真机任务从 83.5 掉到 41.3。这是全篇最硬的一条因果证据：不是数据不够，是数据被记坏了。
2. 有效 epoch 不平衡是真问题，而且有反直觉签名。23K 小时真机数据 vs 386K 小时 ego 数据，约 1:17。真机数据过采样到 120k–150k 步之后，干净场景成功率稳在 63%→64%，随机场景从 62.34% 塌到 44.92%。模型不是在退化，是在记住摄影棚的灯光和桌布。他们给的采样比例建议（真机 : UMI : ego/视频 ≈ 1 : 5 : 10~20）和「必须用扰动场景选 checkpoint」这条，任何做多源预训练的人都能直接用。
3. 非侵入式接口省下的不只是算力。冻结 DA3 反而比联合微调高（12.94% vs 12.54%），参数量只有 VGGT 方案的三分之一，还不需要深度标签。这类「不动它反而更好」的结论，比任何涨点都值钱。
4. 把系统改进和模型改进解耦，账算得很清楚。V6 比 V1 成功数从 31 涨到 45（71 次试验），代价是中位耗时 144→487 秒、工具调用 14→62 次、Token 0.67M→5.19M。这不是免费的提升，是用推理成本买执行可靠性。工程上这个交换常常划算，但报告没有藏着。

必须打的六个问号

  • 没有一个数字是第三方复现的。20B 模型、250 万小时数据、13 台机器人连跑 20 天、3,137 个 episode——这套配置全球没几个团队能重跑。所有 baseline 都是作者自己用相同数据微调的，公平但不独立。
  • 「250 万小时」的说法有营销成分。真正带动作监督的是约 37 万小时（14.8%）。纯互联网视频只监督视觉动态，它对「动作能力」的直接贡献接近零，作用是把世界常识保住。这不是错，但把 250 万当成「动作数据量」读就会高估一个数量级。
  • Harness 的提升，有多少来自 GPT-6.1-sol？规划器在所有实验里固定为同一个强模型，但没有做弱规划器的对照。于是无法区分：是「工具+技能+分层」这套设计带来了 22%→91%，还是「背后有个很强的 VLM」带来了它。这是该方法最需要补的一组消融。
  • RSI 的成功判定仍然是人在环。Agent 自己提交 verdict，再由人工复核。也就是说这个「自动改进循环」里同时有 LLM 的判断和人的判断，循环的自动化程度被高估了。
  • 真机评估的样本量偏小。六项任务每项每 checkpoint 148 个 trial，受控套件每项每设置 8 轮；One-Shot 结论建立在 20 次试验上（14/20）。这种量级能看出趋势，撑不起「one-shot 就够」的强结论。
  • 它自己承认的两个天花板很关键。一是细粒度接触失败——这说明 20B 世界动作模型的物理精度还没到「能替代力控」的程度；二是反复调 VLM 带来的分钟级规划延迟——这意味着 91% 的成功率不是实时拿到的，228 秒完成一个双物品摆放任务，和人类差了一个数量级。
一句话结论：如果只从这份报告里拿一条，就拿「先对齐，再加数据」——它用 83.5→41.3 的崩塌证明了标签一致性比数据规模更靠前；如果拿两条，第二条是「冻结模型，去改壳」——44%→63% 的提升没动一个权重，这是很多团队完全没在算的一笔账。但要清楚，这两条结论的置信度不同：前者有受控消融支撑，后者只有单一强规划器下的自评。
