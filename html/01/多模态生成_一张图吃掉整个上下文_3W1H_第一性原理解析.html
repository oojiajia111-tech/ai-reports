一句话 「统一」不是架构选择，是被 token 预算逼出来的结果
💡 第一性原理核心立论

这篇文章从头到尾在讲一件事：怎么让 LLM 长出图像、音频、视频的输出能力。它给了两条路线——把外部生成器接上去（Late Fusion），或者把生成能力塞进 LLM 内部（Early Fusion），并且明显偏好后者，用的词是「更加原生」。但全文 1.44 万字、53 张图、没有一个数字：没有参数量、没有 token 率、没有 FID、没有 FVD。所以它讲的是怎么搭，不是值不值。而一旦把账算出来，就会发现所谓「统一架构」从一开始就被一个算术关系锁死了：图像 token 数 = (H/f)×(W/f)，当 f=16 时，一张 1024×1024 的图正好是 4096 个 token——把 Janus 的整个上下文窗口吃掉，一个 token 都不给文字留。这不是模型不够聪明，这是账算不过来。

是什么三层结构：先各自生成，再想办法拼起来

这篇文章的组织方式很清晰，是一条从「单模态怎么生成」到「怎么和 LLM 对接」的递进链条。

第一层：单个模态的生成机制

图像 = Diffusion + Latent Space
Stable Diffusion 五个部件：文本编码器、扩散模型、含噪输入、图像编码器、图像解码器。关键在于扩散不直接在像素上做，而是在 VAE 压缩出来的 latent 张量上做——这一步是速度的来源，也是「预测噪声」这个目标能成立的前提。
图像生成的新主角 = DiT
把 latent 切成 patch 当 token，用 Transformer Block 替代 U-Net，通过 adaLN（自适应层归一化）注入时间步和标签条件。代表模型 PIXART-α、FLUX.1 Dev。
音频 = 两级 Token + 三级 Transformer
AudioLM。SoundStream 出 Acoustic Token（音色音高），w2v-BERT 出 Semantic Token（说什么），再由三个串起来 Transformer 依次生成：先语义、再粗粒度声学、最后细节。声音最后由 SoundStream 的 Decoder 重建。
视频 = 图像 + 一个时间维度
Latte。难点全在 tokenization：逐帧切 patch 再拼（Uniform）还是跨帧切 tubelet（Compression）。作者发现后者更差，推测是压缩丢了时空信息。Block 用空间、时间交替排列（Interleaved Fusion）。

第二层：两种把它们接进 LLM 的路线

路线做法可训练参数文中代表
Late Fusion
输出投影		LLM 输出特殊 token（[IMG]/[AUD]/[VID]），由一个 MLP 或小型 Transformer 投影成下游扩散模型能吃的条件向量只有投影层，百万级；主干全冻结NExT-GPT、OmniGen2、BLIP-3o
Early Fusion
统一生成		把图像也变成 token，和文本 token 放进同一条序列，由同一个 LLM 一次生成，再分别解码大部分参数都要动，十亿级Janus

文中的偏好很明确：称 Late Fusion「很简洁，但很难把 LLM 视为一个统一的多模态实体」，甚至直接说「可以理解为一个 Agent 调用其他生成工具」；称 Early Fusion「更加原生」「通常能够获得更高的准确性」。

第三层：Janus 作为 Early Fusion 的样板

Janus 的三阶段训练写得最细：第一阶段只训 Adaptor 和 Image Head，建立视觉与语言的概念联系；第二阶段统一预训练，混着纯文本、多模态理解、视觉生成三种数据；第三阶段用指令数据做 SFT。整个设计只有一个真正的技术选择：理解和生成用两套不同的视觉编码器——理解用 SigLIP，生成用 VQ-GAN。

这个选择就是全文最重要的一句话，但它被当成实现细节写过去了。如果「统一架构」真的成立，那么理解和生成应该能共用一个视觉表征。Janus 恰恰没有这么做。这说明两者需要的东西根本不同，而这一点恰好是后文所有「统一」叙事的地基裂缝。

为什么Janus 的两套编码器，是对「统一」的自我反驳

先看这两套编码器到底在做什么。

SigLIP（理解）VQ-GAN（生成）
输出形态连续向量离散 codebook 索引
训练目标图文配对的 pairwise sigmoid loss（对齐语义）重建损失 + 对抗损失（骗过判别器）
优化的是什么「这张图和这句话是不是一对」「重建出来的图看起来像不像原图」
保留的信息高层语义，丢掉细节细节与纹理，语义不管
能不能给 LLM 直接吃能（连续向量投影即可）能（离散 token 就是词表）

两者的目标函数是互斥的。SigLIP 追求的是把「同一概念的很多张图」压到同一个点上，细节越少越好；VQ-GAN 的对抗损失追求的是让判别器分不出真假，细节越多越好。你没办法用一个编码器同时最大化这两个目标。

于是「Early Fusion」这个词需要重新定义
Janus 的统一只发生在LLM 内部的 token 序列这一层——两个模态的 token 被拼进同一条序列，由一个 Transformer 处理。但在进 LLM 之前，它仍然是两个塔、两个 adapter。也就是说，它的融合点从「模型外部」搬到了「token 序列里」，而不是消除了融合。
换个说法：Janus 做的是「在 LLM 内部做 late fusion」。它真正买到的东西不是「统一表征」，而是联合训练——理解和生成共享同一个 Transformer 的参数，梯度会互相影响。这个价值是真的，但它和「统一架构」是两个不同的卖点，文中把它们混成了一件事。

这也解释了一个文中有提到、但没串起来的现象：NExT-GPT 的输入侧用 ImageBind 编码，生成侧用 Stable Diffusion，两边完全解耦；Janus 则强行把两边塞进一个 LLM。前者训练只要百万参数，后者要动十亿级。如果「统一」的收益只是「准确率更高」这种没有数字的说法，那这笔账在工程上是算不过的——除非统一带来了别的东西。

那个「别的东西」确实存在，而且文章没说出来：联合训练让生成过程可以被语言推理引导。你可以让模型先生成一段「我要画一个火烈鸟站在浅水里，倒影在左下」，再生成图。NExT-GPT 做不到这一点，因为它只是把 LLM 当 prompt 生成器。这才是 Early Fusion 真正的护城河，而不是「更统一」。

算账分辨率天花板是上下文预算决定的，不是模型能力

这是全文最该有、但完全没有的一段。把图像变成 token 之后，它就进入了和文本完全相同的资源竞争——上下文长度。

图像 token 数（VQ-GAN / VAE 下采样因子 f）
\[ N_{img} = \frac{H}{f} \times \frac{W}{f} \]
f 是空间下采样倍数。Stable Diffusion 的 VAE 用 f=8，VQ-GAN 常用 f=16。
代入 1024×1024、f=16：(1024/16)² = 64² = 4096 个 token。
代入 512×512、f=8：(512/8)² = 64² = 同样是 4096 个 token。
两个数量级不同的像素量，压缩后撞在同一个数字上——因为 token 数只取决于 H/f，不取决于 H。

再看预算这边。Janus 这类模型的上下文窗口是 4096 个 token。于是：

上下文约束
\[ N_{img} + N_{text,in} + N_{text,out} \le L \]
L = 4096（Janus 的序列长度）。N_text,in 是一轮对话的 prompt，N_text,out 是要生成的文字。
如果生成 1024×1024（4096 token），则 N_text,in + N_text,out ≤ 0。
也就是说：1024 分辨率的图，在 4096 上下文里连一个字都装不下。

这解释了 Janus 为什么把生成分辨率定在 384×384：

生成分辨率下采样 ftoken 数占 4096 上下文留给文字

所以「统一架构」的真实代价，是把图像生成从「算力问题」变成了「会计问题」。扩散模型时代，提高分辨率的代价是显存和步数，是线性的、可以堆卡的。统一进 LLM 之后，分辨率直接和「模型还能不能说一句话」抢同一个池子，是零和的。这就是为什么 Janus-Pro 要提升生成质量，必须同时扩上下文长度——不是调参，是这两个数被绑死了。

顺带修正文中一个说反了的地方

文中说 DiT Block「遵循与常规 LLM 类似的模式：多个模块堆叠，并通过 Self-Attention 依次处理信息」。这个「依次」用错了。

  • LLM 是自回归的：第 n 个 token 依赖前 n−1 个，所以必须顺序生成，因果掩码是硬约束。
  • 扩散是全并行的：整张图在同一时刻一起降噪，每个 patch 同时更新，不存在 token 顺序。

DiT 从 LLM 那里借的是参数效率（同样的算力能塞进更多参数、更好并行），不是生成范式。文中自己其实给出了正确归因——「U-Net 依赖跳跃连接的深层卷积，规模扩大后内存消耗增加、优化困难、并行化效率低」——但这段话全部是工程指标，没有一项是生成质量。

也就是说：DiT 赢的是规模化赛道，不是画质赛道。文中把「更容易变大」写成了「更好」，这两件事之间没有推导。要证明 DiT 画质更高，需要同参数量下的 FID 对比——文中一个都没有。有意思的是，文中唯一提到的量化指标 FVD，是用来说明 Latte 里「adaLN 变体优于把时间步当 token」这个局部选择的，而不是用来做架构对比的。

批判六条经不起推敲的地方

  1. 全篇零数字。1.44 万字、53 张图、0 个表格、0 个参数量、0 个 token 率、0 个 FID/FVD 横向对比。文中出现的唯一量化指标是 FVD，且只用于单点消融。这意味着它是一篇架构导览，不能用来做技术选型，也不能用来判断哪条路线更优。
  2. 「Early Fusion 通常准确率更高」没有证据。这句出现在第 7 节结尾，紧接着自己承认「训练成本高得多」，但两者之间没有任何数字。一个更高的收益配一个更高的成本，结论取决于比值——而这个比值文中没有。
  3. 把 Janus 的双编码器当成实现细节。这是全文最关键的技术选择，却只用一句话带过。它实际上推翻了「统一表征」这个前提：如果理解与生成可以共用一个编码器，Janus 没有理由用两个。
  4. 跳过了对抗损失的代价。VQ-GAN 和 SoundStream 都用判别器训练。对抗损失的经典性质是用保真度换感知质量——重建图更像「人眼觉得对」，但像素级误差反而更大。这正好是理解任务不能用的原因（理解要的是准确的语义对应，不是好看的纹理）。文中把判别器说成「让重建更接近原始信号」，隐去了这个权衡，于是 Janus 选两个编码器的原因就只能被读成随意。
  5. AudioLM 三级级联的代价被略过。语义 → 粗粒度声学 → 细粒度声学，三次自回归串联。代价有两层：一是误差累积（第一级错了，后两级无法纠正，因为它们是条件生成）；二是不可并行（每级都要逐步生成）。SoundStream 常见配置的 token 率在 50/秒量级，10 秒音频就是 500 个 token × 3 级。这是后来语音模型转向单阶段/流式架构的直接原因，也是「为什么 AudioLM 是里程碑但不是终点」的答案。
  6. 53 张图 / 1.44 万字 = 每 271 字一张图。这不是缺点，但它决定了文章的认知形态：所有机制解释都通过示意图传达，文字是图的旁白。示意图能传达「有几个部件、怎么连」，传达不了「哪个部件的哪一项设计带来多少收益」。读者读完会获得一张准确的结构图，和一组无法验证的判断。

价值这篇该读什么，不该信什么

该读的三段

Latent Space 这一步为什么要做
扩散在 VAE 压缩后的张量上做，不在像素上做——这是整个图像生成效率的基础。理解了这一点，才能理解后面 DiT 为什么能成立（因为 latent 已经被切成小块了，patchify 才有意义）。
Latte 的负结果
Compression Frame Patch（tubelet）表现不如Uniform Frame Patch，作者推测是压缩丢了时空信息。这是全文唯一一个明确的「我们试了 A 方案，它更差」的记录，比所有正面描述都有信息量。
NExT-GPT 的层次化分组
把相似的 patch embedding 先聚成「天空」这种概念，再把「天空 + 云」聚成「天气」，然后才投影给 LLM。这是一个很实用的 trick：让 LLM 处理语义概念而不是底层 patch，减少无效 token。做多模态输入工程的人可以直接借鉴。

不该信的两处

  • 「Early Fusion 更准确」——没有数字支撑的路线偏好，用词带情感（「原生」「统一」）。
  • 「DiT 优于 U-Net」——文中给的三条理由（内存、优化、并行）全是工程指标，不是质量指标。DiT 的真实优势是能更容易变大，而「变大之后更好」是另一件事。

如果只记一句话

多模态生成的竞争，最终不是架构之争，是 token 预算之争。把图像变成 token 的那一刻，它就和文字抢同一个池子。分辨率、上下文长度、生成质量三个数被绑在一条式子上：N = (H/f)² + N_text ≤ L。谁能用更少的 token 表达同一张图（更聪明的 tokenizer），谁就赢——而不是谁能把架构画得更统一。
