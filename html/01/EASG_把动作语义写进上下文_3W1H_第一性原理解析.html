第一性原理核心立论

VLA 的动作头之所以贵，不是因为动作难预测，而是因为它从来没说清自己在说哪种语言。动作是一串数字，数字本身没有意义——意义全部来自坐标系、尺度、单位。「往 +Z 走 6 厘米」这句话，只有在先定义了 +Z 是哪个方向、6 厘米是相机系还是基座系之后才可执行。这批约定在机器人数据里全是隐含的，于是模型只好一边学做事、一边反推约定，两份学费一起交。EASG 把这批约定直接画在图像上、写进提示词里：模型第一次知道自己在说哪种话。剩下的事，它本来就会。

它到底改了什么 两条路都卡在接口 锚定、闭环、约束解码 五个式子 证到了什么、没证到什么

是什么不是造一个更强的动作解码器，是把动作的「语法书」塞进输入

先看结果，因为它反常：一个 27B 的开源 VLM（Qwen-3.8-27B），不做任何机器人动作预训练、不加动作头、不挂技能库，靠原生文本接口直接控制一台 UR3 机械臂，在六项真机任务上零样本拿到 79.4% 平均成功率。

对照一下同批次的 VLA：π0.5 用每任务 30 条示教微调后才 76.1%；把示教加到 50 条，这批 VLA 才拉开到 85.6%–96.7%。也就是说，它零样本的成绩，约等于一个通用 VLA 微调 30 条示教的水平。

它输出的「动作」长这样：

0 | +0.40, -0.10, +0.91, +6.00 | +0.00, +0.00, +1.00, -45.00 | +1.00
读法：任务还没完成｜沿方向 (0.40, −0.10, 0.91) 走 6 厘米｜绕当前 TCP 的 +Z 轴转 −45 度｜夹爪闭合到 1.0。

整串全是普通字符。这正是关键——这些符号本来就在预训练词表里，所以自回归解码器本身就是动作解码器。不需要额外训练一个 head，也不需要独立词表。

最后一行的逻辑值得单独说：模型只在末端位姿空间里预测，机械臂各自的逆运动学和底层控制器负责翻译。6 自由度换 7 自由度，同一个 checkpoint 直接上，几乎不掉点。这不是调出来的，是坐标系选对了的副产品。

为什么动作的语义本来可以被语言描述，却被当成只能从数据里猜的东西

把这件事拆到最底层，是一条五步的公理链，每一步都不需要机器人知识：

公理一：数字本身不携带意义，意义由约定提供
「位移 6」这句话，单位是厘米还是米、方向是相机系还是基座系、旋转用欧拉角还是四元数——换任何一项，同一个数字对应完全不同的物理动作。约定的信息量不小，但它其实是可以被写下来的。
公理二：现有 VLA 把这批约定当成「要从数据里学的东西」
Open X-Embodiment 这类大规模数据里，坐标系、尺度、运动学对应全都隐含在观测与动作标签之间，没有以模型能直接读的形式给出。于是模型必须同时学三件事：动作怎么参数化、参数在物理世界意味着什么、图像里的二维关系怎么对应三维运动。三份学费，一份也没省。
公理三：另一条路（模块化）省了学费，却断了后路
Code as Policies 生成调 API 的程序，VoxPoser 造三维价值图，ReKep 用关键点关系约束求解。它们把操作问题翻译成基础模型已经懂的表示，所以不需要动作预训练就能干活。但「视觉观测 → 连续动作」的映射散在模型和外部模块之间，一旦零样本不够用，你没有一个统一接口能直接拿机器人轨迹去微调那个正在推理的模型。
公理四：所以真正缺的不是能力，是「同一接口的两用性」
要一个接口，既能零样本直接跑，又能在同一个接口上用机器人数据继续学。这要求动作的表示方式本身就落在语言模型的原生表达能力之内——只有这样，「直接推理」和「微调」才是同一件事，而不是两套系统。
推论：动作头不是必需品，词表才是
如果动作是一段合法文本，那么「生成动作」和「生成句子」在计算上就是同一个操作；动作头、动作专家、独立词表这些模块，都是为了绕开「动作不是文本」这个假设而存在的。把这个假设去掉，它们就都不需要了。
那条最反直觉的消融，正好验证了公理一：把「动作坐标系锚定」去掉，或把「深度信息」去掉，平均成功率从 79.4% 直接掉到 0%。不是掉一点，是归零。也就是说，只给任务指令和图像，这个模型完全无法产生可靠动作——它的空间与常识能力是真的，但它缺的是「往哪走、走多远」这两条最基础的信息。

怎么做三件事：把坐标系画在手上、闭上环、把格式焊死

第 1 步：显式动作空间锚定——把坐标轴投影到腕部相机画面里
每个控制步，以当前 TCP（工具中心点）为原点建一个局部坐标系：X 轴沿夹爪开合方向，+Z 从夹爪主体指向指尖，Y 轴与二者构成右手系。然后把这个三维坐标系的三根轴投影到腕部相机的第一人称图像上——模型看到的不是「一个数字」，而是「图像里画出来的三根箭头」。
光有方向还不够，精确控制要知道走多远。所以再用对齐的 RGB-D 观测，估计沿 TCP +Z 到最近可见表面的距离，把这个物理尺度直接告诉模型。最后配一段语言说明，规定平移单位（厘米）、旋转表示（轴角，度）、夹爪语义和输出格式。视觉投影 + 距离 + 语言，三样合起来把原点、轴向、参数化方式、尺度全部交代完。
第 2 步：闭环执行——模型只管说，换算交给确定性代码
每步模型输出一步增量平移、旋转、夹爪指令和完成标志。预测先在 TCP 系里表达，再变换到机器人基座系，然后走逆运动学和底层控制器。执行完重新取观测，进入下一轮。
这条分工是整个方法的地基：VLM 永远在同一个动作空间里推理，各家机械臂的坐标变换和运动学由确定性过程处理。所以换本体不用重新训练——同一套话，换个人来翻译就行。
第 3 步：原生文本动作学习——只用词表里已有的 token
平移用「单位方向向量 + 非负距离（厘米）」，旋转用「单位旋转轴 + 带符号角度（度）」。生成时若向量没严格归一化，执行前做一次归一化。把机器人示教按同样规则转成文本动作后，直接用标准因果语言模型的交叉熵损失微调——零样本执行和后续学习共享同一套动作表示，不换接口、不加预测器。
实测里这一步用的是 LoRA：困难任务每项收 30 条示教，就能把 27B 从「做不了」教到 67.2%。
第 4 步：语法约束解码（GCD）——自由生成会写错格式，那就把非法 token 屏蔽掉
自回归生成动作，一个小错就让整条命令不可解析：少一个字段、分隔符写错、或者数值后面多吐一段解释。GCD 在每一步生成时屏蔽不符合动作语法的候选 token，但保留原模型对合法候选的偏好——约束只作用于格式，具体数值仍由 VLM 自己预测。
效果很硬：LIBERO 上 0.8B 模型 72.66% → 83.28%，四个子集全部改善。而 GCD 没有任何可学参数，也不增加动作头、不改词表。
把四步串起来看：锚定解决「往哪走、走多远」，GCD 解决「说得对不对」，两者都不是让模型变聪明，而是把本来不该由模型猜的东西拿走。真正留给模型学的，只剩「做什么」。

公式五个式子：从「一句话」走到「一次微调」

① 动作的文本形式：四段，全在词表里
\( a_t = \big(s_t \mid \mathbf{v}_t, d_t \mid \mathbf{r}_t, \theta_t \mid g_t\big) \)
大白话：第一段是任务完成位，第二段是单位方向向量加厘米数，第三段是单位旋转轴加角度，第四段是夹爪开合。这个式子的全部价值在于「没有新符号」——每一项都是普通数字，所以不需要任何额外解码器。
② 执行链：模型只在 TCP 系说话，翻译是别人的事
\( \mathbf{a}^{\text{base}}_t = T_{\text{tcp}\to\text{base}}\,\mathbf{a}^{\text{tcp}}_t,\qquad \mathbf{q}^{*}_t = \mathrm{IK}\big(\mathbf{a}^{\text{base}}_t\big) \)
大白话：先把 TCP 系的动作旋到基座系，再解逆运动学得到关节角。跨本体迁移之所以几乎不掉点（63.9% → 62.2%），全部利润都在这个式子里：模型学的是「在末端空间怎么动」，而「怎么用你这台机械臂实现」被隔离在模型之外。
③ 微调目标：和训语言模型一字不差
\( \mathcal{L}_{\text{SFT}} = -\sum_{i=1}^{|a_t|}\log p_\theta\big(a_t^{(i)} \mid a_t^{(大白话：\(o_t\) 是观测（含画了坐标轴的图像），\(l\) 是语言指令，\(\mathcal{A}_t\) 是那段说明动作怎么参数化的话。注意损失函数里没有动作头、没有流匹配、没有扩散项——它就是普通的下一 token 预测。这一行是整篇论文最省钱的贡献。
④ 语法约束解码：只筛候选，不改数值
\( a_t^{(i)} \sim p_\theta(\cdot \mid a_t^{(大白话：\(\mathcal{G}_{\text{pos}}\) 是「这个位置上语法允许出现的字符集合」。把不属于它的 token 概率直接清零，再在剩下的里面采样。它保证字段顺序、分隔符、符号、数值精度都对，但「走 6 厘米还是 8 厘米」仍由模型决定。这就是为什么它能提 10.6 个点却不牺牲能力。
⑤ 零样本成功率：为什么「79.4% 对 0%」这组数最值钱
\( \mathrm{SR} = \frac{1}{N\,T}\sum_{n=1}^{N}\sum_{t=1}^{T}\mathbb{1}\big[\text{success}(n,t)\big] \)
大白话：6 个任务 × 3 轮 × 10 次 = 180 次试验的成功比例。它本身平淡，但配上消融就变成诊断工具：去掉坐标系锚定或深度，这个数从 0.794 变成 0.000。在统计上这不是「性能下降」，这是「系统失效」——说明这两条信息是开关，不是加分项。
还有一组数比成功率更能说明机制：Thinking / Memory 的 2×2 对照——两者都开 79.4%；只留 Memory 关掉 Thinking 11.7%；只留 Thinking 去掉 Memory 64.4%；都关 8.9%。Thinking 是命门，Memory 是补丁。「把香蕉放到盘中」这类多阶段任务，去掉历史信息后成功率从 66.7% 直接掉到 0。这顺带否掉一个流行假设：它不是在背轨迹，因为背轨迹不需要每一步都推理。

价值与局限它最硬的贡献是一句诊断，最软的地方是任务太窄

值得带走的

  • 它把「VLA 到底缺什么」这个模糊问题变成了一句可验证的话：缺上下文。原文的自我批评很尖锐——不管预训练时用关节角还是位姿表示动作，两种格式微调后效果基本一样；推理时甚至完全不输入 RGB、只给当前机械臂姿态，VLA 往往也能成功。这说明模型没在理解任务和图像，是在背轨迹。EASG 用「去掉锚定就归零」证明了这个诊断是真的。
  • 它指了一条成本极低的路：不训动作头。一个 0.8B 模型不做动作预训练，直接在 LIBERO 上微调就 83.3%，超过 Octo（75.1）和 OpenVLA（76.5）。对小团队，这意味着不必先攒百万条轨迹才能开始。
  • 跨本体几乎不掉点，而且原因可解释。63.9% → 62.2%，只用一个 checkpoint。这不是工程调优出来的，是「在末端空间预测、把运动学留在模型外」这个选择的直接结果——所以它可以被复用。

必须打的折扣

  1. 绝对分数不高，而且是被自己超越的那种不高。零样本 79.4% 很好听，但同组 VLA 微调 50 条就到 85.6%–96.7%。它的价值在「不用数据」，不在「比用数据更好」。把它读成「VLA 可以不要了」会严重高估；读成「冷启动的最优解」才准确。
  2. Thinking 一关就崩到 11.7%，这是成本炸弹。每一步都要推理，意味着单步延迟和 token 成本都是普通 VLA 的数倍，而论文没有报任何延迟、吞吐或算力数字。对「10T 参数的模型去叠衣服成本超过人工」这个它自己提出的论点，它没有给出反证。
  3. 任务面很窄：一台 6 自由度 UR3、桌面级、单臂、刚性物体为主。困难任务组只有 6 项，真机每项 30 条示教。没有柔性物体的大规模验证，没有多臂，没有移动底盘。「叠 T 恤 80%」是单点成绩，不是分布。
  4. 它依赖两样在真实场景里不一定成立的东西：可靠的深度，和明确的 TCP 定义。深度消融里「去掉深度就归零」是优点也是软肋——意味着透明物体、反光表面、强光环境会直接把这个方法打回 0。论文没有做这类鲁棒性测试。
  5. 「规模不是唯一决定因素」这个结论，证据偏薄。2B→27B 明显提升、27B→397B 收益有限、闭源更强但「部分任务仍有提升」——它没有拆开「模型家族」和「规模」两个变量，所以只能说「要一起看」，说不了「哪个更重要」。
  6. 它是 post-Astra 讨论的一部分，不是结论。原文末尾把 VLA、WAM、零样本框架三条路线都批了一遍，姿态是「我们在找一个低成本、能直接执行、还能持续变强的模型，EASG 是初步尝试」。按作者的自我定位读，它是一份有说服力的方向论证，不是一份可交付的系统。
一句话总结它的位置：它没有让 VLM 变强，它把一件本来要花数据去猜的事，改成了一件可以直接写下来的事。最值得带走的两条判断：① 动作的语义是可被语言描述的，凡是可以被描述的东西，就不该让模型从数据里反推；② 动作头存在的理由是「动作不是文本」这个假设，假设被去掉，模块就消失了。
而它留下的最大空白也很清楚：零样本 79.4% 的那 20.6% 失败，到底是「不会做」还是「说不清」？如果是后者，这套方法的下一站不是更大的模型，而是更严格的语法与更好的深度。
