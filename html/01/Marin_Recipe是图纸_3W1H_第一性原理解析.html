一句话 科学方法的第二步是「解释为什么」，而只能调 API 的模型根本做不到这一步
💡 第一性原理核心立论

现代 AI 研究有一条因果链：发现问题 → 解释原因 → 提出方案。前沿模型变成只能调 API 的黑箱之后，中间那一环断了——你能看到模型哪里差，却不知道它为什么差。所以开放权重的价值远小于宣传：权重告诉你结果，不告诉你成因。真正稀缺的是另一类东西：可复现的数据、预先注册的实验、以及公开的失败记录。而让这套科学方法在大规模上跑得动的工具很反直觉——一份「Recipe」，一个输入是模型规模、输出是全套超参的函数。它把训练从手艺变成图纸。

What是什么：一份「怎么把基模训练做成可研究的事」的施工说明

这篇不是论文，是一场演讲的编译：Marin 团队讲他们怎么把一个 535B 总参数量、A23B 激活量的 MoE 模型从头训完，并且把整个过程（数据、配方、Checkpoint、失败的实验）一起放出来。他们自己给这件事定的目标不是「训一个更强的模型」，而是「让学术界重新能对前沿模型做科学研究」。这两件事的区别，是全文的骨架。

先把硬数字摊开，判断它的量级：

项目数值含义
模型535B 总参 · A23B 激活（MoE）显存要装 535B，每 token 只算 23B
训练 Token约 20 万亿原始池约 25 万亿，去重删掉约 2 万亿
数据来源Hugging Face 上 152 个数据集「一周就能翻完」——数据早已公开存在
硬件约 11 套 NVL72 系统出口管制型号，EP Kernel 生态与之错配
MoE 收益同 Loss 下比 Dense 快 3.6 倍（wall-clock）不是理论 FLOPs，是实际训练速度
最小实验8 张 H100 跑 8 分钟一个想法当天就能验
外推比Scaling Ladder 最小做到 1/300 规模作者自认「没有任何科学依据，就是随便定的」
一句话定位：这不是「又一个开源大模型」。它是一次方法论演示——用一个真实规模的预训练任务，证明「先画图纸、再施工」在千卡级别是可以做到的。模型是副产品，Recipe 才是主产品。

为什么一个中国读者会在具身智能的号里看到这篇？因为作者的论证起点是「很多人当年错过大模型浪潮、转去具身智能」，而现在基模能力涨得太快，很多原本要在具身领域慢慢啃的问题可能直接被更强的基模吸收掉。于是问题回到最上游：通用智能到底怎么从规模化训练里涌现出来。

Why为什么：三堵墙，堵的都不是「模型不够大」

墙一：可观测性——你能测出它差，测不出它为什么差

作者把机器学习研究拆成三步：拿到 SOTA 模型 → 找出它的问题 → 解释这些问题为什么发生 → 提出方案。中间那一步是整条链的枢纽，也是唯一无法靠调 API 完成的一步。一个只能看输出的模型，你能观察到「它在多跳推理上崩了」，但无法知道是数据里缺这类样本、还是位置编码外推失败、还是某个 attention head 在长上下文里饱和了。既然解释不了，方案就只能猜——猜出来的方案可能有效，也可能和真实成因毫无关系。

这里有个很容易被忽略的细节：作者明确说，「开放权重」并不能解决这个问题。你拿到权重，仍然不知道训练数据是什么、权重是怎么走到这个点的、哪些实验失败了、团队当时优先考虑了什么。权重是结果快照，不是过程记录。所以他们的方案不是「开源得更多」，而是换一类东西去开放：可复现的数据、预先注册的实验、决策过程。

墙二：成本曲线——资本指数增长，能力线性增长

企业投入呈指数增长，性能收益却是线性的。这条曲线一旦成立，学术界就彻底失去了「自己放大规模去追」的可能：不是不想，是买不起。而学术界的激励机制恰好和这类工作相反——它奖励新颖的发现，不奖励「把已知方法老老实实放大」。于是这几年大量论文被迫在「用 API 观察现象 + 猜机制」的模式下生产，作者对此的评价很直接：这些工作可能有用，但和前沿模型实际发生的问题没多大关系。

Marin 的策略因此变得清楚：他们自愿去做那群「愿意做蠢事」的人——公开地用最直接、最笨的方法，把它放大到足够大的规模，产生一批「值得被更聪明的方法改进」的基线。学术界负责想更好的办法，他们负责把办法接进下一轮训练。

墙三：「数据更多」是个假指标——25 万亿里 2 万亿是重复

20 万亿 Token 听起来遥不可及，但真去翻 Hugging Face 会发现数据早就在那了。问题不在有没有，而在三件事：质量参差、跨数据集重复、以及「穿着不同外衣的同一个数据集」。Nemotron 和 Dolma 处理管线不同，源头都是 Common Crawl。直接把所有数据集倒进训练，等于把同一段文本按它被复制了几份来加权——这个隐式权重没有任何人设计过，却会实实在在改变模型。

三堵墙的共同点：没有一堵是「再堆点算力就过去了」。可观测性靠开放过程解决，成本曲线靠小规模外推解决，数据重复靠工程管线解决。三件事都不性感，但三件事都决定了「能不能做研究」。

How怎么做：六步，从「不浪费一个 FLOP」到「让社区改配方」

第 1 步：不从头训——Tootsie 续训法，把每一批的产物混进下一批
Marin 起家时靠 TPU Research Cloud 的免费额度，算力极度受限，于是立了一条规矩：任何一个 FLOP 都不浪费，永远不从零开始训练。做法是让训练过程持续延续——8B 训完，接着往 32B 上续；32B 出问题，也不是推倒重来。名字借的是 Tootsie Roll 的生产工艺：每天把上一批产品的一小部分掺进下一批。作者自己说得很坦白：那些看起来很整齐的训练阶段，不是因为有什么深刻的科学原理，纯粹是为了不浪费已经跑完的 step。
第 2 步：先画图纸——Recipe 是「规模 → 超参」的函数，不是一组数值
这是全文最值得偷的一个概念。传统做法是给某个规模的模型调出一套好超参；Recipe 做的是另一件事：写一个函数，输入模型规模与 token 数，输出这一规模下应该用的学习率、批大小、数据配比、架构选择。有了它，你只要在小规模上跑一批实验、拟合出这条函数，就能在还没拿到大卡的时候预测大模型会到哪。作者的原话很关键：「真正重要的是 Recipe 如何随规模变化，而不是某一个具体模型最终表现如何。」
第 3 步：用 Scaling Ladder 验证外推，把「预测 Loss」和「实际 Loss」画在同一张图上
光有函数不够，必须有人真去跑大模型来验。他们的做法是搭一条阶梯：从最小 1/300 规模一路排到目标规模，每一级都跑，并且公开发布「预测 Loss vs 实际 Loss」的对照图。遇到中途要换数据配比这类反事实实验，就把整条阶梯重跑一遍、更新预测。这套机制的作用不是提高精度，是建立信任——让更多人敢用小实验外推。（1/300 这个比例作者明说「完全没有经过科学论证，只是我第一次做实验时用的数，后来就一直沿用」——这种坦白很难得，也提醒你别把它当定律。）
第 4 步：把散落在各地的抢占式算力焊成一台机器——Iris
买不起一整个数据中心，就只能跨区域训练，而 TRC 的资源是 Pre-emptible（可抢占）的，供给会不可预测地波动。Iris 是一个统一的多区域集群管理系统，本身技术并不复杂，但它让「随时接入一批新卡、立刻跑有意义的实验」成为默认能力。作者的评价很有意思：研究生绝对不会自己去搭这种东西，但专业工程团队会。这正是「把工程当科学基础设施」的具体样子。
第 5 步：让稀疏真的变快——NVL72 上自研 EP Kernel
MoE 论文讲的是理论 FLOP 效率，实际训练看的是 wall-clock。几乎所有优秀的 Expert Parallelism Kernel 都出自中国开源实验室，但几乎没有能在 NVL72 上跑好的——因为 NVL72 受出口管制，不同团队是在完全不同的硬件约束下做优化的。他们把所有开源实现都试了一遍，在 NVL72 上全部远慢于普通 FSDP，最后自己写了 Fixed Pooled-Wave All-to-All。结果：同 Loss 下比 Dense Recipe 快约 3.6 倍。这件事的教训不是「自研更好」，而是硬件约束不同，最优软件就不同，开源生态的「最优解」是有地理边界的。
第 6 步：数据不是筛，是「重新分配」——Datakit 的四个动作
①全局去重：约 25 万亿原始 Token 里删掉约 2 万亿重复，其中大部分来自 NVIDIA 自己的数据生态（发布了大量数据，但没有做跨生态全局去重）。②去污染：把开发用和最终测试用的所有 Benchmark 相关文档都删掉——具体做法是删掉任何包含这些 Benchmark 任意一个 13-gram 片段的文档。③主题聚类：不再把每个数据源当一个数据集，而是把所有文档重新归到主题类目里，这样一个来自通用网页的数学页面，会和专门的数学数据集落进同一类。④质量评分：先用大模型按标准打分，再蒸馏成小分类器处理全量。

最反直觉的是他们对「低质量数据」的处理：不删，保留，只是调低采样权重。理由是——删掉就只剩一种质量分布了；而今天训这个规模需要一种分布，明天训更小的模型可能需要完全不同的分布。用「采样权重」表达需求，比用「过滤器」表达需求灵活得多。作者的说法是：最高质量的数据重复采 10 次，最差的只用极少量，中位数的正好用一次。
第 7 步（隐藏的第 7 步）：Belay——把配方变成公开的 GitHub Issue。任何人都能在 Issue 里提想法，团队认可就让 Agent 自动实现、提交分支、在他们的基础设施上跑实验，并把结果回填到 Issue。效果好的想法就沿 Scaling Ladder 往上放大。这一步才是「开放研究」真正落地的地方：开放的不是权重，是改进的通路。

Formula核心公式：三个式子，一条从「小实验」到「大模型」的链

① 幂律外推：Loss 是参数量与数据量的函数
\[ L(N, D) \;=\; E \;+\; \frac{A}{N^{\alpha}} \;+\; \frac{B}{D^{\beta}} \]
\(N\) 是模型参数量，\(D\) 是训练 token 数，\(E\) 是数据本身决定的不可约损失（再怎么放大也降不下去的那条底），\(\alpha,\beta\) 是两个衰减指数。大白话：模型变大、数据变多，Loss 都会降，但都按幂律降——边际收益递减得很稳定，而且有一块地板永远踩不到。这个式子的实用价值不在预测绝对精度，而在比较不同分配方案：给定固定的算力预算，把钱花在「更大的模型」还是「更多的数据」上，答案就是让两项的边际收益相等。
② isoFLOP 曲线：同一笔算力预算下的最优切分
\[ C \;\approx\; 6\,N\,D, \qquad N^{*}(C) \;=\; G\,\left(\frac{C}{6}\right)^{\frac{\beta}{\alpha+\beta}}, \qquad D^{*}(C) \;=\; G^{-1}\left(\frac{C}{6}\right)^{\frac{\alpha}{\alpha+\beta}} \]
\(C\) 是总浮点运算量，系数 6 来自「前向 2 + 反向 4」的粗略记账。固定 \(C\) 时，\(N\) 和 \(D\) 此消彼长，把它们代回 ① 式求极值，就得到这条 isoFLOP 曲线上的最优点。大白话：算力是固定的，模型大一点就意味数据少一点，反之亦然；存在一个最甜的配比，偏哪边都亏。Marin 的那张「每条曲线代表相同算力预算」的图，画的就是这件事——而他们在 Log-Log 坐标下看到结果接近一条直线，所以敢用小规模去预测大规模。
③ MoE 的稀疏记账：参数量与计算量被拆开了
\[ \text{FLOPs}_{\text{token}} \;\approx\; 2 \cdot \underbrace{\left(\sum_{e \in \mathcal{E}} \mathbb{1}[e \in \mathrm{TopK}(g(x))]\cdot |e|\right)}_{\text{激活参数} \approx 23\text{B}} \;+\; \text{Attn}(x), \qquad \text{显存} \propto \sum_{e\in\mathcal{E}}|e| \approx 535\text{B} \]
\(g(x)\) 是路由器给每个 token 算出的专家偏好，\(\mathrm{TopK}\) 只保留前 K 个专家参与计算。大白话：MoE 把「模型有多大」和「算一个 token 要花多少」这两件事拆开了——装的时候要 535B 的显存，算的时候只动 23B 的参数。但注意这里换来的不是免费的午餐：省下的是 FLOPs，付出的是一次 All-to-All 通信（把 token 发到它该去的卡上）。这就是为什么第 5 步那个自研 Kernel 不是工程细节，而是「稀疏到底能不能变成 wall-clock 收益」的开关——通信慢了，省下来的 FLOPs 全被等待吃掉。
④ 数据混合：用采样权重表达「多要数学、少要菜谱」
\[ p(d) \;\propto\; w_{\text{topic}(d)} \cdot w_{\text{quality}(d)}, \qquad \text{weight}_q \in \{0.1,\,1,\,10\} \;\text{(低 / 中 / 高)} \]
每个文档 \(d\) 被抽到的概率，由它所在主题类目的权重和质量档位的权重相乘决定。大白话：不是「把垃圾删掉」，而是「高质量的采十遍、垃圾的几乎不采」。为什么这个设计更重要：如果删掉，数据池就只剩一种质量分布；用权重，你可以在不同训练阶段、不同模型规模下重新分配，而不用重新处理一遍 20 万亿 token。作者把这件事讲得很直白——「我希望能够直接提出：增加数学数据，减少食谱内容，增加代码数据」，而不是指望网页数据自动按你想要的比例被采样。

Worth价值与局限：它证明的是「可研究」，不是「最优」

它真正贡献了什么

  • 把「Recipe」变成一等公民。大多数团队把超参当调参结果，Marin 把它当可外推的对象。这个视角转换一旦成立，算力不足就不再是「做不了研究」，而只是「实验规模小一点」。
  • 把数据工程从玄学拉回工程。去重、去污染、主题重分配、质量分档、按权重采样——每一步都可以被检查、被复现、被质疑。这比「我们的数据配方效果更好」有用得多。
  • 公开了失败与「蠢办法」。预先注册实验意味着必须公开自己做过的蠢事。这是让「解释为什么」重新可行的前提，也是绝大多数开源模型缺失的部分。
  • 给具身智能一个上游参照。当基模能力上涨时，哪些具身问题会被吸收、哪些不会，取决于基模到底靠什么变强。这篇给的是机制层面的答案，而不是榜单。

必须打的折扣

  1. 这是演讲，不是论文，没有可复核的实验细节。3.6 倍、20 万亿 token、2 万亿重复，全部来自讲者自述。没有对照组设置、没有多次运行、没有误差棒。把它当「一份可信的工程报告」可以，当「可复现的结论」不行。
  2. 「开放」与「可解释」之间仍然隔着东西。作者自己承认开放权重解决不了中间环节。但数据+配方+Checkpoint 是否足够让别人做出因果级解释，这篇没有证据——它证明的是「材料交出来了」，不是「研究真的发生了」。
  3. 规模不算顶尖，20 万亿 token 的对比对象也没交代清楚。原文只说这个规模「小于目前中国大多数针对推理效率优化的前沿模型」，但没有给出具体的横向基线。读者容易把「史上最大实时直播预训练」误读成「史上最大模型」——这是两件事。
  4. 去污染的判据是单一榜单。测试集主要采用 Artificial Analysis Intelligence Index，按 13-gram 匹配删除。这意味着没进这个榜单的评测集完全没有被保护，任何未公开的评测都可能被污染；反之 13-gram 这种硬匹配也会误删正常内容。
  5. 约 25% 数据被确认是 AI 生成的，而且没有过滤。作者判断「保留足够比例自然数据就不会 Model Collapse」，但同时也承认 AI 数据会干扰质量评分器。这两句话放在一起，说明他们给的是一个基于比例的经验判断，不是一个被验证过的安全边界。
  6. 1/300 的外推比没有科学依据，最小实验 8 张卡 8 分钟也未必够。作者很诚实地说了这个比例是随手定的。但那意味着「用小实验预测大模型」这条链的强度，取决于一个未经论证的经验常数——恰好在最需要严格性的地方留了一个软肋。
  7. 最关键的一点：这篇的所有收益都要靠「有人真的去用」才兑现。Belay 让社区提想法、Agent 自动跑实验，听起来很美，但它同时也把「提出好问题」这件事外包给了愿意在 GitHub Issue 里留言的人。材料开放 ≠ 研究发生，这一步的转化率，演讲里没有数字。
一句话总结：它没有回答「怎么训出最强的模型」，它回答的是一个更前置的问题——当算力被少数机构垄断之后，科学方法还能不能继续用？它的答案是把训练过程本身产品化：Recipe 当图纸、Scaling Ladder 当验收、数据管线当原材料、Belay 当改进通路。这套东西的价值不取决于 Marin 这个模型强不强，而取决于别人能不能拿它做出自己原本做不了的研究。
